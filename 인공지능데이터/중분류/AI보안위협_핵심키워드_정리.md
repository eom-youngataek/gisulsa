# AI 보안 위협 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 위협 분류표(MECE) → 발생원인 → OWASP 항목별 대응 매핑

***

## 0. 위협 분류표 (MECE 통합표)

AI 시스템의 생애주기(학습단계 / 운영(추론)단계 / 시스템·인프라단계)를 기준으로 7개 키워드를 MECE하게 분류

| 생애주기 단계       | 위협 키워드                         | 한 줄 정의                               |
| ------------- | ------------------------------ | ------------------------------------ |
| **학습단계**      | 적대적공격 4유형 中 데이터포이즈닝(Poisoning) | 학습데이터에 악성 데이터를 섞어 모델을 오염             |
| **추론(운영)단계**  | 적대적공격 4유형 中 회피공격(Evasion)      | 입력을 미세조작해 모델이 오판하도록 유도               |
| **추론(운영)단계**  | 프롬프트 인젝션                       | 악의적 지시문을 입력에 숨겨 LLM이 의도치 않은 동작을 하게 함 |
| **추론(운영)단계**  | 모델전도공격(Model Inversion)        | 모델 출력만으로 학습데이터(개인정보 등)를 역추론          |
| **시스템/인프라단계** | Model DoS                      | 과도한 요청·악성입력으로 모델 서비스를 마비시킴           |
| **거버넌스/평가**   | AI신뢰성검인증(CAT)                  | 위 모든 위협에 대한 모델의 안전성을 제3자가 검증·인증      |
| **위협정보 분석**   | TTPs                           | 공격자의 공격수법을 체계적으로 분류·공유하는 위협인텔리전스 틀   |

***

## 1. 적대적공격 4유형

**위협유형표 (4유형, MECE)**

| 유형                              | 공격 시점      | 방식                                  |
| ------------------------------- | ---------- | ----------------------------------- |
| ① 회피공격(Evasion Attack)          | 추론(운영)단계   | 입력에 미세한 노이즈를 섞어 모델이 오분류하도록 유도       |
| ② 오염공격(Poisoning Attack)        | 학습단계       | 학습데이터에 악성 샘플을 주입해 모델 자체를 오염         |
| ③ 추출공격(Extraction Attack)       | 추론단계(반복질의) | 모델에 반복 질의해 내부 로직·파라미터를 복제(모델 도용)    |
| ④ 역공학공격/멤버십추론(Inference Attack) | 추론단계       | 출력 패턴으로 "이 데이터가 학습에 쓰였는지" 등 민감정보 추론 |

**발생원인**

* 딥러닝 모델이 입력 공간의 미세한 변화에도 민감하게 반응하는 **선형적 결정경계의 취약성**
* 학습데이터·모델 API에 대한 접근통제 미흡

**OWASP 항목별 대응 매핑**

* 회피공격 → 적대적 훈련(Adversarial Training, 노이즈를 섞은 데이터로 미리 학습), 입력값 검증
* 오염공격 → 데이터 출처 검증, 이상탐지 기반 학습데이터 필터링
* 추출/역공학 → API 질의빈도 제한(Rate Limiting), 출력값에 노이즈 추가(차분프라이버시)

***

## 2. 프롬프트 인젝션 (Prompt Injection)

**위협유형표**

| 유형     | 방식                                                           |
| ------ | ------------------------------------------------------------ |
| 직접 인젝션 | 사용자가 직접 "이전 지시를 무시하고…"식 악성 프롬프트 입력                           |
| 간접 인젝션 | 웹페이지·문서 등 LLM이 참조하는 외부 콘텐츠에 악성 지시문을 숨겨놓음 (RAG 검색결과에 포함되어 실행) |

**발생원인**

* LLM이 "시스템 지시"와 "사용자/외부 입력"을 구조적으로 명확히 구분하지 못함(둘 다 그냥 텍스트로 처리)

**OWASP Top10 for LLM 매핑**

* **OWASP LLM01: Prompt Injection** (2025년 1순위 위협)
* 대응: 입력 출처별 권한 분리, 시스템 프롬프트와 사용자 입력의 구조적 격리, \*\*LLM 가드레일(Guardrails)\*\*로 출력 전 필터링

***

## 3. 모델전도공격 (Model Inversion Attack)

**위협유형표**

| 구분   | 내용                                                        |
| ---- | --------------------------------------------------------- |
| 목적   | 모델의 출력(예: 신뢰도 점수)만으로 학습에 사용된 원본데이터(얼굴, 의료정보 등)를 복원/추론     |
| 대표사례 | 얼굴인식 모델에 다양한 입력을 넣어 출력 신뢰도가 최대가 되는 이미지를 역산 → 학습데이터의 얼굴 복원 |

**발생원인**

* 모델이 학습데이터의 통계적 패턴을 과도하게 "암기"(과적합)
* 모델 API가 신뢰도·확률값 등 세밀한 출력정보를 그대로 노출

**OWASP Top10 for LLM 매핑**

* **OWASP LLM02: Sensitive Information Disclosure**
* 대응: 출력 정보를 범주형(라벨만)으로 단순화, 차분프라이버시 적용 학습, 모델 접근권한 최소화

***

## 4. Model DoS

**위협유형표**

| 유형       | 방식                                        |
| -------- | ----------------------------------------- |
| 자원소모형    | 매우 긴 입력/복잡한 질의를 반복 전송해 GPU·메모리 자원을 고갈     |
| 무한루프 유도형 | 에이전트(MAS 등)가 같은 작업을 반복 수행하도록 유도해 비용·자원 폭증 |

**발생원인**

* LLM의 추론(토큰생성) 비용이 입력 길이에 비례해 커지는 구조적 특성
* 사용량 제한(쿼터) 미설정

**OWASP Top10 for LLM 매핑**

* **OWASP LLM10: Unbounded Consumption**
* 대응: 입력 토큰 길이 제한, 사용자별 호출 횟수/비용 쿼터 설정, 비정상 트래픽 탐지(레이트리미팅)

***

## 5. OWASP Top10 for LLM (2025)

**위협유형표 (10대 항목)**

| 순위    | 항목                               | 한줄 요약                              |
| ----- | -------------------------------- | ---------------------------------- |
| LLM01 | Prompt Injection                 | 악성 지시문 주입                          |
| LLM02 | Sensitive Information Disclosure | 민감정보 유출(모델전도 등)                    |
| LLM03 | Supply Chain                     | 학습데이터·플러그인·MCP서버 등 공급망 위협          |
| LLM04 | Data and Model Poisoning         | 데이터/모델 오염                          |
| LLM05 | Improper Output Handling         | 출력값을 검증 없이 그대로 실행(예: 생성된 코드 즉시 실행) |
| LLM06 | Excessive Agency                 | 에이전트에 과도한 권한 부여로 의도치 않은 행동 실행      |
| LLM07 | System Prompt Leakage            | 시스템 프롬프트(내부지침) 유출                  |
| LLM08 | Vector and Embedding Weaknesses  | RAG 벡터DB 조작·오염                     |
| LLM09 | Misinformation                   | 환각(Hallucination) 기반 허위정보 생성       |
| LLM10 | Unbounded Consumption            | 자원 무제한 소비(Model DoS)               |

**발생원인**: LLM이 "자연어 입력=명령어와 데이터의 구분 없는 단일 채널"이라는 근본적 설계 한계

**대응 매핑**: 입력검증·출력검증의 이중 게이트, 최소권한 원칙의 에이전트 설계, 공급망 신뢰성 검증(SBOM과 유사한 "AI BOM" 개념 확산 중)

***

## 6. AI신뢰성검인증(CAT, Certification for AI Trustworthiness)

**위협유형표(검증 영역 분류)**

| 검증영역  | 내용                     |
| ----- | ---------------------- |
| 기능안전성 | 의도된 성능을 안정적으로 발휘하는지    |
| 보안성   | 위 OWASP 위협들에 대한 방어력    |
| 윤리성   | AI윤리기준(10대 핵심요건) 충족 여부 |
| 설명가능성 | 판단 근거를 설명할 수 있는지       |

**발생원인(인증 필요성)**: 기업이 자체 주장하는 "AI 안전성"을 제3자가 객관적으로 검증할 표준 절차가 없으면 시장의 신뢰 형성이 어려움

**대응(인증 프로세스)**: 모델 제출 → 표준화된 테스트셋·시나리오로 평가 → 등급/인증서 발급 → 사후 모니터링(재인증)

***

## 7. TTPs (Tactics, Techniques, and Procedures)

**위협유형표(3단계 구조)**

| 구분             | 정의                                   |
| -------------- | ------------------------------------ |
| Tactics(전술)    | 공격자의 큰 목표(예: "정찰", "초기침투", "지속성 확보") |
| Techniques(기법) | 전술을 달성하는 구체적 방법(예: "피싱메일을 통한 침투")    |
| Procedures(절차) | 특정 공격자(그룹)가 그 기법을 실행하는 세부 단계·도구      |

**발생원인(왜 분류하나)**: 공격을 "이 IP가 나쁘다"식 단편 정보가 아니라 **행동패턴 단위**로 분류해야 새로운 변종 공격도 미리 식별 가능

**대응 매핑**

* MITRE ATT\&CK 프레임워크가 TTPs를 표준화한 대표사례(최근 MITRE ATLAS로 AI 특화 TTPs도 별도 체계화됨)
* SOC/SOAR(이전 학습한 보안운영 키워드)에서 TTPs 기반으로 위협 탐지 룰을 설계 → 알려진 공격그룹의 수법을 사전 방어

***

## 📌 연관 키워드 모음 (확장 학습용)

| 연관 키워드                             | 연결 포인트                                                         |
| ---------------------------------- | -------------------------------------------------------------- |
| **LLM 가드레일(Guardrails)**           | 프롬프트 인젝션·Improper Output Handling을 막는 입출력 필터링 아키텍처             |
| **차분 프라이버시(Differential Privacy)** | 모델전도공격·멤버십추론 방어를 위한 출력 노이즈 추가 기법(PET 기술)                       |
| **적대적 훈련(Adversarial Training)**   | 회피공격 방어를 위해 노이즈 데이터를 미리 학습에 포함시키는 기법                           |
| **멤버십추론공격(Membership Inference)**  | 적대적공격 4유형 중 역공학공격의 세부 유형, "이 데이터가 학습셋에 있었는가" 추론                |
| **SBOM / AI BOM**                  | OWASP LLM03(Supply Chain) 대응 — AI모델·데이터 출처를 명세화해 공급망 위협 관리     |
| **MITRE ATLAS**                    | TTPs를 AI/ML 공격에 특화해 표준화한 프레임워크(ATT\&CK의 AI버전)                  |
| **제로트러스트(Zero Trust)**             | "AI 에이전트도 기본적으로 신뢰하지 않는다"는 원칙으로 Excessive Agency(LLM06) 방어와 연결 |
| **레드티밍(Red Teaming)**              | AI신뢰성검인증(CAT) 전 단계에서 모의공격으로 취약점을 사전 발굴하는 활동                    |
| **MCP(Model Context Protocol)**    | 외부도구 연동 표준이지만, 악성 MCP서버 연결 시 OWASP LLM03 공급망 위협의 통로가 될 수 있음    |
| **AI RMF / ISO 42001**             | 위 모든 위협을 조직 차원에서 관리하는 상위 거버넌스 프레임워크(이전 정리 키워드와 연결)             |
| **환각(Hallucination)**              | OWASP LLM09(Misinformation)의 핵심 원인, 검증 없는 LLM 출력 신뢰의 위험성       |

***

## 종합 흐름도

```
[AI 생애주기]
학습단계 ──→ 오염공격(Poisoning), 데이터 포이즈닝
   │
추론단계 ──→ 회피공격, 프롬프트인젝션, 모델전도공격, 멤버십추론, Model DoS
   │
시스템/공급망 ──→ MCP·플러그인 통한 공급망공격(OWASP LLM03)
   │
   ▼
[방어체계] LLM가드레일 + 차분프라이버시 + 적대적훈련 + 제로트러스트 + SBOM
   │
   ▼
[검증/인증] AI신뢰성검인증(CAT) ← 레드티밍으로 사전 점검
   │
[위협정보 공유] TTPs(MITRE ATLAS) 기반으로 공격패턴 분류·대응룰 설계
```
