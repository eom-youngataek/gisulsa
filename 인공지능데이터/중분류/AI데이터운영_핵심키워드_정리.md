# AI 데이터 운영/거버넌스 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 아키텍처도 → 문제 발생원인 → 관리/방지 절차 (3단 구성)

---

## 1. 데이터레이크 아키텍처 vs 데이터스웜프

**아키텍처도**
```
[원천데이터] 정형/반정형/비정형 데이터 그대로 수집
      ↓
[수집(Ingestion)] 배치/스트리밍으로 원본 그대로 적재
      ↓
[저장(Raw Zone)] 스키마 정의 없이 원본 그대로 보관(Schema-on-Read)
      ↓
[정제(Curated/Trusted Zone)] 가공·표준화된 데이터 영역 분리
      ↓
[분석/소비] BI, ML, AI 모델 학습 등에서 활용
```

**문제 발생원인 (데이터스웜프, Data Swamp)**
- 메타데이터 관리 부재 → "이 데이터가 뭔지, 누가 만들었는지" 추적 불가
- 데이터 카탈로그·태깅 미적용 → 검색·재사용 불가능
- 정제/검증 없이 무분별하게 적재만 계속됨 → 신뢰할 수 없는 늪(swamp)으로 변질

**관리/방지 절차**
1. 데이터 카탈로그 구축(메타데이터 자동 수집·태깅)
2. Zone 구조화(Raw→Curated→Trusted)로 품질 단계 구분
3. 데이터 거버넌스 정책(소유자·접근권한·수명주기) 수립 및 정기 감사

---

## 2. AI학습데이터 품질관리 지표·활동

**아키텍처도**
```
[데이터 기획] → [수집] → [정제/가공] → [라벨링] → [검증] → [학습용 데이터셋 확정]
   (전 단계마다 품질지표 체크포인트 배치)
```

**문제 발생원인**
- 데이터 편향(특정 계층·상황 데이터 과소/과대 포함) → 모델 편향으로 전이
- 라벨링 오류·일관성 부족(작업자 간 기준 차이)
- 데이터 노이즈·결측치 미처리

**관리/방지 절차 (+품질지표)**
- **품질지표**: 정확성(라벨 정확도), 완전성(결측률), 일관성(작업자간 일치도, Inter-Annotator Agreement), 다양성(편향 점검지표)
- **관리활동**: 표본 검수(샘플링 검증), 교차검증(다수 작업자 합의), 데이터 생애주기별 품질관리 체크리스트 운영

---

## 3. 데이터 어노테이션 (Data Annotation)

**아키텍처도**
```
[원본데이터(이미지/텍스트/음성)] → [어노테이션 가이드라인 수립] 
→ [작업자/AI보조 라벨링] → [검수(QA)] → [라벨링 완료 데이터셋]
```

**문제 발생원인**
- 가이드라인이 모호 → 작업자마다 다른 기준으로 라벨링(일관성 저하)
- 대량 데이터 수작업의 비용·시간 부담
- 희귀 클래스(소수 사례) 라벨링 데이터 부족

**관리/방지 절차**
1. 명확한 어노테이션 가이드라인 및 예시 사전 배포
2. AI보조 라벨링(Pre-labeling) 도입으로 작업자는 검증만 수행(효율화)
3. 작업자 간 일치도(IAA) 측정 및 불일치 건 재검토 프로세스 운영

---

## 4. 연합학습 (Federated Learning)

**아키텍처도**
```
[중앙서버: 글로벌모델 배포]
      ↓ (모델만 전송, 데이터는 전송 안함)
[기기/기관A 로컬학습] [기기/기관B 로컬학습] [기기/기관C 로컬학습]
      ↓ (학습된 가중치만 전송)
[중앙서버: 가중치 집계(Aggregation) → 글로벌모델 업데이트] → 반복
```

**문제 발생원인(해결하고자 한 문제)**
- 원본데이터를 중앙으로 모으면 개인정보 유출·법적 제약 발생(병원 간 환자데이터 공유 불가 등)
- 데이터가 기관별로 분산(Silo)되어 있어 통합학습이 어려움

**관리/방지 절차(보안기술 포함)**
1. 로컬 학습 후 가중치만 전송(원본데이터는 기관 내부에 유지)
2. 차분 프라이버시(Differential Privacy)·동형암호 등 PET 기술 결합으로 가중치 자체의 역추론 위험도 차단
3. 비잔틴 공격(악의적 참여자의 가중치 조작) 방지를 위한 이상 가중치 탐지·검증 로직 운영

---

## 5. MLOps (CT 파이프라인 포함)

**아키텍처도**
```
[데이터] → [모델학습(CI)] → [모델검증] → [배포(CD)] → [운영 모니터링]
                                              ↑___________│
                              [CT: Continuous Training, 성능저하 감지 시 자동 재학습 트리거]
```

**문제 발생원인**
- 운영 중 데이터 분포가 변하는 **데이터 드리프트/모델 드리프트** 발생 → 시간이 지날수록 모델 성능 저하
- 수동 재학습 방식은 대응이 느려 서비스 품질 저하 지속

**관리/방지 절차**
1. 운영 데이터와 학습 데이터의 분포 차이를 모니터링(드리프트 감지 지표 설정)
2. 드리프트 감지 시 **CT(Continuous Training) 파이프라인이 자동으로 트리거**되어 재학습 수행
3. 재학습된 모델을 자동 검증(A/B테스트) 후 점진적 배포(Canary)로 안전하게 전환

---

## 6. 데이터 가치평가·자산화

**아키텍처도**
```
[데이터 식별] → [가치평가(정량/정성 모델 적용)] → [자산 등록(메타데이터+가치정보)] 
→ [데이터 거래/내부활용/대차대조표 반영]
```

**문제 발생원인(왜 어려운가)**
- 데이터는 사용해도 소모되지 않고(비배제성), 결합방식에 따라 가치가 달라짐(맥락의존성) → 전통적 자산가치평가 모델 적용이 어려움
- 가치를 객관적으로 측정할 표준 방법론 부재

**관리/방지 절차(가치평가 방법론)**
1. 정량적 접근: 원가법(구축비용 기준), 수익접근법(데이터 활용으로 창출된 매출/비용절감 추정), 시장접근법(유사 데이터 거래사례 비교)
2. 정성적 보완: 데이터 품질·희소성·활용범위를 가중치로 반영
3. 가치평가 결과를 데이터 카탈로그에 등록해 "자산"으로 관리 → 데이터 거래소 등록 또는 회계상 무형자산 반영 검토

---

## 7. 데이터 관측가능성(Data Observability)

**아키텍처도**
```
[데이터 파이프라인 전 구간] 수집→저장→변환→서빙
      ↓ (각 구간에 모니터링 센서 배치)
[관측지표 수집: 신선도/볼륨/스키마/분포/계보] → [이상 탐지·알림] → [원인 추적(Lineage)]
```

**문제 발생원인(왜 필요해졌나)**
- 파이프라인이 복잡해지며 "데이터가 갑자기 비거나, 형식이 바뀌거나, 늦게 도착"하는 문제가 발생해도 원인 파악이 늦어 비즈니스 의사결정에 악영향(Garbage In, Garbage Out)

**관리/방지 절차(5대 관측 축)**
1. **신선도(Freshness)**: 데이터가 제때 도착하는지
2. **볼륨(Volume)**: 데이터 양이 평소와 비슷한지(급감/급증 탐지)
3. **스키마(Schema)**: 컬럼 구조가 갑자기 바뀌었는지
4. **분포(Distribution)**: 값의 통계적 분포가 이상한지
5. **계보(Lineage)**: 문제 발생 시 어느 상류(upstream) 단계가 원인인지 추적

## 📌 키워드 간 연결 요약

```
데이터레이크 vs 데이터스웜프 ──→ 데이터 관측가능성 (스웜프 방지를 위한 상시 모니터링 체계)
        │
        └──→ AI학습데이터 품질관리 ──→ 데이터 어노테이션 (품질관리의 구체적 실행 단계)

연합학습 ──→ (개인정보 분산환경에서) 데이터 가치평가·자산화와 연계 가능

MLOps(CT파이프라인) ──→ 데이터 관측가능성(드리프트 감지의 기반 데이터)
                     ──→ AI학습데이터 품질관리(재학습 시 신규데이터 품질 검증 필요)
```

### 한 줄 비교 암기
| 키워드 | 핵심 한 줄 |
|---|---|
| 데이터레이크 vs 스웜프 | "정리된 호수"와 "방치된 늪"의 차이 = 메타데이터 관리 여부 |
| AI학습데이터 품질관리 | 정확성·완전성·일관성·다양성 4축 점검 |
| 데이터 어노테이션 | 가이드라인 명확화 + 작업자 간 일치도 관리가 핵심 |
| 연합학습 | "데이터는 그대로, 학습결과(가중치)만 이동" |
| MLOps(CT) | 드리프트 감지 → 자동 재학습 → 검증 후 배포 |
| 데이터 가치평가·자산화 | 원가법/수익접근법/시장접근법 3가지로 측정 |
| 데이터 관측가능성 | 신선도·볼륨·스키마·분포·계보 5대 축 |
