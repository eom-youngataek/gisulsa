# 암호기술 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 암호 원리(수식 가능) → 유형 분류 → 비교/활용사례

---

## 1. 대칭암호 vs 비대칭암호

**암호 원리**
- **대칭암호(Symmetric)**: 암호화와 복호화에 **동일한 키** 사용. C = Ek(P), P = Dk(C)
- **비대칭암호(Asymmetric)**: **공개키(암호화)와 개인키(복호화)가 서로 다른 키쌍**. C = E(공개키, P), P = D(개인키, C)

**유형 분류**

| 구분 | 대칭암호 | 비대칭암호 |
|---|---|---|
| 키개수 | 1개(공유키) | 2개(공개키+개인키) |
| 대표알고리즘 | AES, DES, 3DES | RSA, ECC, 디피헬만 |
| 속도 | 빠름 | 느림(연산량 큼) |
| 키분배 문제 | 사전에 안전하게 키 공유 필요(어려움) | 공개키는 누구나 알아도 됨(쉬움) |

**비교/활용사례**
- 실무에서는 **하이브리드 방식**으로 결합: 비대칭암호로 대칭키를 안전하게 교환 → 본 데이터는 빠른 대칭암호로 암호화(TLS, 전자봉투의 핵심원리)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 전자봉투 | 대칭+비대칭 하이브리드 방식의 대표 실무 적용사례(아래에서 상세 정리) |
| TLS1.3 핸드셰이크 | 비대칭암호로 키교환 후 대칭암호로 본통신, 동일한 하이브리드 원리 |
| 디피헬만(키교환) | 비대칭암호 원리를 활용한 대칭키 안전교환 전용 알고리즘 |

## 2. 동형암호 (Homomorphic Encryption)

**암호 원리**
> 데이터를 **복호화하지 않고 암호화된 상태 그대로 연산**해도, 그 결과를 복호화하면 평문으로 연산한 것과 동일한 결과가 나오는 암호기법
> 수식: E(a) ⊕ E(b) = E(a+b)  (암호화된 값끼리 연산 → 복호화하면 원본의 연산결과와 동일)

**유형 분류**

| 유형 | 가능한 연산 |
|---|---|
| **부분동형암호(PHE)** | 덧셈 또는 곱셈 중 한가지 연산만 무제한 가능 |
| **약간동형암호(SHE)** | 덧셈+곱셈 모두 가능하나 횟수 제한 |
| **완전동형암호(FHE)** | 덧셈+곱셈 모두 무제한 가능(연산량 매우 큼) |

**비교/활용사례**: 의료데이터를 암호화한 채로 클라우드에 위탁해 통계분석(병원은 원본데이터를 클라우드사업자에게 노출하지 않고도 분석결과만 받음), PET(개인정보보호강화기술)의 핵심 구성요소

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| PET(차분프라이버시, 합성데이터) | 동형암호와 함께 비교되는 프라이버시 보호 핵심기술 3종 |
| 연합학습(Federated Learning) | 동형암호를 결합해 학습결과(가중치)의 노출까지 추가로 막는 보강기법 |
| MPC(다자간계산) | 동형암호와 유사한 목적(암호화 상태 연산)을 가진 또 다른 프라이버시 보호 패러다임 |

## 3. PQC vs QKD

**암호 원리**
- **PQC(Post-Quantum Cryptography, 양자내성암호)**: 양자컴퓨터로도 풀기 어려운 **새로운 수학적 난제**(격자기반, 코드기반 등)를 활용한 차세대 암호 알고리즘(기존처럼 소프트웨어로 구현)
- **QKD(Quantum Key Distribution, 양자키분배)**: 양자역학의 원리(측정 시 상태가 변함)를 이용해, 도청 시도 자체를 물리적으로 탐지 가능한 키교환 방식(전용 하드웨어 필요)

**유형 분류**

| 구분 | PQC | QKD |
|---|---|---|
| 구현방식 | 소프트웨어(알고리즘 교체만으로 적용) | 전용 양자통신 하드웨어 필요 |
| 적용범위 | 기존 인터넷망에 그대로 적용 가능 | 별도 광케이블 인프라 구축 필요(거리제약 있음) |
| 보안근거 | 수학적 난제의 계산복잡도 | 양자역학적 물리법칙(도청 즉시 감지) |
| 비용/확장성 | 상대적으로 낮음, 전세계 확산 용이 | 높음, 현재는 일부 구간(금융망 등)에 한정 |

**비교/활용사례**: RSA·ECC가 향후 양자컴퓨터(쇼어 알고리즘)에 깨질 것에 대비해, 정부가 2035년까지 국가 정보통신기반시설에 PQC 전환을 추진 중(국가 PQC 전환 마스터플랜)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 타원곡선암호(ECC) | 현재 표준이지만 양자컴퓨터 등장 시 PQC로 대체되어야 하는 대상 |
| 양자컴퓨터(큐비트/양자우월성) | PQC/QKD 등장의 근본 배경(양자컴퓨터의 암호해독 위협) |
| RSA(소인수분해 기반) | 쇼어 알고리즘으로 양자컴퓨터가 깰 수 있는 대표적 비대칭암호 |

## 4. 타원곡선암호 (ECC, Elliptic Curve Cryptography)

**암호 원리**
> 타원곡선 위의 점들이 만드는 **이산대수문제(ECDLP)**의 계산적 어려움을 이용한 비대칭암호. 타원곡선 방정식: y² = x³ + ax + b (mod p)

**유형 분류**: ECDH(타원곡선 기반 키교환), ECDSA(타원곡선 기반 전자서명)

**비교/활용사례 (RSA와 비교)**

| 구분 | RSA | ECC |
|---|---|---|
| 보안근거 | 소인수분해 문제 | 타원곡선 이산대수문제 |
| 동일 보안강도의 키길이 | 2048bit 필요 | **256bit**로 충분(약 8배 짧음) |
| 연산속도/리소스 | 느림, 키길이가 길어 부담 | 빠름, 짧은 키로 동일보안(IoT·모바일에 적합) |

**활용사례**: 모바일/IoT 기기 인증(연산자원 제약 환경), 비트코인 등 블록체인 전자서명(ECDSA)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| RSA vs DSA | ECC는 DSA(전자서명)를 타원곡선으로 구현한 ECDSA와 직결(아래 키워드) |
| PQC | ECC도 양자컴퓨터에 취약해 PQC로의 전환대상에 포함 |

## 5. 블록암호 4모드 (ECB / CBC / CFB / OFB)

**암호 원리**
> 블록암호(AES 등)는 고정된 크기(예 128bit)의 블록 단위로만 암호화 가능 → 여러 블록을 연속으로 안전하게 암호화하기 위한 **운용모드(Mode of Operation)**가 4가지 필요

**유형 분류**

| 모드 | 동작방식 | 특징 |
|---|---|---|
| **ECB(Electronic CodeBook)** | 각 블록을 독립적으로 암호화 | 단순하나 동일평문블록→동일암호문블록(패턴노출 취약) |
| **CBC(Cipher Block Chaining)** | 이전 블록의 암호문을 현재 블록과 XOR 후 암호화(체이닝) | 패턴 은닉 우수, 순차적 처리 필요(병렬화 어려움) |
| **CFB(Cipher FeedBack)** | 블록암호를 스트림암호처럼 사용(이전 암호문을 암호화해 평문과 XOR) | 블록단위 아닌 비트/바이트 단위 처리 가능 |
| **OFB(Output FeedBack)** | 키스트림을 미리 생성(평문과 무관)해 평문과 XOR | 키스트림을 사전 생성 가능(병렬화 용이), 오류 전파 안됨 |

**비교/활용사례**: ECB는 보안상 거의 사용 금지(패턴노출), CBC는 파일암호화 등 범용적으로 가장 널리 사용, CFB/OFB는 실시간 스트리밍 데이터 암호화에 적합

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| AES(고급암호표준) | 4가지 모드가 실제로 적용되는 대표 대칭암호 알고리즘 |
| GCM(Galois/Counter Mode) | 최근 TLS1.3 등에서 표준으로 채택된 5번째 모드(암호화+인증 동시제공, 출제 확장 가능) |
| 전자봉투 | 대칭암호 모드로 암호화된 본문데이터가 전자봉투의 핵심 구성요소 |

## 6. 해시함수 (Rainbow Table / Salt / 키스트레칭)

**암호 원리**
> 임의 길이의 입력을 고정길이의 출력(다이제스트)으로 변환하는 **일방향(복호화 불가능)** 함수. H(x) = h, 역으로 h에서 x를 구하기는 사실상 불가능해야 함

**유형 분류 (공격과 방어기법)**

| 구분 | 내용 |
|---|---|
| **Rainbow Table(공격)** | 미리 계산된 "평문-해시값" 쌍의 거대한 테이블로 역추적 시도 |
| **Salt(방어1)** | 비밀번호마다 다른 임의값(Salt)을 추가해 해시 → 같은 비밀번호도 사용자마다 해시값이 달라져 Rainbow Table 무력화 |
| **키 스트레칭(방어2)** | 해시 연산을 수천~수만번 반복(PBKDF2, bcrypt 등)해 공격자의 대량 시도(Brute-force) 비용을 비현실적으로 증가시킴 |

**비교/활용사례**: 비밀번호 저장(평문저장 절대금지, Salt+키스트레칭 해시값만 저장), 데이터 무결성 검증(파일 변조 여부 확인), 블록체인의 블록 연결(이전블록 해시값 포함)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| MAC(메시지인증코드) | 해시함수에 비밀키를 추가로 결합해 무결성+인증을 동시에 제공하는 확장기법 |
| RSA/DSA(전자서명) | 전자서명 시 원문 전체가 아닌 "해시값"에 서명해 효율성 확보 |
| 디피헬만 | 해시함수와 함께 키교환 프로토콜의 부속요소로 활용(키유도함수 등) |

## 7. RSA vs DSA

**암호 원리**
- **RSA**: 소인수분해의 어려움 기반, 암호화·복호화·전자서명에 모두 사용 가능한 범용 비대칭암호
- **DSA(Digital Signature Algorithm)**: **전자서명 전용**으로 설계, 이산대수문제 기반(암호화/복호화 용도로는 사용 불가)

**유형 분류 및 비교**

| 구분 | RSA | DSA |
|---|---|---|
| 용도 | 암호화+전자서명 모두 가능 | 전자서명 전용(암호화 불가) |
| 보안근거 | 소인수분해 문제 | 이산대수문제 |
| 서명 생성속도 | 느림 | 빠름 |
| 서명 검증속도 | 빠름 | RSA보다 느림 |

**비교/활용사례**: RSA는 SSL/TLS 인증서, 전자봉투의 키교환에 널리 사용 / DSA(및 ECDSA)는 빠른 서명 생성이 중요한 환경(블록체인 트랜잭션 서명 등)에 적합

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 타원곡선암호(ECC) | DSA를 타원곡선으로 구현한 ECDSA로 발전(키길이 단축) |
| 전자봉투 | RSA가 전자봉투의 키 암호화(봉투 봉인) 단계에서 사용되는 대표 알고리즘 |
| PKI(공개키기반구조) | RSA/DSA 인증서를 발급·관리하는 상위 신뢰체계 |

## 8. 디피헬만 (Diffie-Hellman) 키교환

**암호 원리**
> 통신 양측이 **암호화할 데이터 없이도, 공개된 통신채널에서 안전하게 공통의 비밀키를 만들어내는** 알고리즘. 이산대수문제 기반
```
A: 비밀값 a 선택 → 공개값 g^a mod p 전송
B: 비밀값 b 선택 → 공개값 g^b mod p 전송
A: (g^b)^a mod p 계산 = g^ab mod p
B: (g^a)^b mod p 계산 = g^ab mod p
→ 양측 모두 동일한 g^ab(공통 비밀키) 보유, 도청자는 a,b를 몰라 역산 불가
```

**유형 분류**: 기본 DH(고정키), ECDH(타원곡선 기반, 더 짧은키로 동일 보안)

**비교/활용사례**: TLS 핸드셰이크에서 세션키 생성, VPN(IPSec)의 IKE 키교환 단계

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 전방위 비밀성(PFS) | 디피헬만 키교환을 매 세션마다 새로 수행하면 PFS를 달성(TLS1.3 강제사항) |
| TLS1.3(1-RTT) | 디피헬만 키교환이 실제로 일어나는 핸드셰이크 단계 |
| RSA | 과거에는 RSA로 키를 직접 교환했으나, PFS 미지원 문제로 디피헬만 기반 키교환으로 전환 |

## 9. 전자봉투 (Digital Envelope)

**암호 원리**
> 대용량 데이터는 빠른 **대칭키**로 암호화하고, 그 대칭키 자체는 수신자의 **공개키**로 암호화해 함께 전송하는 하이브리드 방식(대칭+비대칭 결합)

**생성절차**
```
1. 송신자가 임의의 대칭키(세션키) 생성
2. 원본데이터를 대칭키로 암호화 → 암호문 생성
3. 대칭키를 수신자의 공개키로 암호화 → "봉투(암호화된 키)" 생성
4. [암호문 + 봉투]를 함께 전송
```

**개봉절차**
```
1. 수신자가 자신의 개인키로 "봉투"를 복호화 → 대칭키(세션키) 획득
2. 획득한 대칭키로 암호문을 복호화 → 원본데이터 획득
```

**비교/활용사례**: S/MIME(이메일 암호화), 전자문서유통, 공인인증서 기반 전자결재 시스템

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 대칭/비대칭암호 | 전자봉투는 두 방식을 결합한 가장 대표적인 실무 적용 패턴 |
| RSA | 봉투(키) 암호화 단계에서 흔히 사용되는 비대칭암호 알고리즘 |
| 블록암호 4모드 | 봉투 안의 본문 데이터를 실제로 암호화하는 대칭암호의 운용모드 |

## 10. 암호문공격 (Ciphertext Attack)

**암호 원리(공격자 관점의 분류 기준 = 공격자가 확보한 정보의 종류)**

**유형 분류**

| 공격유형 | 공격자가 가진 정보 | 목표 |
|---|---|---|
| **암호문단독공격(Ciphertext-only)** | 암호문만 확보 | 통계적 분석으로 평문/키 추측(가장 어려운 공격) |
| **알려진평문공격(Known-plaintext)** | 일부 평문-암호문 쌍을 알고 있음 | 나머지 암호문 해독 |
| **선택평문공격(Chosen-plaintext)** | 임의 평문을 암호화시켜볼 수 있음 | 암호시스템의 키/패턴 추론 |
| **선택암호문공격(Chosen-ciphertext)** | 임의 암호문을 복호화시켜볼 수 있음 | 가장 강력한 공격모델 |

**비교/활용사례**: 암호 알고리즘 설계 시 "암호문단독공격에도 안전한가"는 최소요건, 최신 암호시스템은 가장 강력한 "선택암호문공격"에도 안전하도록 설계(IND-CCA 안전성)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| ECB모드 취약점 | 동일평문→동일암호문 패턴이 암호문단독공격의 단서가 되는 대표 취약사례 |
| Rainbow Table | 해시함수에 대한 암호문단독공격과 유사한 사전계산 기반 공격기법 |
| PQC | 양자컴퓨터를 이용한 공격(쇼어/그로버 알고리즘)도 암호문공격의 미래 확장형태 |

## 종합 흐름도

```
[기초원리] 대칭암호(빠름) ←→ 비대칭암호(느림, 키분배 용이)
        │
        ├──→ 전자봉투(하이브리드: 비대칭으로 키교환 + 대칭으로 본문암호화)
        │
        ├──→ 디피헬만(비대칭원리로 키교환 전용) ──→ RSA vs DSA(서명/암호화 용도분리)
        │                                              │
        │                                         타원곡선암호(ECC, 짧은키로 동일보안)
        │
        ├──→ 블록암호 4모드(대칭암호의 안전한 운용방식)
        │
        ├──→ 해시함수(일방향) + Salt/키스트레칭(Rainbow Table 방어)
        │
        └──→ PQC vs QKD(양자컴퓨터 위협에 대응하는 차세대 암호)
                    │
              [공격관점] 암호문공격 4유형 — 모든 암호시스템이 방어해야 할 위협모델
```
