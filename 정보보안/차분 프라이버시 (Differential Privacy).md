### **차분 프라이버시 (Differential Privacy)**

#### **프라이버시 보장 수학적 기반: 차분 프라이버시 (Differential Privacy)**

***

#### 답안 전체 스토리 흐름 (목차)

```
Ⅰ. 개요 (왜 "익명화"만으로는 프라이버시를 보장 못 하는가)
Ⅱ. 차분 프라이버시 핵심 원리 및 수식
Ⅲ. 구현 메커니즘 및 적용 체계
Ⅳ. 결론
```

포인트: 개요에서 \*\*"앞서 다룬 Hoepman 8대 전략의 추상화(Abstract) 전략이 '개인 식별 수준을 낮추는 설계 원칙'이라면, 차분 프라이버시(Differential Privacy·DP)는 그 원칙을 수학적으로 엄밀하게 구현하는 기법이다 — 단순 익명화·k-익명성이 배경 지식 공격(재식별 공격)에 취약한 근본 한계를 Cynthia Dwork이 2006년 제안한 DP가 '단일 개인의 데이터 포함 여부가 쿼리 결과에 수학적으로 구별 불가능한 영향만 미치도록 노이즈를 추가'함으로써 해소하며, 앞서 다룬 멤버십 추론 공격·DP-SGD·HaveIBeenPwned k-익명성이 모두 차분 프라이버시의 실무 구현 형태"\*\*라는 한 줄로 시작하면 전체 맥락이 드러납니다.

***

#### Ⅱ. 차분 프라이버시 핵심 원리 및 수식

**가. 핵심 정의 및 직관**

```
[차분 프라이버시 직관적 이해]

홍길동이 데이터셋에 포함된 경우:
  쿼리 결과 분포: M(D)

홍길동이 데이터셋에 미포함된 경우:
  쿼리 결과 분포: M(D')

차분 프라이버시 보장:
  두 분포가 수학적으로 거의 구별 불가능
  → 공격자가 결과를 봐도
    홍길동의 데이터 포함 여부 판단 불가 ✅
```

**나. 핵심 수식 및 파라미터**

| **핵심 척도**  | **📊 ε-차분 프라이버시 정의 🚨**                                                                                            | **🔑 노이즈 메커니즘 🚨**                                                                                         | **🏁 DP-SGD·실무 적용 💯**                                                                     |
| :--------- | :----------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------- |
| **핵심 수식**  | **Pr\[M(D) ∈ S] ≤ e^ε × Pr\[M(D') ∈ S]** / D·D': 인접 데이터셋(1개 레코드 차이) / ε(엡실론): 프라이버시 예산 / ε 작을수록 강한 프라이버시 보장        | **라플라스 메커니즘**: 연속형 수치 / 노이즈 ~ Lap(Δf/ε) / Δf: 전역 민감도(함수 최대 변화량) / **가우시안 메커니즘**: (ε,δ)-DP / 가우시안 분포 노이즈 추가 | **DP-SGD**: ML 학습 그래디언트에 가우시안 노이즈 추가 / 배치별 그래디언트 클리핑+노이즈 / 앞서 다룬 **멤버십 추론 공격** 방어 핵심 수단    |
| **ε 파라미터** | **ε=0**: 완벽 프라이버시 (쿼리 불가) / **ε=1**: 강한 보장 (실용적 시작점) / **ε=10**: 약한 보장 / **ε→∞**: 프라이버시 없음 / **실무**: ε=1\~10 범위 사용 | **전역 민감도(Δf)**: 1개 레코드 변화 시 함수 최대 변화량 / 평균 쿼리: Δf=1/n / COUNT 쿼리: Δf=1 / 민감도가 낮을수록 노이즈 少                   | **프라이버시 예산 관리**: 반복 쿼리마다 ε 소진 / 컴포지션 정리: k번 쿼리 → 총 kε 소진 / 앞서 다룬 **MLOps**: 학습 반복당 ε 추적·관리 |
| **보장 수준**  | **순수 DP(ε-DP)**: 가장 강한 보장 / **(ε,δ)-DP**: δ 확률로 예외 허용 / **지역 DP(LDP)**: 개인이 직접 노이즈 추가 / Apple·Google RAPPOR 적용     | **지역 차분 프라이버시(LDP)**: 서버에 원본 전송 없음 / 랜덤화 응답(Randomized Response) / Apple iOS 사용 통계 수집 / 구글 Chrome 히스토그램    | **앞서 다룬 HaveIBeenPwned**: k-익명성 = DP 유사 개념 / SHA-1 앞 5자리만 전송 / 서버가 전체 해시 보유 안 함            |

#### Ⅲ. 구현 메커니즘 및 적용 체계

**가. 라플라스 메커니즘 예시**

```
[차분 프라이버시 적용 예시]

시나리오: 직원 평균 급여 쿼리

①민감도 계산
  평균 함수 전역 민감도(Δf) = 최대급여/n
  = 10,000만원 / 1,000명 = 10만원

②노이즈 생성 (ε=1 설정)
  노이즈 ~ Lap(Δf/ε) = Lap(10만원)
  생성 노이즈: +7.3만원 (랜덤)

③공개 결과
  실제 평균: 350만원
  공개 값: 357.3만원 (노이즈 포함)
  → 특정 개인 급여 역산 불가 ✅

[DP-SGD AI 학습 적용]

표준 SGD:
  그래디언트 계산 → 모델 업데이트
  → 학습 데이터 멤버십 추론 취약 🚨

DP-SGD:
  그래디언트 계산
       ↓
  그래디언트 클리핑 (최대 norm C)
  → 개인 기여 상한 제한
       ↓
  가우시안 노이즈 추가 (σ 비례)
       ↓
  모델 업데이트
  → 멤버십 추론 공격 방어 ✅
  → ε 예산 소진 추적
```
