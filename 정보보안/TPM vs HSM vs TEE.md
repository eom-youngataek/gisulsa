### **하드웨어 기반 보안 신뢰 루트: TPM vs HSM vs TEE**

***

#### 답안 전체 스토리 흐름 (목차)

```
Ⅰ. 개요 (왜 소프트웨어 암호화만으로는 신뢰를 보장 못 하는가)
Ⅱ. TPM·HSM·TEE 핵심 원리
Ⅲ. 비교 및 적용 체계
Ⅳ. 결론
```

포인트: 개요에서 \*\*"앞서 다룬 패스더해시·골든 티켓이 '메모리에서 자격증명을 탈취'하는 공격이라면, TPM·HSM·TEE는 '암호화 키와 민감 연산을 하드웨어 격리 영역에 가둬 운영체제·관리자 권한이 침해되어도 키 자체는 탈취 불가능하게 만드는 하드웨어 신뢰 루트(Root of Trust)'다 — TPM(Trusted Platform Module)이 '기기 무결성 증명과 키 저장에 특화된 보급형 보안 칩'이라면, HSM(Hardware Security Module)은 '고성능 암호 연산에 특화된 엔터프라이즈 전용 장비', TEE(Trusted Execution Environment)는 '프로세서 내부에 격리된 신뢰 실행 공간'으로 목적과 성능·비용 계층이 다른 3대 하드웨어 보안 기술이며, 앞서 다룬 온디바이스 NPU의 생체인식 처리·Argon2 키 관리·SLSA 공급망 서명이 이들 위에서 구현되는 하드웨어 보안의 3층 구조"\*\*라는 한 줄로 시작하면 전체 맥락이 드러납니다.

***

#### Ⅱ. TPM·HSM·TEE 핵심 원리

**가. TPM (Trusted Platform Module) 핵심 원리**

```
[TPM 핵심 기능]

①플랫폼 무결성 측정 (Measured Boot)
  부팅 각 단계(BIOS→부트로더→OS) 해시값을
  PCR(Platform Configuration Register)에 순차 기록
  → 부팅 과정 변조 여부 검증 가능

②키 생성·저장
  EK(Endorsement Key): 제조 시 내장·기기 고유 식별
  SRK(Storage Root Key): 다른 키들의 암호화 루트
  키가 TPM 밖으로 절대 유출 안 됨 ✅

③원격 증명 (Remote Attestation)
  PCR 값을 서명해 원격 서버에 전송
  → "이 기기는 변조되지 않았다" 증명

④봉인(Sealing)
  특정 PCR 상태에서만 복호화 가능하도록 데이터 봉인
  부팅 상태 변경 시 복호화 불가
```

***

**나. HSM (Hardware Security Module) 핵심 원리**

```
[HSM 핵심 기능]

①고성능 암호 연산
  초당 수천~수만 건 서명·암복호화
  전용 암호 프로세서 탑재

②키 생명주기 관리
  생성→저장→사용→로테이션→파기
  FIPS 140-2/3 Level 3~4 인증

③물리적 변조 방지 (Tamper Response)
  물리적 침입 감지 시 키 즉시 자동 삭제(Zeroization)
  에폭시 코팅·센서 메시로 물리 보호

④다중 승인 (M of N)
  키 사용에 복수 관리자 승인 필요
  단일 내부자 위협 방지
```

***

**다. TEE (Trusted Execution Environment) 핵심 원리**

```
[TEE 핵심 기능]

①격리된 실행 환경
  Secure World / Normal World 분리
  (ARM TrustZone·Intel SGX)
  OS 커널이 침해돼도 Secure World 접근 불가

②암호화된 연산
  Enclave 내부 데이터는 메모리에서도 암호화
  RAM 덤프해도 평문 노출 안 됨

③원격 증명 (Attestation)
  Enclave 코드 자체의 무결성 증명
  변조된 코드 실행 시 증명 실패
```

***

#### Ⅲ. 비교 및 적용 체계

**가. TPM vs HSM vs TEE 핵심 비교**

| 비교 항목       | TPM           | HSM                  | TEE                     |
| :---------- | :------------ | :------------------- | :---------------------- |
| **형태**      | 마더보드 내장 칩     | 별도 전용 장비/카드          | CPU 내부 격리 영역            |
| **주요 목적**   | 기기 무결성·부팅 검증  | 고성능 암호 연산·키 관리       | 민감 연산 격리 실행             |
| **성능**      | 낮음 (저속 연산)    | **매우 높음** (전용 프로세서)  | 높음 (CPU 자체 속도)          |
| **비용**      | 매우 저렴 (수달러)   | **매우 고가** (수백\~수천만원) | 추가 비용 없음 (CPU 내장)       |
| **인증 표준**   | ISO/IEC 11889 | FIPS 140-2/3         | 프로세서별 자체 표준             |
| **적용 대상**   | PC·노트북·IoT 기기 | 금융·CA·클라우드 KMS       | 모바일·서버 CPU              |
| **대표 구현**   | TPM 2.0 칩     | Thales·AWS CloudHSM  | ARM TrustZone·Intel SGX |
| **키 유출 방어** | 물리 칩 분리       | 물리 변조 감지·자동 삭제       | 메모리 암호화·격리              |

**나. 앞서 다룬 개념과의 연결**

| 연계 개념             | 연결 내용                                      |
| :---------------- | :----------------------------------------- |
| **패스더해시·골든 티켓**   | TPM 기반 Credential Guard가 lsass 해시를 VBS로 격리 |
| **온디바이스 NPU**     | TEE(TrustZone) 내에서 생체인식 AI 추론 수행           |
| **Bcrypt·Argon2** | HSM이 마스터 키를 물리적으로 보관·키 유도 가속               |
| **SLSA 공급망**      | HSM/TEE 기반 Sigstore 키리스 서명의 신뢰 루트          |
| **SDP**           | mTLS 인증서 개인키를 TPM에 저장해 탈취 방지               |
| **N2SF·CSAP**     | 국가 기밀 등급 시스템의 HSM 사용 의무화                   |

***

**다. 적용 시나리오별 선택 기준**

| 시나리오                      | 권장 기술         | 이유                   |
| :------------------------ | :------------ | :------------------- |
| **PC 디스크 암호화(BitLocker)** | TPM           | 부팅 무결성 검증 연계         |
| **인증서 발급기관(CA) 루트키**      | **HSM**       | FIPS 인증·물리 변조 방지 필수  |
| **은행 카드 PIN 처리**          | **HSM**       | 초당 대량 트랜잭션 암호 연산     |
| **스마트폰 생체인증·결제**          | **TEE**       | CPU 내장·추가 하드웨어 비용 없음 |
| **클라우드 기밀 컴퓨팅**           | TEE (SGX·SEV) | 클라우드 관리자도 접근 불가      |
| **국가 기밀 시스템**             | HSM + TPM 이중  | 최고 등급 보안 요건          |

***

**(제언)** "TPM·HSM·TEE는 '어디에 신뢰의 뿌리를 심을 것인가'라는 질문에 각기 다른 답을 제시하는 하드웨어 보안의 3계층입니다. **앞서 다룬 패스더해시 방어의 Credential Guard는 TPM 기반 VBS로 자격증명을 격리하고, 온디바이스 NPU의 생체인식 처리는 TEE Secure World에서 실행되며, SLSA 공급망 서명의 최상위 신뢰 루트는 HSM이 담당하는 것처럼 세 기술은 경쟁이 아닌 계층적 협력 관계이므로, 시스템 설계 시 기기 무결성(TPM)·고성능 키 관리(HSM)·민감 연산 격리(TEE)를 용도에 맞게 조합하는 것이 하드웨어 신뢰 루트 설계의 핵심 전략입니다.**"
