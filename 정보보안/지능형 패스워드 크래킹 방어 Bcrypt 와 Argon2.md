포인트: 개요에서 \*\*"앞서 다룬 크리덴셜 스터핑·인포스틸러가 '탈취한 해시로 패스워드를 역산하는 위협'이라면, Bcrypt와 Argon2는 '패스워드 해시를 의도적으로 느리고 자원 집약적으로 만들어 무차별 대입(Brute Force) 공격의 연산 비용을 수억 배 높이는 패스워드 전용 해시 함수'다 — MD5·SHA-256은 초당 수백억 번 해시 계산이 가능해 GPU 크래킹에 무방비이나, Bcrypt는 Work Factor로 계산 비용을 조절하고 Argon2는 메모리·병렬성·시간 3축으로 공격 자원을 고갈시켜 앞서 다룬 개인정보 안전조치의 비밀번호 일방향 암호화 의무를 실질적으로 이행하는 현대 패스워드 보호의 사실상 표준"\*\*이라는 한 줄로 시작하면 전체 맥락이 드러납니다.

#### Ⅱ. Bcrypt 핵심 원리

**가. Bcrypt 구조**

```
[Bcrypt 해시 구조]

$2b$12$SaltSaltSaltSaltSaltSaHashHashHashHashHashHashHashHash

$2b$   : Bcrypt 버전
12     : Work Factor (cost factor)
Salt   : 22자 랜덤 솔트 (자동 생성·내장)
Hash   : 31자 해시값

Work Factor 의미:
  2^12 = 4,096번 반복 연산
  Work Factor 1 증가 → 연산 시간 2배
  → GPU 병렬 크래킹 비용 기하급수 증가
```

***

**나. Bcrypt 핵심 특성**

| 항목              | 내용                                                       |
| :-------------- | :------------------------------------------------------- |
| **기반 알고리즘**     | Blowfish 블록 암호 기반 / Niels Provos·David Mazières 1999년 설계 |
| **Work Factor** | 4\~31 범위 / 실무 권장 12\~14 / 서버 성능에 따라 조정                   |
| **자동 솔팅**       | 128비트 랜덤 솔트 자동 생성·해시에 내장 / 레인보우 테이블 무력화                  |
| **출력 길이**       | 항상 60자 고정 / 버전·Work Factor·솔트·해시 통합                      |
| **한계**          | 최대 72바이트 입력 제한 🚨 / 메모리 하드닝 없음 / GPU 병렬화 부분 취약           |

#### Ⅲ. Argon2 핵심 원리

**가. Argon2 3대 변형**

| 변형           | 특화                             | 적용                   |
| :----------- | :----------------------------- | :------------------- |
| **Argon2d**  | 데이터 의존 메모리 접근 / GPU 공격 최적 방어   | 암호화폐·비대화형 서비스        |
| **Argon2i**  | 데이터 독립 메모리 접근 / 사이드채널 공격 방어    | 패스워드 해싱·키 유도         |
| **Argon2id** | d+i 하이브리드 / **PHC 우승·권장 표준** ✅ | **일반 패스워드 저장 실무 표준** |

***

**나. Argon2 3대 비용 파라미터**

| **핵심 척도** | **📊 메모리 비용 (m) 🚨**                                 | **🔑 시간 비용 (t) 🚨**                    | **🏁 병렬성 (p) 💯**                  |
| :-------- | :--------------------------------------------------- | :------------------------------------- | :--------------------------------- |
| **정의**    | 연산에 사용할 **메모리 크기(KB)** / 높을수록 메모리 집약적                | 알고리즘 **반복 횟수** / 높을수록 연산 시간↑           | 사용할 **스레드·레인 수** / 공격자 병렬화 제한      |
| **공격 억제** | GPU는 코어당 메모리 매우 少 / 대용량 메모리 요구 → **GPU 병렬 공격 원천 차단** | 반복 증가 → 연산 시간 선형 증가 / 공격자 시도당 비용 직접 상승 | 서버는 p=4 설정 / 공격자가 p=1만 사용 시 4배 느려짐 |
| **권장 설정** | m = 64MB↑ (OWASP 권장) / 고보안: 256MB↑                   | t = 1\~3 (m이 높으면 t=1도 충분)              | p = 서버 CPU 코어 수 기준                 |

#### Ⅳ. 비교 및 실무 적용

**가. 전체 비교표**

| 비교 항목       | MD5·SHA-256 | Bcrypt          | Argon2id             |

| **설계 목적**   | 일반 해시·무결성   | 패스워드 전용         | 패스워드 전용              |

**나. 도식화**

```
[패스워드 크래킹 방어 원리]

공격자 시나리오: GPU 1,000개로 크래킹 시도

MD5/SHA-256:
  GPU 1,000개 × 10억 해시/초 = 1조 해시/초
  8자리 패스워드: 수초 내 크래킹 🚨

Bcrypt (Work Factor=12):
  GPU당 Blowfish 4,096회 반복
  메모리 집약 낮아 GPU 일부 효과
  8자리 패스워드: 수일~수주

Argon2id (m=64MB, t=1, p=4):
  GPU 코어당 64MB 메모리 필요
  GPU 1,000개 → 실제 수십 개만 동작
  8자리 패스워드: 수년~수십 년 ✅

[솔팅 효과]
  레인보우 테이블 공격:
  솔트 없음 → 사전 계산 테이블 재사용 🚨
  솔트 있음 → 사용자마다 고유 해시
            → 레인보우 테이블 무효 ✅

[실무 구현 예시]
// Argon2id (Python)
import argon2
ph = argon2.PasswordHasher(
    time_cost=1,
    memory_cost=65536,  # 64MB
    parallelism=4,
    hash_len=32
)
hash = ph.hash("user_password")
ph.verify(hash, "user_password")  # 검증
```

***

**(제언)** "Bcrypt와 Argon2는 패스워드를 '느리게 해싱하는 것이 오히려 보안'이라는 역발상의 산물입니다. **앞서 다룬 개인정보 안전조치의 비밀번호 일방향 암호화 의무를 이행할 때 MD5·SHA-1은 절대 사용하지 말고, 신규 시스템은 NIST가 권장하는 Argon2id(m≥64MB), 레거시 호환이 필요하면 Bcrypt(Work Factor≥12)를 선택하며, 앞서 다룬 패스키(FIDO2)로 전환해 패스워드 자체를 제거하는 것이 크리덴셜 스터핑·인포스틸러 위협으로부터 사용자 계정을 근본적으로 보호하는 최선의 전략입니다.**"
