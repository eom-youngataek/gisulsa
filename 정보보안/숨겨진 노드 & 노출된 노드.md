### **무선 네트워크 MAC 계층 핵심 문제: 숨겨진 노드 & 노출된 노드**

***

```

Ⅳ. 해결 메커니즘 및 비교
```

포인트: 개요에서 \*\*"앞서 다룬 차량용 이더넷·TSN이 '유선 기반 결정론적 실시간 통신'을 다룬다면, 무선 네트워크의 MAC 계층은 '공유 매체에서 충돌 없이 통신 기회를 분배하는 문제'를 다루며, 그 핵심 장애물이 숨겨진 노드(Hidden Node)와 노출된 노드(Exposed Node) 문제다 — 유선 이더넷은 CSMA/CD로 충돌을 감지하나 무선은 자신의 송신 중 수신 신호를 탐지하기 어려워 CSMA/CA(충돌 회피)를 사용하고, 숨겨진 노드는 '서로를 감지 못하는 두 노드가 동시에 같은 AP에 송신해 충돌'하는 문제, 노출된 노드는 '송신 중인 노드를 감지한 다른 노드가 불필요하게 전송을 자제해 네트워크 효율이 저하'되는 반대 문제이며, IEEE 802.11의 RTS/CTS 핸드셰이킹이 두 문제를 동시에 해소하는 핵심 메커니즘"\*\*이라는 한 줄로 시작하면 전체 맥락이 드러납니다.

***

#### Ⅱ. 숨겨진 노드 문제 핵심 원리

**가. 숨겨진 노드 발생 구조**

```
[숨겨진 노드 (Hidden Node Problem)]

물리적 배치:
  노드A ←── 전파 범위 ──→ AP ←── 전파 범위 ──→ 노드B
  |←────── A 범위 ────→|        |←──── B 범위 ────→|
  A와 B는 서로 전파 범위 밖 → 상대 감지 불가

문제 발생:
  ①노드A: 채널 조용함 → AP로 전송 시작
  ②노드B: 채널 조용함 (A 감지 못함) → AP로 전송 시작
  ③AP: A·B 신호 동시 수신 → 충돌(Collision) 🚨
  ④A·B: 자신의 송신만 알고 충돌 인지 불가

결과:
  AP에서 패킷 손상 → 재전송 급증
  처리량(Throughput) 급감 🚨
  지연 증가·연결 불안정
```

***

#### Ⅲ. 노출된 노드 문제 핵심 원리

**가. 노출된 노드 발생 구조**

```
[노출된 노드 (Exposed Node Problem)]

물리적 배치:
  AP1 ←── A 범위 ──→ 노드A ←── A·B 겹침 ──→ 노드B ←── B 범위 ──→ AP2
  노드A와 노드B는 서로 감지 가능

문제 발생:
  ①노드A: AP1로 전송 시작 (채널 사용 중)
  ②노드B: 노드A 전송 감지 → "채널 사용 중" 판단
  ③노드B: AP2로의 전송 자제 (불필요한 대기) 🚨
  ④실제: 노드B → AP2 전송은 A→AP1과 충돌 없음

결과:
  B의 AP2 전송은 A에 간섭 안 줌
  → 불필요한 전송 억제 → 채널 낭비 🚨
  → 네트워크 효율 저하
```

#### Ⅳ. 해결 메커니즘 및 비교

**가. RTS/CTS 핵심 체계**

| **핵심 척도**      | **📊 RTS/CTS 동작 원리 🚨**                                                                                                                                                                  | **🔑 숨겨진 노드 해결 🚨**                                                                                                                         | **🏁 노출된 노드 해결·한계 💯**                                                                                               |
| :------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------- |
| **RTS/CTS 구조** | **RTS(Request To Send)**: 송신 노드 → AP / 전송 예약 요청·데이터 크기·시간 포함 / **CTS(Clear To Send)**: AP → 전체 범위 브로드캐스트 / "이 시간 동안 나에게 송신 금지" / **NAV(Network Allocation Vector)**: CTS 수신 노드가 대기 시간 설정 | **숨겨진 노드 해결**: AP의 CTS가 A·B 모두에게 도달 / A·B가 서로 감지 못해도 AP CTS는 둘 다 수신 / CTS에 전송 기간 명시 → A는 B의 RTS 후 CTS 보고 대기 / **결과**: AP 기준 송신 조율 → 충돌 방지 ✅ | **노출된 노드 부분 해결**: B가 A의 RTS 감지 → NAV 설정 불필요 / B가 A의 RTS만 듣고 CTS 못 들으면 → 전송 가능 판단 / 완전 해결은 어려움 🚨 / 방향성 안테나·채널 분리로 보완 |
| **CSMA/CA 연계** | **CSMA/CA 기본 흐름**: 채널 감지(CS) → 유휴 확인 → DIFS 대기 → 랜덤 백오프 → 전송 / RTS/CTS는 CSMA/CA 위에 추가 핸드셰이킹 / **소규모 패킷**: RTS/CTS 오버헤드 > 이득 → 임계값 이상 패킷만 적용                                              | **4-way 핸드셰이킹**: RTS → CTS → Data → ACK / ACK: 수신 확인으로 충돌 최종 검증 / **NAV 타이머**: CTS 수신 노드 전송 억제 시간 / 앞서 다룬 **TSN 타임 슬롯**과 유사한 시간 분할 개념       | **RTS/CTS 한계**: 오버헤드 증가 (소패킷 비효율) / RTS 자체 충돌 가능 / 다중 AP 환경 복잡 / **보완책**: 채널 본딩·OFDMA(Wi-Fi 6)·공간 분할 다중화             |

***

**나. 도식화**

```
[RTS/CTS 동작 전체 흐름]

숨겨진 노드 해결:

  노드A              AP                노드B
    │──RTS(A→AP)──→│                  │
    │               │←──RTS(B→AP)──── │  (동시 시도 시 RTS 충돌)
    │               │                  │
    │               │──CTS(AP 브로드캐스트)──────────→│
    │←──────────────│CTS 수신          │CTS 수신
    │               │                  │NAV 설정(대기)
    │──Data────────→│                  │(전송 억제)
    │               │──ACK────────────→│
    │               │                  │(NAV 해제 후 RTS 재시도)

노출된 노드 상황:

  AP1    노드A    노드B    AP2
   │←Data──│         │──Data──→│  ← 동시 가능 (충돌 없음)
   │        │──RTS──→│         │
   │        │        │(RTS만 듣고
   │        │        │ CTS 못 받으면
   │        │        │ 전송 가능 판단)
   │        │        │──RTS──────────→│
   │        │        │←──────CTS──────│
   │        │        │──Data──────────→│ ✅

[Wi-Fi 6(802.11ax) OFDMA 개선]
기존: 단일 사용자 채널 점유
OFDMA: 채널을 RU(Resource Unit)로 분할
  → 여러 노드 동시 전송
  → 숨겨진·노출된 노드 문제 근본 완화 ✅
  앞서 다룬 5G OFDMA와 동일 원리
```

***

**다. 숨겨진 노드 vs 노출된 노드 비교**

| 비교 항목          | 숨겨진 노드           | 노출된 노드              |
| :------------- | :--------------- | :------------------ |
| **문제 본질**      | 충돌 발생 (감지 못해서)   | 효율 저하 (불필요 대기)      |
| **인지 실패**      | 상대 노드 존재 미인지     | 상대 전송이 자신에게 무해함 미인지 |
| **결과**         | AP에서 패킷 충돌·손상 🚨 | 채널 낭비·처리량 감소 🚨     |
| **RTS/CTS 효과** | 완전 해결 ✅          | 부분 해결               |
| **심각도**        | 높음 (데이터 손실)      | 중간 (효율 저하)          |

***

**(제언)** "숨겨진 노드와 노출된 노드는 무선 네트워크의 공유 매체 특성에서 비롯되는 구조적 문제로, RTS/CTS가 AP를 중재자로 활용해 전자를 효과적으로 해결합니다. **앞서 다룬 차량용 이더넷·TSN의 결정론적 시간 슬롯 할당 철학이 Wi-Fi 6의 OFDMA·BSS Coloring·MU-MIMO로 무선에 구현되면서 숨겨진·노출된 노드 문제를 근본적으로 완화하고 있으며, 5G NR의 스케줄러 기반 자원 할당이 중앙 집중 조율로 이 두 문제를 원천 해소하는 방향으로 진화하는 것이 무선 MAC 설계의 핵심 트렌드입니다.**"
