# 사이버위협 및 공격기법 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 공격 메커니즘/구조도 → 영향(피해범위) → 기술적·관리적 대응(이중구조)

---

## 1. 랜섬웨어 / RaaS (Ransomware as a Service)

**공격 메커니즘/구조도**
```
[침투] 피싱메일/취약점/RDP탈취 → [내부확산] 측면이동으로 주요서버까지 침투
   → [암호화] 파일을 암호화하고 몸값(비트코인 등) 요구 → [이중협박] 데이터 유출위협까지 병행

[RaaS 생태계 분업구조]
랜섬웨어 개발자(코드제작) → 제휴사(Affiliate, 실제침투수행) → 초기접근중개상(IAB, 침투경로판매)
(개발자는 수익 일부를 수수료로 받고, 비전문가도 "구독"만으로 공격 가능 → 진입장벽 급격히 낮아짐)
```

**영향(피해범위)**: 전사 시스템 마비(업무중단), 데이터 영구손실(복구실패 시), 이중/삼중 협박(유출+2차공격위협)으로 피해 확대, 공급망 전체로 전이(협력사 시스템도 마비)

**기술적·관리적 대응(이중구조)**
- 기술적: 정기 오프라인 백업(에어갭), EDR(엔드포인트 탐지·대응)로 암호화 행위 조기탐지, 네트워크 분할(세그멘테이션)로 확산 차단
- 관리적: NIST SP 800-61r3 단계별 대응체계(준비→탐지분석→格리퇴치→복구) 수립, 침해사고 대응 모의훈련 정기실시

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 측면이동(Lateral Movement) | 랜섬웨어가 내부 확산 시 사용하는 핵심 기법(아래에서 상세 정리) |
| 제로트러스트 / 마이크로세그멘테이션 | 랜섬웨어의 전체망 확산을 차단하는 근본적 아키텍처 대응 |
| BCP/DRS | 랜섬웨어로 시스템 마비 시 업무연속성을 확보하는 상위 복구체계 |

## 2. 크리덴셜 스터핑 (Credential Stuffing)

**공격 메커니즘/구조도**
```
[A사이트 유출] 다른 사이트에서 유출된 ID/비밀번호 목록 확보(다크웹 거래 등)
   → [자동화 시도] 봇으로 여러 서비스(B사이트, C사이트...)에 동일 계정정보로 무차별 로그인 시도
   → [성공계정 발견] 같은 비밀번호를 재사용한 사용자 계정 탈취
```

**영향(피해범위)**: 계정탈취를 통한 개인정보 유출, 금융계정의 경우 직접적 금전피해, 탈취계정으로 2차 사기(피싱 발송 등)에 악용

**기술적·관리적 대응(이중구조)**
- 기술적: 다중인증(MFA) 의무화, 로그인 시도 이상행위 탐지(짧은시간 대량시도 차단), CAPTCHA 적용
- 관리적: 비밀번호 재사용 금지 정책·교육, 유출된 계정정보 모니터링 서비스(다크웹 감시) 활용

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 다중인증(MFA) / 식별vs인증 | 크리덴셜 스터핑을 무력화하는 가장 효과적인 직접대응 |
| 해시함수(Salt/키스트레칭) | 원천적으로 비밀번호 유출 자체를 막는 저장방식 대응 |
| 큐싱 / 피싱 | 크리덴셜(계정정보) 자체를 탈취하는 또다른 경로(다음 키워드) |

## 3. 큐싱 (Qshing, QR코드 피싱)

**공격 메커니즘/구조도**
```
[악성QR코드 배포] 가짜 결제QR, 주차요금QR스티커 부착, 이메일 내 QR이미지 삽입
   → [사용자 스캔] 의심없이 QR코드 스캔(URL이 직접 안보여 의심도 낮음)
   → [악성사이트 연결] 피싱사이트로 이동해 개인정보·금융정보 입력 유도, 또는 악성앱 설치
```

**영향(피해범위)**: 전통적 피싱보다 URL을 눈으로 확인하기 어려워 탐지율이 낮아 피해 확률 증가, 금융정보 탈취·악성앱(스미싱 연계) 설치

**기술적·관리적 대응(이중구조)**
- 기술적: QR코드 스캔 시 URL 미리보기 표시 기능 활성화, 모바일 백신의 QR검사 기능 활용
- 관리적: 공공장소 QR코드 이용 시 출처확인 습관화 교육, 결제QR은 공식앱 내에서만 사용권장 캠페인

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 피싱(Phishing) / 스미싱(Smishing) | 큐싱이 속하는 상위 사회공학적 공격 분류 |
| 딥페이크 | 최근 큐싱·피싱이 딥페이크 음성/영상과 결합해 신뢰도를 높이는 복합공격으로 진화 |

## 4. 딥페이크 (Deepfake)

**공격 메커니즘/구조도**
```
[학습] 대상인물의 얼굴/음성 데이터를 GAN/오토인코더 계열 모델로 학습
   → [생성] 합성된 가짜 영상/음성 생성(실제처럼 보이거나 들리도록)
   → [악용] 가짜 화상통화로 금전송금 지시(CEO사칭), 허위정보 유포, 명예훼손 영상 제작
```

**영향(피해범위)**: 기업사기(CEO 사칭 송금지시), 가짜뉴스로 인한 사회적 혼란, 개인 명예훼손·디지털성범죄, 신원인증(안면인식) 시스템 우회 위험

**기술적·관리적 대응(이중구조)**
- 기술적: 딥페이크 탐지 AI(미세한 깜빡임·픽셀 패턴 분석), 콘텐츠 워터마킹(생성형AI 결과물에 출처표시 의무화 추진), 라이브니스 검사(실제 사람인지 확인)
- 관리적: 중요 의사결정(송금 등)은 화상통화만으로 결정하지 않고 별도채널 재확인 절차 의무화, 딥페이크 관련 법적 처벌 강화

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| VAE / GAN | 딥페이크 생성의 핵심 AI 기술(딥러닝 도메인과 연결) |
| 안면인식 결제서비스 | 딥페이크가 무력화를 시도하는 대표적 생체인증 시스템 |
| AI 신뢰성검인증(CAT) | 딥페이크 탐지기술의 신뢰성을 객관적으로 검증하는 제도와 연결 |

## 5. 스푸핑 (ARP / IP / DNS Spoofing)

**공격 메커니즘/구조도**
```
[ARP 스푸핑] 공격자가 위조된 ARP응답("내가 게이트웨이다")을 전송
   → 피해자의 ARP테이블이 오염 → 모든 트래픽이 공격자를 거쳐 전달(중간자공격, MITM)

[IP 스푸핑] 공격자가 출발지 IP주소를 위조해 전송 → 신뢰된 IP로 가장해 접근통제 우회

[DNS 스푸핑] 공격자가 가짜 DNS응답을 빠르게 보내 도메인을 악성IP로 매핑
   → 사용자가 정상 도메인 입력해도 가짜 사이트로 연결됨
```

**영향(피해범위)**: 중간자공격(MITM)으로 통신내용 탈취·변조, 가짜사이트로 유도해 피싱 피해, IP기반 접근통제(화이트리스트) 우회로 내부망 침투

**기술적·관리적 대응(이중구조)**
- 기술적: ARP스푸핑→정적ARP테이블/ARP모니터링도구, IP스푸핑→Ingress/Egress 필터링(비정상 출발지 차단), DNS스푸핑→DNSSEC(DNS 응답 전자서명 검증)
- 관리적: 네트워크 분할로 공격범위 최소화, 정기 네트워크 트래픽 모니터링

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| DNS(개요/구성요소/보안취약점) | DNS스푸핑이 노리는 대상 시스템 자체에 대한 이해 |
| MITM(중간자공격) | 3가지 스푸핑 공격이 공통적으로 달성하려는 공격형태 |
| VPN(IPSec) | 통신경로 자체를 암호화해 스푸핑으로 가로채도 내용해석을 막는 대응 |

## 6. DDoS (Distributed Denial of Service)

**공격 메커니즘/구조도**
```
[봇넷 구성] 공격자가 다수의 좀비PC/IoT기기를 악성코드로 감염시켜 봇넷 구축(미라이봇넷 등)
   → [공격명령] C&C서버가 봇넷 전체에 동시공격 명령 하달
   → [대량트래픽] 수천~수백만 대가 동시에 표적서버로 트래픽 전송 → 서버 자원/대역폭 고갈 → 서비스마비
```

**영향(피해범위)**: 서비스 가용성 완전 마비(매출손실 직결), 정상 사용자의 접근 불가, 공격 대응 중 다른 보안위협(랜섬웨어 등) 은폐 목적으로 동시 활용되는 경우도 존재

**기술적·관리적 대응(이중구조)**
- 기술적: CDN/스크러빙센터(트래픽 분산·필터링)로 대량트래픽 흡수, DDoS사이버대피소(국가기관 제공) 활용, Anycast로 공격트래픽 지역분산
- 관리적: 사전 DDoS 대응 계약(클라우드/통신사와), 평상시 트래픽 패턴 기준선(Baseline) 수립으로 이상탐지 정확도 향상

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 미라이봇넷(Mirai Botnet) | DDoS의 대표적 실행 인프라(IoT기기 감염, 아래에서 상세 정리) |
| 리버스프록시 / DDoS사이버대피소 | 실제 DDoS 방어에 사용되는 인프라적 대응수단 |
| Model DoS | AI/LLM 환경에서 DDoS 개념이 변형 적용된 신종위협(AI보안 도메인과 연결) |

## 7. 인포스틸러 (InfoStealer)

**공격 메커니즘/구조도**
```
[유포] 크랙 소프트웨어, 피싱첨부파일 등으로 악성코드 설치 유도
   → [정보탈취] PC 내 저장된 브라우저 쿠키/비밀번호, 암호화폐지갑, 게임계정 등을 스캔해 자동수집
   → [전송] 탈취정보를 공격자의 C&C서버로 전송(이후 다크웹 판매 또는 추가공격에 활용)
```

**영향(피해범위)**: 대량 계정정보 유출(크리덴셜스터핑의 원료가 됨), 암호화폐 지갑 탈취로 직접적 금전손실, 기업 내부정보 유출(업무용PC 감염 시)

**기술적·관리적 대응(이중구조)**
- 기술적: 백신/EDR의 실시간 악성코드 탐지, 불필요한 브라우저 자동저장 비밀번호 기능 비활성화
- 관리적: 정품 소프트웨어만 사용 정책, 침해 발견 시 즉시 전체 계정 비밀번호 초기화(영향범위 차단)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 크리덴셜스터핑 | 인포스틸러로 탈취된 계정정보가 다음 단계 공격(크리덴셜스터핑)의 원료가 됨 |
| Shellcode | 인포스틸러 등 악성코드가 실제 시스템에서 실행되는 저수준 공격코드 형태(다음 키워드) |

## 8. 미라이 봇넷 (Mirai Botnet)

**공격 메커니즘/구조도**
```
[스캐닝] 인터넷의 IoT기기(IP카메라, 라우터 등)를 무작위로 스캐닝
   → [취약점 침투] 기본 비밀번호(admin/admin 등)를 그대로 사용하는 기기에 자동로그인
   → [감염/봇넷화] 악성코드 설치 후 C&C서버에 등록 → 대규모 봇넷 구성 → DDoS공격에 동원
```

**IoT 서비스 생애주기별 보안위협 및 해결방안**
- 기획/설계단계: 기본 비밀번호 정책 미고려 → 출고 시 고유 비밀번호 강제설정
- 운영단계: 펌웨어 업데이트 방치 → 자동 보안패치 체계 구축
- 폐기단계: 데이터 잔존 위험 → 초기화/폐기 절차 표준화

**IoT 공통보안 7대원칙(예시)**: 비밀번호 정책 강화, 보안패치 체계, 안전한 초기설정, 통신데이터 암호화, 물리보안, 취약점 점검, 보안인증 등

**영향(피해범위)**: 대규모 DDoS공격(2016년 Dyn DNS 공격으로 미국 동부 인터넷 대란 사례), 무방비 IoT기기 전체가 공격무기로 전락

**기술적·관리적 대응(이중구조)**
- 기술적: IoT기기 기본 비밀번호 변경 의무화, 불필요한 외부포트(Telnet 등) 차단
- 관리적: IoT 제조사 대상 보안인증 제도(KC인증 등) 강화, IoT기기 보안 가이드라인 준수 점검

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| DDoS | 미라이봇넷의 최종 목적(공격수단)이 DDoS |
| 네트워크 스캐닝 | 미라이봇넷이 취약한 IoT기기를 찾아내는 첫 단계 기법(다음 키워드) |
| AIoT 보안취약점 | IoT가 AI와 결합되며 확대되는 차세대 위협영역 |

## 9. BPFdoor

**공격 메커니즘/구조도**
```
[은밀한 설치] 서버(주로 Linux)에 BPF(Berkeley Packet Filter)를 악용한 백도어 설치
   → [수동형 대기] 일반 백도어처럼 포트를 열어두지 않고, 모든 패킷을 커널레벨에서 몰래 감시
   → [트리거 패킷 감지] 공격자가 보낸 특수 "매직패킷"을 BPF필터로 감지하면 그때만 활성화
   → [원격제어] 활성화되면 방화벽 룰과 무관하게 공격자와 통신(기존 보안장비 탐지 회피)
```

**기존 백도어 방식과의 차이점**: 일반 백도어는 항시 리스닝포트가 열려있어 포트스캔으로 탐지 가능하나, BPFdoor는 평상시 포트를 열지 않고 커널레벨에서 패킷을 몰래 감청하다가 트리거시에만 반응 → 방화벽·포트스캔 기반 탐지를 모두 회피

**영향(피해범위)**: 장기간 탐지되지 않는 지속적 침투(APT 공격의 핵심수단), 방화벽 정책과 무관하게 우회통신 가능해 기존 보안체계 무력화

**기술적·관리적 대응(이중구조)**
- 기술적: 커널레벨 행위 모니터링(eBPF 기반 보안솔루션), 비정상 프로세스의 raw socket 사용 탐지
- 관리적: 정기 시스템 무결성 점검(루트킷 탐지도구), 커널모듈 변경사항 감시체계 운영

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| APT(Advanced Persistent Threat) | BPFdoor가 활용되는 대표적 지속적 표적공격 유형 |
| 측면이동(Lateral Movement) | BPFdoor로 최초침투 후 내부 확산 시 사용되는 다음 단계 기법 |

---

## 10. 측면이동 (Lateral Movement)

**공격 메커니즘/구조도**
```
[초기침투] 한 대의 PC/서버에 최초 접근권한 획득(피싱 등)
   → [권한상승] 로컬관리자 권한 탈취(취약점 또는 자격증명 탈취)
   → [내부 정찰] 네트워크 스캐닝으로 다른 시스템·자산 파악
   → [측면이동] 탈취한 계정정보(Pass-the-Hash 등 기법)로 인접 시스템으로 이동 반복
   → [핵심자산 도달] 최종적으로 도메인컨트롤러·핵심DB 등 표적 도달
```

**단계별 메커니즘과 주요기법**: Pass-the-Hash(해시값 자체로 인증 우회), RDP/SMB 무차별 접속시도, 합법 관리도구(PsExec 등) 악용해 정상행위처럼 위장

**영향(피해범위)**: 초기침투 1대에서 시작해 전체 네트워크로 피해 확산(랜섬웨어의 전사 마비도 이 단계를 거침), 핵심자산(인사·재무DB) 유출

**기술적·관리적 대응(이중구조)**
- 기술적: 마이크로세그멘테이션(네트워크 구간 분리)으로 이동 자체를 차단, EDR/NDR로 비정상 내부 이동 탐지
- 관리적: 최소권한 원칙(필요한 시스템만 접근권한 부여), 관리자 계정의 다중인증 강제

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 공격표면(Attack Surface) / 공격벡터(Attack Vector) | 측면이동의 전제가 되는 초기 침투지점 개념 |
| 제로트러스트 / 마이크로세그멘테이션 | 측면이동을 구조적으로 차단하는 가장 근본적인 아키텍처 대응 |
| 랜섬웨어 / BPFdoor | 측면이동이 실제로 활용되는 대표적 상위 공격시나리오 |

---

## 11. 변조(Modification) vs 위조(Fabrication)

**공격 메커니즘/구조도(보안위협의 4대 분류 중 2가지)**

| 위협 | 정의 | 침해 대상 |
|---|---|---|
| **변조(Modification)** | 전송 중인 데이터나 저장된 데이터의 내용을 **무단으로 수정** | 무결성(Integrity) |
| **위조(Fabrication)** | 존재하지 않던 데이터/메시지를 마치 정당한 송신자가 보낸 것처럼 **새로 만들어 삽입** | 무결성(또는 인증성) |
| (참고)가로채기(Interception) | 전송 중 데이터를 몰래 열람 | 기밀성 |
| (참고)차단(Interruption) | 정상적인 데이터 전달을 막음 | 가용성 |

**영향(피해범위)**: 변조(거래금액 위변조 등으로 금융사기), 위조(가짜 명령/메시지 주입으로 시스템 오작동, 피싱메일 발신자 위조)

**기술적·관리적 대응(이중구조)**
- 기술적: 변조 방지 — 해시함수/전자서명으로 무결성 검증, 위조 방지 — MAC(메시지인증코드)·전자서명으로 송신자 인증 확인
- 관리적: 데이터 변경 로그(감사추적) 의무화, 중요거래는 이중확인(승인절차) 적용

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 해시함수 / MAC | 변조·위조를 탐지하는 핵심 암호기술 |
| 스푸핑(IP/DNS) | 위조(가짜 발신자로 위장)의 대표적 실제 구현사례 |

## 12. Shellcode

**공격 메커니즘/구조도**
```
[취약점 발견] 버퍼오버플로우 등 메모리 취약점이 있는 프로그램 발견
   → [Shellcode 삽입] 공격자가 원하는 동작(보통 쉘 획득)을 수행하는 짧은 기계어 코드를 입력값에 삽입
   → [실행흐름 변경] 취약점을 이용해 프로그램의 실행주소(Return Address 등)를 Shellcode 위치로 변경
   → [임의코드 실행] 프로그램이 의도와 다르게 Shellcode를 실행 → 공격자가 시스템 제어권 획득(쉘 획득)
```

**영향(피해범위)**: 시스템 완전장악(루트권한 획득 가능), 인포스틸러·랜섬웨어 등 후속 악성코드 설치의 실행기반(공격체인의 핵심 매개)

**기술적·관리적 대응(이중구조)**
- 기술적: ASLR(주소공간배치 임의화)·DEP(데이터실행방지) 등 OS 레벨 메모리보호기법 적용, 시큐어코딩으로 버퍼오버플로우 원천차단
- 관리적: 정기 취약점 점검(모의해킹) 및 패치관리 프로세스, 소스코드 보안검토(시큐어코딩 가이드 준수 확인)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 버퍼오버플로우 | Shellcode 공격이 성립하는 가장 대표적인 취약점 유형 |
| 시큐어코딩 / OWASP | Shellcode를 막기 위한 안전한 코드작성 표준 가이드 |
| 인포스틸러 / BPFdoor | Shellcode 실행 이후 설치되는 후속 악성코드 사례 |

## 13. 네트워크 스캐닝 (Network Scanning)

**공격 메커니즘/구조도**
```
[공격자] → 표적 IP범위에 대해 다양한 스캔 기법 시도
   ① Ping스캔: 살아있는 호스트(IP) 탐지
   ② 포트스캔: 열려있는 서비스포트 탐지(예: TCP SYN스캔)
   ③ 취약점스캔: 식별된 서비스의 버전·패치상태로 알려진 취약점(CVE) 매칭
   → [결과 분석] 공격 가능한 진입점(약한 서비스/패치미적용 포트) 선정 → 본공격 단계로 진행
```

**영향(피해범위)**: 직접적 피해는 없으나(정찰단계) 본격적인 공격(랜섬웨어·미라이봇넷 침투 등)의 사전단계로, 방어 측에서는 "공격 임박 신호"로 해석 가능

**기술적·관리적 대응(이중구조)**
- 기술적: 방화벽에서 비정상 스캔 패턴(짧은시간 다중포트 접속시도) 탐지·차단, 불필요한 서비스 포트 폐쇄(공격표면 축소)
- 관리적: 정기 자체 취약점진단(모의해킹)으로 선제적 발견, 외부노출 자산 인벤토리 관리(ASM, Attack Surface Management)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 미라이봇넷 | 네트워크 스캐닝이 실제로 취약한 IoT기기를 찾아내는 첫 단계 |
| 공격표면(Attack Surface) | 스캐닝의 대상이 되는 외부 노출 자산 전체 |
| 측면이동 | 외부 스캐닝과 마찬가지로, 내부침투 후 "내부 정찰"단계에서도 스캐닝 기법이 재사용됨 |

## 종합 흐름도 (공격 생애주기 기준)

```
[정찰] 네트워크 스캐닝 → 취약 자산 식별(미라이봇넷의 IoT탐색도 동일 원리)
        │
[초기침투] 피싱/큐싱/딥페이크(사회공학) ── 스푸핑(ARP/IP/DNS, 기술적 침투) ── Shellcode(취약점 악용)
        │
[정보탈취/지속화] 인포스틸러(계정정보 탈취) ── BPFdoor(은밀한 백도어 지속)
        │
[내부확산] 측면이동(Lateral Movement) — 탈취정보로 권한상승 후 전파
        │
[목표달성]
  랜섬웨어/RaaS(금전요구) ── DDoS(서비스마비, 미라이봇넷이 실행체) ── 크리덴셜스터핑(탈취정보 재활용)
        │
[보안위협 본질 분류] 가로채기·차단·변조·위조 — 모든 공격은 이 4대 침해유형 중 하나 이상에 해당
```
