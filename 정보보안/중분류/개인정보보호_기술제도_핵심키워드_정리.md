> **공통 답안 전개 구조**: 원칙/기준 제시 → 내용 항목화 → 법조항과 비교

## 1. PbD (Privacy by Design)

**원칙/기준 제시**
> 캐나다 온타리오주 정보프라이버시위원 Ann Cavoukian이 창안한 개념으로, 개인정보보호를 사후대응이 아니라 **시스템 설계단계부터 내재화**해야 한다는 원칙. 7대 원칙과 이를 실무화한 8대 전략으로 구성

**내용 항목화**

**7대 원칙**
1. 사후대응이 아닌 **사전예방**적 조치
2. 프라이버시를 **기본설정값**으로(별도 설정없이 자동보호)
3. 설계에 프라이버시를 **내재화**(추가기능이 아닌 핵심설계요소)
4. **완전한 기능성**(보안과 기능을 양자택일이 아닌 동시 확보, Positive-sum)
5. **전체 생애주기** 보호(수집~파기까지 End-to-End)
6. **가시성·투명성** 확보(검증가능하게 공개)
7. **이용자 중심**(사용자 프라이버시를 최우선 존중)

**8대 전략(실무 구현방법)**: 데이터 최소화, 데이터 분리(Separate), 데이터 추상화(가명처리 등), 데이터 은닉, 정보제공(Inform), 통제권 부여(Control), 책임이행(Enforce), 입증(Demonstrate)

**법조항과 비교 (개인정보보호법 제3조 개인정보 보호원칙)**

| 개인정보보호법 제3조 | PbD 대응원칙 |
|---|---|
| 목적에 필요한 최소한의 개인정보 수집(최소수집) | 8대전략의 "데이터 최소화" |
| 처리목적 명확화, 목적외 이용금지 | 7대원칙의 "전체생애주기 보호" |
| 안전하게 관리(분실·도난·유출 방지) | 7대원칙의 "사전예방", 8대전략의 "데이터 은닉" |
| 처리방침 등 공개(투명성) | 7대원칙의 "가시성·투명성" |
| 정보주체의 권리보장 | 7대원칙의 "이용자중심", 8대전략의 "통제권 부여" |

> **시사점**: 법 제3조는 "무엇을 지켜야 하는가(원칙)"를 규정하고, PbD는 "어떻게 시스템에 구현하는가(설계방법론)"를 제시 — 법이 정한 원칙을 실제 시스템 설계에 매핑하는 실무 프레임워크로 PbD를 활용

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| PET(아래 키워드) | PbD의 8대전략(데이터 추상화·은닉)을 실제 기술로 구현하는 수단 |
| 개인정보 안전성확보조치 | PbD 원칙을 국내법상 구체적 기술·관리적 조치로 의무화한 고시 |
| ISO/IEC 29100 / 27701 | PbD와 유사한 국제표준 프라이버시 원칙체계(아래에서 비교) |

## 2. PET (Privacy Enhancing Technology) — 동형암호/차분프라이버시/합성데이터

**원칙/기준 제시**
> 데이터 활용성(분석·AI학습)과 프라이버시보호를 동시에 달성하기 위한 기술적 수단의 집합 — PbD의 "완전한 기능성(Positive-sum)" 원칙을 기술로 실현

**내용 항목화 (3대 기술 비교)**

| 기술 | 원리 | 특징 |
|---|---|---|
| **동형암호** | 암호화된 상태 그대로 연산 가능, 복호화하면 평문연산과 동일결과 | 원본데이터를 한번도 평문노출 없이 분석(연산비용 매우 큼) |
| **차분프라이버시** | 통계결과에 의도적으로 노이즈를 추가해, 특정 개인의 포함여부를 역추적 불가능하게 함 | 통계적 유용성과 프라이버시 간 트레이드오프(ε값으로 조절) |
| **합성데이터** | 원본데이터의 통계적 패턴을 학습한 AI모델(GAN/VAE 등)로 가상의 새 데이터를 생성 | 원본과 1:1 대응되지 않아 재식별위험 낮음, 가공편의성 높음 |

**법조항과 비교(개인정보보호법상 가명처리·익명처리 규정)**

| 법적 개념 | 대응 PET기술 |
|---|---|
| 가명처리(추가정보 결합 시 재식별 가능) | 차분프라이버시(노이즈 추가로 통계적 보호, 원본구조 유지) |
| 익명처리(재식별 불가능 수준) | 합성데이터(원본과 직접 매칭 안되는 새 데이터 생성) |
| 데이터3법상 가명정보의 안전한 결합 | 동형암호 기반 결합(결합 전문기관에서 원본노출 없이 결합·분석) |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 연합학습(Federated Learning) | PET과 결합해 원본데이터 비공개 + 학습결과 노출까지 차단하는 보강기법 |
| MPC(다자간계산) | 동형암호와 유사한 목적의 또 다른 프라이버시 보호 연산기술 |
| AI 개인정보보호 자율점검표 | AI학습데이터에 PET 적용여부를 점검하는 실무 체크리스트 |

## 3. 가명처리 / 익명처리

**원칙/기준 제시**
> 개인정보보호법(데이터3법 개정)이 정의한 비식별화 처리수준의 2단계 구분 — 가명처리는 "추가정보 없이는 식별 불가", 익명처리는 "어떤 방법으로도 식별 불가"

**내용 항목화(처리기법)**
- **가명처리 기법**: 가명대체(이름→임의코드), 총계처리(평균값으로 대체), 데이터 마스킹(일부만 표시, 예: 010-****-1234), 범주화(나이→연령대)
- **익명처리 기법**: k-익명성(동일속성 k명 이상 존재하도록 일반화), 데이터 삭제(식별가능 항목 완전제거)

**적정성 평가 절차**: ①목적 명확화 → ②가명처리 기법 적용 → ③재식별 위험성 검토(전문가 평가단) → ④추가 비식별 보완 → ⑤사후관리(재식별시도 모니터링)

**법조항과 비교(개인정보보호법)**

| 구분 | 가명정보 | 익명정보 |
|---|---|---|
| 법적 정의 | 추가정보 결합 시에만 재식별 가능 | 더 이상 개인정보가 아닌 것으로 봄(법 적용대상 제외) |
| 동의없는 활용 | 통계작성·연구·공익기록보존 목적이면 가능(제28조의2) | 제한없이 자유�로운 활용 가능 |
| 재식별 시도 | 법으로 금지(제28조의5), 위반시 처벌 | - |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 데이터3법 | 가명정보 개념 자체를 도입한 법적 근거 |
| PET(합성데이터) | 익명처리의 최신 고도화 기법으로서 합성데이터가 대안으로 부상 |
| 데이터안심구역 | 가명정보를 안전하게 결합·분석하는 통제된 물리적 환경 |

## 4. 개인정보 안전성확보조치 (내부관리계획/암호화)

**원칙/기준 제시**
> 개인정보보호법 제29조(안전조치의무) 및 「개인정보의 안전성 확보조치 기준」 고시에 따라 개인정보처리자가 의무적으로 갖춰야 할 기술적·관리적·물리적 보호조치

**내용 항목화**

| 조치영역 | 세부내용 |
|---|---|
| **내부관리계획 수립·이행** | 개인정보보호책임자 지정, 처리직원 권한관리, 교육계획, 점검계획을 문서화한 내부 정책 |
| **암호화 적용방안** | 비밀번호 일방향암호화(해시), 주민번호 등 고유식별정보 암호화 저장, 전송시 암호화(TLS 등) |
| **접근통제** | 접근권한 차등부여, 비인가자 접근차단, 접속기록 보관(최소 1년) |
| **물리적 조치** | 전산실·자료보관실 출입통제 |

**법조항과 비교**: 동 고시는 개인정보보호법 제29조(안전조치의무)의 **하위 시행규정**으로, 법은 "안전하게 관리해야 한다"는 원칙만 선언하고 고시가 구체적 기술기준(암호화 알고리즘, 접속기록 보관기간 등)을 명시하는 위임관계

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| PbD 7대원칙 | "사전예방", "내재화" 원칙이 내부관리계획·암호화로 구체화됨 |
| ISMS-P | 안전성확보조치 준수여부가 ISMS-P 인증심사의 핵심 점검항목 |
| 해시함수(Salt/키스트레칭) | 암호화 적용방안 중 비밀번호 보호의 실제 구현기술 |

## 5. CBPR (Cross Border Privacy Rules) — APEC 프라이버시 9원칙

**원칙/기준 제시**
> APEC(아시아태평양경제협력체)이 회원국 간 개인정보의 국경간 이전을 안전하게 촉진하기 위해 마련한 인증체계, APEC 프라이버시 9원칙을 기반으로 함

**내용 항목화 (APEC 프라이버시 9원칙)**
1. 피해예방(Preventing Harm)
2. 통지(Notice)
3. 수집제한(Collection Limitation)
4. 개인정보의 이용(Uses of Personal Information)
5. 선택권(Choice)
6. 무결성(Integrity of Personal Information)
7. 보안수단(Security Safeguards)
8. 접근·정정권(Access and Correction)
9. 책임성(Accountability)

**CBPR 주요 인증기준**: 기업의 개인정보처리방침이 9원칙을 충족하는지 책임인증기관(Accountability Agent)이 심사·인증, 인증받은 기업은 회원국 간 데이터를 통일된 기준으로 이전 가능

**법조항과 비교**: 국내 개인정보보호법의 국외이전 규정(제28조의8)이 "적정성 인정국가" 또는 "보호조치 마련" 등을 요구하는데, CBPR 인증이 이 국외이전 요건을 충족시키는 국제적으로 통용되는 수단 중 하나로 활용

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 개인정보 국외이전 | CBPR이 실무적으로 충족시키는 법적 요구사항 |
| GDPR(EU일반개인정보보호법) | CBPR과 유사한 목적의 또 다른 지역 개인정보보호 체계(상호인정 논의 진행) |

## 6. ISO/IEC 29100 (프라이버시 11원칙) · ISO/IEC 27701

**원칙/기준 제시**
> ISO/IEC 29100은 프라이버시 프레임워크의 **공통 용어·원칙**을 정의한 국제표준, ISO/IEC 27701은 ISO27001(정보보호)에 **개인정보보호 관리체계(PIMS)** 요구사항을 추가한 인증가능 표준

**내용 항목화 (ISO/IEC 29100 프라이버시 11원칙)**
동의 및 선택, 목적 적합성·제한, 수집 제한, 데이터 최소화, 이용·보유·공개의 제한, 정확성·품질, 개방성·투명성·통지, 개인참여 및 접근, 책임성, 정보보안, 프라이버시 준수

**ISO/IEC 27701의 구조**: ISO27001(ISMS) 요구사항에 **PII Controller(개인정보처리자)용 통제항목**과 **PII Processor(수탁처리자)용 통제항목**을 추가로 부속서 형태로 결합 → 인증가능

**법조항과 비교(국내 ISMS-P)**

| 구분 | ISO/IEC 27701 | 국내 ISMS-P |
|---|---|---|
| 인증주체 | 국제인증기관 | 한국인터넷진흥원(KISA) |
| 법적근거 | 자율 국제표준 | 개인정보보호법/정보통신망법 법정 인증제도 |
| 활용 | 해외사업·글로벌 고객 신뢰확보 | 국내 법적 의무대상 충족 |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| ISMS-P | ISO27701과 유사 목적의 국내 법정 인증제도(글로벌vs국내 비교출제 빈번) |
| ISO/IEC 42001(AI관리시스템) | 27701과 동일하게 ISO27001을 기반확장한 유사 구조의 신규 표준(AI거버넌스 도메인과 연결) |
| PbD | 29100의 11원칙이 PbD의 7대원칙과 상당부분 중첩(비교출제 가능) |

## 7. TOCTOU (Time-Of-Check to Time-Of-Use)

**원칙/기준 제시**
> 시큐어코딩 보안약점의 한 유형으로, 프로그램이 **자원의 상태를 검사한 시점(Check)**과 **실제로 그 자원을 사용하는 시점(Use)** 사이에 시간차가 있을 때, 그 틈을 노려 자원이 몰래 변경되는 경쟁조건(Race Condition) 취약점

**내용 항목화(문제발생 메커니즘)**
```
1. 프로그램: "파일이 존재하고 권한이 있는지 검사(Check)" → 정상 확인
2. (이 틈에 공격자가 해당 파일을 심볼릭링크로 바꿔치기)
3. 프로그램: "검사를 통과했으니 파일사용(Use)" → 실제로는 공격자가 바꾼 다른(악성) 파일에 접근
→ 권한검사를 우회해 비인가 파일에 접근/변조 발생
```

**보안대책**: 검사와 사용을 원자적(Atomic)으로 처리(파일 핸들을 검사시점에 그대로 유지해 재참조 방지), 락(Lock)으로 검사-사용 구간을 보호, O_EXCL 같은 원자적 시스템콜 사용

**법조항과 비교(관련 가이드)**: 행정안전부 「소프트웨어 개발보안 가이드」의 보안약점 점검항목 중 "시간 및 상태(Time and State)" 분류에 해당, 시큐어코딩 의무대상 공공시스템 개발 시 필수 점검항목

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| Race Condition | TOCTOU가 속하는 상위 개념(경쟁조건의 대표 사례) |
| 락 기반 병행제어(2PL) | TOCTOU 방어에 사용되는 동시성제어 메커니즘(DB도메인과 동일원리) |
| 시큐어코딩 / OWASP | TOCTOU를 포함한 보안약점 점검의 표준 가이드체계 |
