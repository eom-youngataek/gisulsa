# 산업/OT 보안 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 표준/모델 개념 → 계층구조 → 보안고려사항

---

## 1. ISA/IEC 62443

**표준/모델 개념**
> 국제전기기술위원회(IEC)와 국제자동화협회(ISA)가 공동 제정한 **산업자동화제어시스템(IACS) 전용 보안표준**. 기존 IT보안표준(ISO27001 등)이 OT(운영기술) 환경의 특수성(실시간성·가용성 최우선·레거시장비)을 충분히 다루지 못해 별도 제정됨

**계층구조(구성체계)**

| 구성 | 대상 | 내용 |
|---|---|---|
| **62443-1.x** | 일반(General) | 개념·용어·모델 정의 |
| **62443-2.x** | 정책·절차 | 보안관리체계(자산소유자 대상) |
| **62443-3.x** | 시스템 | **보안수준(SL, Security Level) 0~4** 정의, 영역(Zone)·통로(Conduit) 분할 개념 |
| **62443-4.x** | 구성요소/제품 | 제품개발사가 따라야 할 보안개발 생명주기(SDLC) 요구사항 |

**보안수준(SL) 4단계**: SL0(보호없음) → SL1(우발적 오용 방지) → SL2(단순 의도적 공격 방지) → SL3(고급 공격 방지) → SL4(국가수준 공격까지 방지)

**보안고려사항**
- IT보안과 달리 OT환경은 **가용성(생산중단 불가) > 기밀성**의 우선순위가 다름 → 패치 적용 시에도 생산라인 정지 영향을 최소화하는 절차 필요
- 영역(Zone)·통로(Conduit) 개념으로 망을 분할(세그멘테이션)해 한 구역의 침해가 전체로 확산되지 않도록 설계

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 퍼듀(Purdue) 모델 | ISA/IEC 62443의 Zone/Conduit 분할이 퍼듀모델의 계층구조를 보안 관점에서 구체화한 것(바로 다음 키워드) |
| MODBUS / CAN통신 | ISA/IEC 62443이 보호대상으로 삼는 OT 통신프로토콜(대부분 보안기능 자체가 취약) |
| 제로트러스트 | OT환경에도 최근 제로트러스트 원칙(최소권한, 지속검증)을 접목하려는 시도가 확대 중 |

## 2. 산업제어시스템 퍼듀(Purdue) 모델

**표준/모델 개념**
> 산업제어시스템(ICS)의 네트워크 구조를 IT(기업업무망)와 OT(현장제어망) 영역으로 명확히 계층화해, 보안 통제지점을 체계적으로 설계하기 위한 참조 아키텍처(원래는 1990년대 퍼듀대학에서 제조업 정보통합 모델로 제안)

**계층구조 (Level 0~5)**

| 레벨 | 명칭 | 내용 |
|---|---|---|
| **Level 5** | 엔터프라이즈(IT) | 기업 전체 비즈니스 시스템(ERP 등) |
| **Level 4** | 사이트 비즈니스망 | 공장 단위의 업무시스템(생산계획 등) |
| **Level 3** | 운영관리(DMZ 경계) | MES(제조실행시스템), 생산 모니터링 — **IT/OT 경계 DMZ가 통상 이 지점에 위치** |
| **Level 2** | 감독제어 | SCADA, HMI(작업자 인터페이스) |
| **Level 1** | 기본제어 | PLC, DCS(분산제어시스템) — 실시간 제어 로직 수행 |
| **Level 0** | 현장기기 | 센서, 액추에이터(실제 물리적 동작 수행) |

**보안고려사항**
- **Level 3(DMZ)를 명확히 두어 IT망(Level4~5)과 OT망(Level0~2)을 물리적/논리적으로 분리**하는 것이 핵심 — IT 침해가 직접 생산설비(OT)로 전이되지 않도록 차단
- 레벨이 낮아질수록(현장에 가까울수록) 레거시 장비·실시간성 요구가 커져 일반 IT보안 패치·백신 적용이 어려움 → 망분리와 화이트리스트 방식의 통제가 대안

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| MODBUS | Level 1~2(PLC-SCADA 간) 통신에 실제로 사용되는 대표 프로토콜 |
| 망분리 | 퍼듀모델의 IT/OT 분리원칙이 일반 기업의 망분리 정책과 동일한 철학 |
| 스마트팩토리 보안위협 | 퍼듀모델의 각 레벨이 스마트팩토리 보안 요구사항 분석의 기본 틀로 활용 |

## 3. 안티드론 시스템 프레임워크

**표준/모델 개념**
> 불법·위협드론(테러·정찰·밀수 등)을 탐지·식별·무력화하기 위한 국가 차원의 표준 참조구조(국내 정보통신단체표준 TTAK.KO-10.1460 등에서 정의)

**계층구조(참조구조)**

| 단계 | 기능 |
|---|---|
| **탐지(Detection)** | 레이더·RF센서·음향센서 등으로 드론의 존재 자체를 감지 |
| **식별(Identification)** | 카메라·RF시그널 분석으로 드론종류·비행경로·조종자 위치 추정 |
| **무력화(Neutralization)** | 전파재밍(통신차단), GPS스푸핑(경로교란), 포획망/요격 등 물리적 무력화 |

**기술적 조치 참조구조**: 탐지센서(레이더/RF/광학/음향) → 통합관제시스템(C2, 다중센서 융합판단) → 대응장비(재머·포획장치) 연계 흐름으로 구성

**보안고려사항**
- 오탐(민간 드론을 위협으로 오인) 시 불필요한 무력화 조치로 인한 2차 피해(추락 등) 위험 → 다중센서 융합으로 식별 정확도 제고 필요
- 재밍 등 전자전 대응수단은 주변 정상 통신(항공·이동통신)에 영향을 줄 수 있어 운용범위·시점 통제 필요(법적 권한 문제도 고려)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| FANET(드론 애드혹망) | 안티드론 시스템이 탐지·교란해야 하는 대상인 드론 군집통신 구조 |
| FHSS/DSSS | 드론의 무선통신방식 — 안티드론의 전파재밍·신호분석이 직접 상대하는 통신기술 |
| UAM(Urban Air Mobility) | 안티드론과 대조적으로, 합법적 비행체의 안전한 운용을 위한 관제체계와 비교 출제 가능 |

## 종합 흐름도

```
[OT보안 표준] ISA/IEC 62443 — SL(보안수준) 0~4 정의, Zone/Conduit 망분할 원칙
        │
        ▼
[참조 아키텍처] 퍼듀모델(Level 0~5) — IT(L4~5)/DMZ(L3)/OT(L0~2) 계층 분리
        │
        ▼
[현장 적용 보안] MODBUS/CAN(레벨1~2 통신 보호) + 망분리(DMZ 경계 강화)
        │
[신흥 OT/물리보안 영역] 안티드론 시스템 — 탐지→식별→무력화의 동일한 "계층화 방어" 철학 적용
```

### 한 줄 비교 암기
| 키워드 | 핵심 한 줄 |
|---|---|
| ISA/IEC 62443 | "OT전용 보안표준, SL 0~4로 보안수준 정의" |
| 퍼듀모델 | "IT(L4~5)-DMZ(L3)-OT(L0~2)로 계층 분리" |
| 안티드론 시스템 | "탐지→식별→무력화의 3단계 대응체계" |
