# 디지털포렌식 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 절차 → 수집기법 → 대응체계

---

## 1. 디지털포렌식 유형/절차

**절차 (디지털포렌식 5대 표준절차)**
```
①사전준비 → ②증거수집(현장에서 원본 보존)
   → ③포렌식 이미징(원본 훼손없이 사본 생성)
   → ④분석(아티팩트·삭제파일 등 분석)
   → ⑤보고(법적 효력있는 보고서 작성)
(전 과정에서 무결성 보존을 위한 "연계보관성(Chain of Custody)" 문서화 필수)
```

**수집기법(유형별 증거수집 방법)**

| 유형 | 수집대상 | 기법 |
|---|---|---|
| **네트워크 포렌식** | 트래픽·로그 | 패킷캡처(PCAP), 방화벽/IDS 로그 분석 |
| **시스템 포렌식** | OS·메모리 | 디스크이미징, 메모리덤프(휘발성 데이터) |
| **데이터베이스 포렌식** | DB 트랜잭션로그 | 변경이력·삭제레코드 복구 |
| **응용프로그램 포렌식** | 앱 데이터 | 캐시·임시파일·앱 자체 로그 분석 |
| **모바일 포렌식** | 스마트폰 | 백업파일·앱데이터 추출(JTAG/Chip-off 등) |

**대응체계**: 수집된 증거는 해시값(MD5/SHA) 산출로 무결성 검증 후 보관, 법정 제출 시 수집·분석 전 과정의 절차적 정당성(영장 등)이 함께 입증되어야 효력 인정

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 연계보관성(Chain of Custody) | 포렌식 절차 전체를 관통하는 법적 효력의 핵심 — 증거가 수집부터 법정까지 손상없이 추적관리되었음을 입증 |
| 디지털포렌식 아티팩트 | 분석단계에서 실제로 찾아내는 증거의 구체적 형태(아래에서 상세) |
| e-Discovery | 법적 분쟁에서 디지털 증거를 체계적으로 수집·검토하는 미국식 절차로 확장 출제 가능 |

## 2. 파일카빙 4기법 (File Carving)

**절차**
```
[삭제/손상된 디스크] → (파일시스템의 메타데이터 없이) 
→ 디스크의 raw 데이터(0과1)를 직접 스캔 → 파일의 시그니처(헤더/푸터 패턴)로 파일경계 추정 → 복구
```

**수집기법(4가지 카빙기법)**

| 기법 | 방식 | 특징 |
|---|---|---|
| **헤더-푸터 기반(Header-Footer Carving)** | 파일 시작(헤더)과 끝(푸터) 시그니처를 모두 찾아 그 사이를 복구 | JPEG·PDF 등 명확한 푸터가 있는 파일에 효과적 |
| **헤더-크기 기반(Header-Length Carving)** | 헤더에 파일크기 정보가 포함된 경우, 그 크기만큼 추출 | 크기정보 내장 포맷에 적합 |
| **파일구조 기반(File Structure-based)** | 파일 내부의 구조적 규칙(예: ZIP의 디렉토리구조)을 분석해 복구 | 압축파일 등 복잡한 구조 파일에 적합, 정확도 높음 |
| **콘텐츠 기반(Content-based, 통계적 카빙)** | 파일 내용물의 통계적 특성(엔트로피 등)으로 파일종류·경계 추정 | 시그니처가 불명확한 파일에 보조적으로 활용 |

**대응체계**: 파일카빙은 파일시스템 메타데이터(파일명·생성일 등)가 손실된 상태에서도 내용복구가 가능해, 의도적 삭제·포맷 후에도 핵심 증거(이미지·문서) 확보에 활용

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 파일슬랙(File Slack) | 파일카빙으로도 찾기 어려운 잔여 데이터가 숨어있는 또 다른 영역(다음 키워드) |
| 디스크이미징 | 파일카빙을 수행하기 위한 전제(원본디스크의 비트단위 사본이 먼저 필요) |
| 안티포렌식 | 파일카빙으로 복구가 가능하다는 점을 노려, 안티포렌식 기법은 덮어쓰기(Wiping)로 복구 자체를 차단하려 함 |

## 3. 디스크 이미징 (D2D / D2F)

**절차**
```
[원본 디스크] → (쓰기방지장치로 원본 보호) → [이미징 도구로 비트단위 완전복제]
   → [원본해시값 vs 복제본해시값 비교] → 일치 확인(무결성 검증) → 이후 분석은 복제본으로만 수행(원본 보존)
```

**수집기법(D2D vs D2F 방식)**

| 방식 | 정의 | 특징 |
|---|---|---|
| **D2D(Disk to Disk)** | 원본디스크를 다른 물리디스크에 통째로 그대로 복제 | 원본과 동일한 디스크 구조 유지, 즉시 부팅·마운트 가능 |
| **D2F(Disk to File)** | 원본디스크의 내용을 하나의 **이미지파일**(예: .E01, .dd)로 저장 | 저장공간 효율적, 여러 사본 배포·보관 용이, 분석도구로 가상마운트 |

**디스크이미징을 활용한 증거수집 방법**: 압축/비압축 이미지 포맷 선택, 이미징 전·후 해시값(SHA256) 검증으로 무결성 입증, 분석은 항상 사본(이미지)으로만 진행해 원본 훼손 방지

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 쓰기방지장치(Write Blocker) | 이미징 과정에서 원본디스크의 변경을 물리적으로 차단하는 필수 하드웨어 |
| 해시함수(무결성검증) | 이미징 전후 동일성을 증명하는 핵심 암호기술(보안 도메인과 연결) |
| 파일카빙 | 디스크이미지(D2F)를 대상으로 실제 분석·복구 작업을 수행하는 다음 단계 |

## 4. 안티포렌식 대응 컴플라이언스 (구축/활용 프로세스)

**절차(등장배경 및 안티포렌식 기술)**
> 공격자/내부자가 수사 회피를 위해 흔적을 지우거나 분석을 방해하는 **안티포렌식(Anti-Forensic)** 기법(데이터삭제·덮어쓰기, 암호화, 타임스탬프 변조, 스테가노그래피 은닉 등)이 고도화됨에 따라, 기업은 이를 사전에 대비하는 컴플라이언스 체계가 필요

**구축 프로세스**
```
①정책수립(로그보관 의무기간, 삭제방지 정책 정의)
→ ②기술적 통제 적용(중앙로그서버로 실시간 전송, 로컬삭제와 무관하게 별도 보존)
→ ③지속적 모니터링(안티포렌식 행위 자체를 탐지 — 대량삭제, 타임스탬프 비정상 변경 등)
→ ④정기 점검·개선(체계의 우회가능성 재검토)
```

**활용 프로세스(실제 사고대응 시)**
```
①사고인지 → ②중앙보존된 로그·백업으로 1차 증거 확보(로컬흔적 삭제와 무관)
→ ③안티포렌식 흔적 자체를 역분석(언제·어떻게 흔적을 지웠는지가 오히려 의도적 증거인멸의 증거가 됨)
→ ④법적 대응(증거인멸 행위 자체를 추가 입증자료로 활용)
```

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 파일슬랙(File Slack) | 일반 삭제로는 지워지지 않는 영역이라 안티포렌식 시도에도 증거가 남는 대표 사례 |
| 데이터 관측가능성 | 중앙집중 로그보존·모니터링 체계라는 점에서 안티포렌식 대응체계와 기술적으로 유사 |
| SOAR/SIEM | 안티포렌식 행위(대량 로그삭제 시도 등) 자체를 실시간 탐지하는 보안운영 인프라 |

## 5. 파일슬랙 (File Slack)

**절차(개념 및 발생원리)**
```
[디스크 클러스터(예: 4KB 단위)] 파일은 클러스터 단위로만 공간을 차지
   → 실제 파일크기(예: 1.5KB)가 클러스터 크기(4KB)보다 작으면
   → 남는 공간(2.5KB)에 "이전에 그 클러스터를 사용했던 다른 파일의 잔여데이터"가 그대로 남아있음
   = 이 잔여영역이 "파일슬랙"
```

**수집기법(슬랙 영역 종류)**
- **RAM 슬랙**: 파일의 마지막 섹터 내에서 메모리상의 임의 데이터로 채워지는 부분
- **드라이브 슬랙**: 마지막 섹터 이후 클러스터 끝까지, 디스크에 이전에 저장됐던 데이터 잔여물이 남는 부분

**대응체계(포렌식 활용가치)**: 사용자가 파일을 "삭제"해도 실제로는 클러스터의 슬랙영역에 이전 데이터의 흔적이 남아있어, 이를 분석하면 이미 지워진 줄 알았던 문서·이미지의 파편을 복구할 수 있음(강력한 증거 확보 수단)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 파일카빙 4기법 | 파일슬랙에서 발견된 파편 데이터를 실제로 복원하는 데 사용되는 기법 |
| 안티포렌식 | 파일슬랙까지 완전히 지우려면 단순삭제가 아닌 "디가우징/완전덮어쓰기(Wiping)"가 필요함을 보여주는 근거 |
| SSD FTL(플래시변환계층) | HDD와 달리 SSD는 TRIM명령으로 슬랙 데이터가 빠르게 실제 삭제되어 포렌식 복구 가능성이 낮아지는 차이점(컴퓨터구조 도메인과 비교출제 가능) |

## 6. 디지털포렌식 아티팩트 (Artifact)

**절차(개념)**
> 시스템·애플리케이션이 사용자의 행위 흔적으로 자동 생성·기록하는 모든 디지털 잔존물 — 사용자가 의도적으로 남긴 것이 아니라 OS/앱이 부수적으로 생성

**수집기법(주요 아티팩트 유형)**

| 아티팩트 유형 | 예시 |
|---|---|
| **시스템 아티팩트** | 레지스트리(Windows), 이벤트로그, 프리페치(실행이력) |
| **네트워크 아티팩트** | 브라우저 히스토리·쿠키, DNS캐시, ARP테이블 |
| **애플리케이션 아티팩트** | 최근사용문서목록(MRU), 휴지통, 임시파일, 클립보드 기록 |
| **모바일 아티팩트** | 앱 사용시간, 위치기록(GPS로그), 메신저 캐시 |

**대응체계(분석 활용)**: 아티팩트는 사용자가 직접 지우기 어렵거나 그 존재자체를 인지하기 힘든 경우가 많아, "삭제된 파일은 없지만 어떤 행위를 했는지"를 입증하는 핵심 정황증거로 활용(예: 프리페치로 특정 악성파일을 실행한 사실 입증)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 파일슬랙 / 파일카빙 | 아티팩트가 "행위의 흔적"을 보여주는 것과 달리, 이들은 "삭제된 콘텐츠 자체"를 복구하는 기법으로 상호보완적 |
| TTPs(공격자 행동패턴) | 아티팩트 분석으로 공격자의 TTPs(어떤기법을 사용했는지)를 역추적 가능(보안위협 도메인과 연결) |
| MDM(모바일기기관리) | 기업 모바일기기의 아티팩트 수집·관리정책과 연계되는 보안체계 |

## 종합 흐름도

```
[포렌식 표준절차] 사전준비→수집→이미징(D2D/D2F)→분석→보고
        │
[이미징 단계] 디스크이미징(원본보존, 해시검증) → 분석은 항상 사본으로 진행
        │
[분석 단계 — 증거발굴]
  파일카빙(4기법, 삭제파일 복구) ── 파일슬랙(클러스터 잔여데이터 분석)
  디지털포렌식 아티팩트(레지스트리/로그/캐시 등 행위흔적 분석)
        │
[방어적 대응] 안티포렌식 컴플라이언스 — 안티포렌식 시도 자체를 사전대비·탐지하는 기업 보안체계
```
