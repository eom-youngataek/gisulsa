# 신흥 보안위협/제도 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 등장배경 → 위협요인 → 대응전략

## 1. 공급망보안 / SBOM (Software Bill of Materials)

**등장배경**
> SolarWinds 해킹사고처럼, 직접 공격이 아닌 **소프트웨어에 포함된 오픈소스·서드파티 라이브러리를 경유한 침투**가 급증 → "내 코드"만 안전해도 의존하는 외부 컴포넌트가 취약하면 전체가 뚫리는 구조적 위험 부각

**위협요인**
- 오픈소스 라이브러리의 알려진 취약점(CVE) 방치, 출처가 불분명한 패키지의 악성코드 포함(타이포스쿼팅 등)
- 어떤 컴포넌트를 어디서 누가 만들었는지 추적 불가능한 "불투명성"

**대응전략**
- **SBOM(소프트웨어 구성요소 명세서)**: 제품에 포함된 모든 오픈소스·라이브러리·버전정보를 명세화해, 신규 취약점(CVE) 발표 시 영향범위를 즉시 파악
- 공급업체에 SBOM 제출 의무화(공공조달 요건화 추세), 자동화도구(SCA, Software Composition Analysis)로 빌드 시점에 취약 컴포넌트 자동탐지

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| OWASP LLM03(Supply Chain) | AI모델·데이터의 공급망 위협까지 확장된 "AI BOM" 개념(아래 키워드와 직결) |
| 오픈소스 라이선스 정책변화 | SBOM 관리는 라이선스 컴플라이언스 점검과도 함께 수행되는 실무 |
| 제로트러스트 | 공급망상의 컴포넌트도 "기본신뢰"하지 않고 검증한다는 점에서 철학적으로 연결 |

## 2. OWASP Top10 for LLM

**등장배경**
> 생성형AI/LLM이 기업 서비스에 급속히 도입되면서, 전통 웹보안 가이드(OWASP Top10)로는 다루지 못하는 **LLM 특유의 신종 위협**(프롬프트 인젝션, 환각 등)이 다수 발생 → 2023년부터 OWASP가 LLM 전용 가이드라인 별도 발표(2025년 개정판 최신)

**위협요인(핵심 위협 카테고리)**: 프롬프트 인젝션(LLM01), 민감정보유출(LLM02), 공급망(LLM03), 데이터/모델 포이즈닝(LLM04), 부적절한 출력처리(LLM05), 과도한 에이전시(LLM06), 시스템프롬프트 유출(LLM07), 벡터/임베딩 취약점(LLM08), 환각/허위정보(LLM09), 무제한소비(LLM10)

**대응전략**: 입력·출력 검증의 이중 게이트, 에이전트 최소권한 부여(Excessive Agency 방지), RAG 벡터DB 접근통제, 사용량 쿼터제한(Model DoS 방지), LLM 가드레일 아키텍처 도입

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 프롬프트 인젝션 / 모델전도공격 | OWASP LLM Top10의 1·2위 위협 항목(AI보안 도메인에서 상세정리됨) |
| LLM 가드레일(Guardrails) | OWASP가 제시한 위협 전반에 대한 통합적 기술 대응체계 |
| MCP(Model Context Protocol) | 외부도구 연동 시 LLM03(공급망) 위협의 새로운 통로로 부각 |

## 3. AIoT 보안취약점

**등장배경**
> 일반 IoT가 AI 분석기능까지 탑재(AIoT, AI+IoT)하면서, 기존 IoT의 취약점(약한 비밀번호 등)에 더해 **AI모델 자체에 대한 공격표면**까지 추가로 노출되는 복합 위협 환경 조성

**위협요인**
- 기존 IoT 취약점 계승: 기본 비밀번호 방치, 미패치 펌웨어, 불필요한 개방포트
- AI 추가위협: 엣지에 탑재된 AI모델 자체에 대한 모델추출·적대적공격(엣지기기는 물리적 접근이 쉬워 모델파일 탈취 위험 더 높음), 센서 데이터 위변조로 AI 오판 유도

**대응전략(AIoT 디바이스 보안기술 3가지)**: ①디바이스 보안부팅(Secure Boot, 변조된 펌웨어 실행 차단) ②엣지AI모델 암호화·난독화(모델파일 탈취 시에도 역분석 방지) ③경량 암호화 통신(저전력 환경에 맞는 경량암호로 센서-서버 통신보호)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 미라이봇넷 | AIoT 이전, 일반 IoT의 기본 비밀번호 취약점을 노린 대표적 선행사례 |
| 적대적공격 4유형 | AIoT의 엣지AI모델이 직접 노출되는 대표 위협(AI보안 도메인과 연결) |
| NB-IoT / 스마트팩토리 | AIoT가 실제로 적용되는 대표 산업현장(네트워크 도메인과 연결) |

## 4. 양자암호통신

**등장배경**
> 양자컴퓨터의 발전으로 기존 공개키암호(RSA·ECC)가 미래에 무력화될 위협이 가시화 → 양자역학 원리를 활용한 근본적으로 새로운 통신보안 방식의 필요성 부각

**위협요인(현재 직면한 문제)**
- "Harvest Now, Decrypt Later" 공격: 지금 암호화된 데이터를 가로채 저장해두고, 미래 양자컴퓨터로 나중에 복호화하려는 선제적 위협
- 양자암호통신 자체의 한계: 광케이블 거리제약(보통 100km 이내, 중계기 필요), 고비용 전용 인프라

**대응전략(주요기술)**
- **양자키분배(QKD)**: 광자의 양자상태로 키를 전송, 도청시도 시 양자상태가 변형되어 즉시 탐지 가능 → 탐지된 키는 폐기하고 재생성
- **양자내성암호(PQC)**: 소프트웨어적으로 양자컴퓨터도 풀기 어려운 수학문제 기반 알고리즘으로 즉시 전환 가능

**취약점**: 측면채널공격(광원·검출기의 물리적 결함을 이용한 우회공격), 중계기 구간의 신뢰성 문제

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| PQC vs QKD | 양자위협에 대한 두 가지 대응축(암호기술 도메인에서 상세비교됨) |
| 타원곡선암호(ECC) / RSA | 양자컴퓨터(쇼어 알고리즘)에 의해 무력화될 위험에 처한 현재의 표준 암호 |
| 국가 PQC 전환 마스터플랜 | 양자암호통신 위협에 대응하는 국가차원의 단계적 전환 정책 |

## 5. EMP 공격 (HEMP 원리)

**등장배경**
> 전자장비에 의존하는 현대사회의 구조적 취약성 — 군사적 목적(전자전) 또는 자연현상(태양풍)으로 인한 강력한 전자기파가 모든 전자기기를 동시에 무력화할 수 있는 위협의 부각

**위협요인(공격 구분 및 원리)**
- **EMP공격 구분**: 핵폭발에 의한 EMP(NEMP), 비핵 EMP(재래식 폭발물 기반), **HEMP(High-altitude EMP, 고고도 핵EMP)**
- **HEMP의 원리**: 고고도(수십~수백km)에서 핵폭발 시, 감마선이 대기 상층부 분자와 충돌해 대량의 전자를 방출 → 지구자기장과 상호작용하며 광범위 지역(대륙급)에 순간적으로 매우 강한 전자기파(E1~E3 단계) 유도 → 반도체·전력망 등 광범위 동시파괴

**대응전략(방호방안)**
- 물리적 차폐: 패러데이케이지(전자기파 차단함)로 핵심장비 보호
- 전력계통 보호: 변전소에 EMP 보호용 서지차단기(SPD) 설치
- 백업체계: 핵심 통신·전력시스템은 EMP 영향이 미치지 않는 별도 격리시설에 백업 보관

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| BCP/DRS(재해복구) | EMP는 광범위 동시파괴 특성상 일반 재해복구체계의 한계를 시험하는 극단적 시나리오 |
| 데이터센터(IDC) 지리적 위치선정 | EMP 등 광역재해를 고려한 데이터센터 분산배치 전략과 연계 |

## 6. CAPTCHA

**등장배경**
> 웹사이트가 자동화된 봇(Bot)의 무차별 가입·로그인시도·스팸등록을 구별하지 못해, 크리덴셜스터핑·스팸 등 자동화 공격에 그대로 노출되는 문제 해결 필요

**위협요인(CAPTCHA가 막아야 하는 공격)**: 크리덴셜스터핑(자동화 로그인시도), 매크로를 이용한 대량가입/예매, 스팸봇의 댓글·게시물 대량등록

**대응전략(CAPTCHA의 의미와 발전)**
> CAPTCHA = Completely Automated Public Turing test to tell Computers and Humans Apart — "사람만 풀 수 있고 기계는 풀기 어려운" 문제를 제시해 자동화봇을 구별
- 1세대: 왜곡된 텍스트 읽기
- 2세대: 이미지 선택형(reCAPTCHA v2, "나는 로봇이 아닙니다")
- 3세대: 사용자 행동패턴(마우스움직임 등) 분석으로 사람여부를 백그라운드에서 판별(사용자가 별도 문제를 풀지 않아도 됨, reCAPTCHA v3)

**한계**: 최근 AI(이미지인식·OCR 발전)가 CAPTCHA를 자동으로 풀어내는 사례가 늘어, CAPTCHA만으로는 완전한 방어가 어려워짐 → MFA·행동기반 이상탐지와 결합 필요

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 크리덴셜스터핑 | CAPTCHA가 직접 대응하는 대표적 자동화 공격(보안위협 도메인과 연결) |
| 튜링테스트 | CAPTCHA 명칭의 유래가 된 AI 판별 개념(역설적으로 AI가 CAPTCHA를 깨는 현재상황과 대비) |

## 7. 정보보호제품 신속확인제도

**등장배경**
> 기존 CC(국제공통평가기준) 인증은 평가절차에 통상 수개월~1년 이상 소요되어, 빠르게 변화하는 신기술(AI보안·클라우드보안 솔루션 등)이 시장 출시 적기를 놓치는 문제 발생

**위협요인(해결하려는 문제)**: 보안인증 지연으로 공공시장 진입이 늦어져 우수 신기술 보안제품의 도입 지체, 신종위협(랜섬웨어 등) 대응제품의 신속한 시장공급 필요성

**대응전략(제도 운영방식)**: 국가보안기술연구소(NSR) 등이 정식 CC인증보다 **간소화된 절차**로 신청제품의 보안성을 신속 확인, 일정기간(통상 6개월 등) 동안 공공기관 도입을 임시 허용 → 그 기간 내 정규 CC인증 절차를 별도 진행하도록 유도

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| CC(Common Criteria) | 신속확인제도가 보완하는 기존 정식인증제도의 절차적 한계 |
| 소프트웨어 기술성 평가기준 / 조달청 제안서평가기준 | 공공조달 시 보안성 외 기술성 평가와 함께 고려되는 제도(경영정보시스템 도메인과 연결) |

## 8. DRM vs DLP 비교

**등장배경**
> 기업의 핵심 디지털콘텐츠·문서가 내부유출되는 사고가 증가하며, "콘텐츠 자체를 보호"하는 접근(DRM)과 "유출경로를 차단"하는 접근(DLP) 두 가지 패러다임이 함께 발전

**위협요인 및 비교**

| 구분 | DRM(Digital Rights Management) | DLP(Data Loss Prevention) |
|---|---|---|
| 보호대상 | 콘텐츠 자체(파일에 권한정보 내재화) | 데이터의 이동경로(이메일·USB·메신저 전송) |
| 동작방식 | 파일을 암호화하고, 열람권한(읽기/인섄/복사 등)을 세부통제 | 콘텐츠를 스캔해 민감정보 패턴(주민번호 등) 탐지 시 전송 차단 |
| 보호범위 | 파일이 외부로 나가도 권한통제 유지(파일 자체가 잠겨있음) | 내부망 안에서의 이동/유출시도 자체를 감지·차단 |
| 한계 | 권한서버 의존(서버장애시 열람불가), 적용범위 제한적 콘텐츠유형 | 암호화된 파일·새로운 유출경로(스크린샷 등) 탐지 어려움 |

**대응전략**: 두 기술을 상호보완적으로 결합 — DLP로 1차 유출시도 차단 + DRM으로 만약 유출되더라도 콘텐츠 자체의 권한통제를 유지(이중방어)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 망분리 / 융합보안관제 | DRM·DLP 모두 내부정보 유출방지라는 동일한 목적을 가진 인접 보안체계 |
| 안전성확보조치(암호화) | DRM의 핵심기술기반이 되는 암호화 적용방안 |

## 종합 흐름도

```
[공급망/AI 신흥위협] SBOM(공급망 투명화) ──→ OWASP LLM Top10(AI특화 위협대응)
        │
[물리/IoT 신흥위협] AIoT 보안취약점 ──→ EMP공격(국가급 물리적 위협)
```
