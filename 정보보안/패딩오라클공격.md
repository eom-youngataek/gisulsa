### Ⅰ. 개요

앞서다룬 \*\*"CBC모드"\*\*는 블록단위로 암호화하는데, 평문길이가 블록크기(16바이트등)의배수가아니면 \*\*"패딩(빈공간채우기)"\*\*을 추가해야합니다 — 복호화할때 서버는 \*\*"패딩이올바른형식인지"\*\*를 검사하는데, 이때 \*\*"패딩오류"\*\*와 \*\*"다른오류"\*\*를 **다른메시지로알려주면**, 공격자가 그 \*\*차이(오라클)\*\*를 이용해 **평문을바이트단위로복원**할수있습니다.

### Ⅱ. 공격원리 — 오라클을이용한바이트단위복원

| 개념                 | 내용                                                                                    |
| :----------------- | :------------------------------------------------------------------------------------ |
| **PKCS#7패딩**(대표방식) | 부족한바이트수만큼 **그숫자자체를반복해서채움**(예:3바이트부족하면 03 03 03추가)                                     |
| **오라클**(Oracle)    | 서버가 \*\*"패딩이맞다/틀리다"\*\*를 **다른응답(에러메시지,응답시간등)으로알려주는것**— 이자체가 **정보누출**                  |
| **공격핵심원리**         | 앞서다룬 \*\*"CBC의XOR구조"\*\*를 이용— **암호문블록을 한바이트씩바꿔가며**, \*\*"패딩이맞았다"\*\*는 응답이나올때까지 **시도** |

→ 암기: **"서버가패딩이맞는지틀린지만알려줘도, 그정보하나로 평문전체를복원할수있다"** — 앞서다룬 \*\*"암호문공격유형의CCA(선택암호문공격)"\*\*가 \*\*"복호화결과를관찰할수있는능력"\*\*을 악용했다고했는데, 패딩오라클공격이 바로 그 **CCA의가장유명한실제사례**입니다.

### Ⅲ. 구체적공격과정 및 방어책 — 핵심 배점

**함정 방지: "오류메시지를본다"고만답하면절반. 실제로"어떻게한바이트씩복원하는지" XOR연산의구체적원리와, 왜GCM이이문제를원천해결하는지보여줘야완성됩니다.**

**공격과정**(마지막바이트복원예시)

| 단계                 | 내용                                                                                     |
| :----------------- | :------------------------------------------------------------------------------------- |
| **①암호문끝바이트조작**     | 이전블록의 **마지막바이트를0\~255까지 하나씩바꿔가며**전송                                                    |
| **②패딩=0x01이되는값찾기** | 어떤값을넣었을때 \*\*"패딩이맞다"(즉,복호화결과마지막바이트가0x01)\*\*는 응답이나오면                                   |
| **③XOR로원본복원**      | 앞서다룬 \*\*CBC의"복호화값⊕이전블록=평문"\*\*구조를 이용해, \*\*"내가넣은값⊕0x01=복호화중간값"\*\*을 역산해 **원본평문바이트도출** |
| **④반복**            | 이과정을 **블록의모든바이트에대해반복**해 **전체평문복원**                                                     |

→ 암기: **"한바이트씩값을바꿔보며 '패딩이딱맞는지점'을찾고, 그지점의값을이용해 XOR로거꾸로원본을계산해낸다"** — 이는 앞서다룬 \*\*"모델전도공격(출력을거꾸로이용해원본을역산)"\*\*과 **유사한'오라클을이용한역산'철학**입니다.

**방어책**

| 방어                           | 내용                                                                                      |
| :--------------------------- | :-------------------------------------------------------------------------------------- |
| **동일한에러메시지**(1차방어,불완전)       | \*\*"패딩오류"\*\*와 \*\*"다른오류"\*\*를 **구분안되게 똑같은메시지**로응답 — 단, \*\*응답시간차이(타이밍공격)\*\*로 여전히누출가능 |
| **AEAD/GCM 채택**(근본해결,앞서다룬그것) | \*\*"인증태그검증을 패딩검증보다먼저"\*\*수행— \*\*"암호문이변조됐으면, 패딩을보기도전에즉시거부"\*\*되어 **오라클자체가원천봉쇄**        |

→ 암기: **"에러메시지를숨기는건임시방편이고,애초에GCM처럼무결성부터검증하면 패딩오라클자체가성립할수없다"**

### 도식화 제안

```
[방어책 비교]
[1차방어 - 불완전]
같은에러메시지 반환 → 하지만 처리시간차이로 여전히 
                       "타이밍공격"으로 정보누출가능

[근본해결 - AEAD/GCM(앞서다룬그것)]
①인증태그검증(먼저!) → 불일치시 즉시거부(패딩을보기도전에차단)
②일치해야만 → 패딩검증 진행
     ↓
"애초에 변조된암호문은 패딩검증단계까지 도달조차못함"
= 패딩오라클공격 원천불가능
```

**역사적사례**(실무적경각심): 이공격은 \*\*"POODLE(2014),Lucky13(2013)"\*\*같은 **실제CVE로알려진취약점**을통해 \*\*SSL/TLS(구버전)\*\*에서 실제로악용되었으며, 이것이 앞서다룬 \*\*"TLS1.3에서구식CBC스위트를완전히제거하고 AEAD(GCM,ChaCha20-Poly1305)만허용"\*\*하게된 **직접적인계기**입니다.

### Ⅳ. 결론

패딩오라클공격은 **"CBC모드가패딩오류여부를서버가알려주는것자체를 정보누출로악용해, 암호문을바이트단위로 반복시도하며원본평문을완전히복원하는"** 공격입니다 — \*\*"패딩값이맞는지점을찾아, CBC의XOR구조를역산"\*\*하는것이 핵심메커니즘이며, \*\*"동일에러메시지"\*\*같은 **부분적방어**로는 **타이밍공격**등으로 여전히 뚫릴수있습니다 — 근본적해결은 앞서다룬 **AEAD/GCM**처럼 \*\*"인증태그를패딩검증보다먼저확인해, 변조된암호문자체를원천적으로거부"\*\*하는것이며, 이는 실제로 **POODLE,Lucky13**같은 **실제취약점사례**를거쳐 **TLS1.3이CBC를완전히퇴출**시킨 **직접적계기**가 되었습니다 — 이는 오늘하루다룬 **블록암호4모드→암호문공격유형→AEAD/GCM→패딩오라클공격**으로 이어지는 암호학시리즈전체가, **"이론적취약점이,실제CVE로,그리고결국차세대표준(TLS1.3)의탄생으로이어지는"** 완결된 보안기술진화의 이야기로 마무리됩니다.
