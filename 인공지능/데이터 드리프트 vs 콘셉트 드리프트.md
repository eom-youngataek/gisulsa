#### Ⅱ. 데이터 드리프트 vs 컨셉 드리프트 핵심 비교

| **핵심 척도**   | **📊 데이터 드리프트 🚨**                                                            | **🔑 컨셉 드리프트 🚨**                                                                                                     | **🏁 탐지 지표 💯**                                                                      |     |
| ----------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | --- |
| **정의**      | **P(X) 변화** / 입력 데이터의 통계적 분포 변화 / 모델이 학습 못한 패턴 입력 증가                          | **P(Y\|X) 변화** / 동일 입력→다른 정답 관계 변화 / 모델이 학습한 관계 자체가 무효화                                                               | PSI(0.1미만:안정·0.2이상:불안정) / KL 발산·JSD / KS 검정 / 모델 정확도·F1 직접 모니터링                      |     |
| **발생 원인**   | 계절·시간적 변화 / COVID-19 같은 사회·환경 변화 / 수집 장비·시스템 교체 / 고객 구성 변화                    | 스팸 필터: "비아그라"→"비@그라" 변형 / 금리 인상 후 대출 상환율 패턴 변화 / 사용자 행동 양식의 근본적 변화                                                    | **데이터 드리프트**: 레이블 없이 탐지 가능 ✅ / **컨셉 드리프트**: 실제 레이블 필요 🚨 (지연 탐지)                     |     |
| **드리프트 유형** | 공변량 드리프트(P(X)변화) / 레이블 드리프트(P(Y)변화) / 피처 드리프트(특정 컬럼 분포) / 데이터 품질 드리프트(결측·이상치) | **급격한(Sudden)**: 즉각 대응 필수 / **점진적(Gradual)**: 정기 모니터링 / **반복(Recurring)**: 계절성 모델 대응 / **증분(Incremental)**: 신조어·문화 변화 | **ADWIN**: 슬라이딩 윈도우 오차율 변화 탐지 / **DDM**: 오차율+표준편차 경보 / **Page-Hinkley**: 급격한 드리프트 특화 |     |

#### Ⅲ. 탐지·대응 체계

**가. 재학습 트리거 전략**

```
[재학습 트리거 3대 전략]

①시간 기반 (Schedule)
  주·월 단위 주기적 재학습
  → 단순·안정적 / 드리프트 타이밍 불일치 🚨

②성능 기반 (Performance)
  정확도·F1 임계값 이하 시 트리거
  → 정확·즉각 / 실제 레이블 필요 🚨

③드리프트 기반 (Drift) ← 권장
  PSI > 0.2 또는 JSD > 임계값 시 자동 트리거
  → 사전 예방 / 레이블 불필요 ✅
  → 앞서 다룬 데이터 계약 품질 기준 연동
```

---

**나. MLOps CT 파이프라인 통합**

```
[드리프트 탐지 → CT 자동화 흐름]

운영 데이터 수집
       ↓
드리프트 탐지 엔진
  (EvidentlyAI·WhyLogs·Alibi Detect)
       ↓
PSI < 0.1  → 정상·모니터링 유지
0.1≤PSI<0.2→ 주의·알림 발송
PSI ≥ 0.2  → CT 자동 트리거 🚨
       ↓
재학습 파이프라인 실행
  새 데이터 수집→학습→검증→배포
       ↓
Champion vs Challenger A/B 테스트
       ↓
자동 모델 교체 또는 롤백
```

**다. 핵심 비교 암기표**

|구분|데이터 드리프트|컨셉 드리프트|
|---|---|---|
|**변화 대상**|입력 분포 P(X)|입출력 관계 P(Y\|X)|
|**레이블 필요**|❌ 불필요|✅ 필요|
|**탐지 난이도**|낮음|높음 🚨|
|**대표 탐지**|PSI·JSD·KS 검정|ADWIN·DDM·성능 지표|
|**해결 방향**|데이터 재수집·재학습|레이블 재획득·모델 재설계|

→ 암기: **"데이터 드리프트는 세상이 변한 것, 컨셉 드리프트는 진리가 변한 것"**

---

**(제언)** "드리프트는 모델이 배포된 순간부터 시작되는 숙명적 성능 저하입니다. **핵심 방어 원칙은 세 가지 — 데이터 드리프트는 PSI·JSD로 레이블 없이 선제 탐지, 컨셉 드리프트는 지연 레이블 체계로 실제 성능 모니터링, 재학습은 드리프트 기반 트리거로 자동화 — 이며, 앞서 다룬 데이터 계약의 품질 기준을 드리프트 임계값과 연동하고 LLMOps 환경에서는 프롬프트 분포·응답 품질의 드리프트도 별도 모니터링하는 것이 AI 서비스 SLA 유지의 핵심입니다.**"
