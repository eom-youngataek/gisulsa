탄탄한 근거를 확보했습니다. 이 제도는 **"왜 만들었나(속도) → 어떻게 심사·선정하나 → 어떻게 계약하나"** 3단 흐름이 명확해서, 이 흐름대로 스토리를 짜면 조항번호까지 자연스럽게 붙습니다.

### 답안 전체 스토리 흐름 (목차)

```
Ⅰ. 개요 (도입배경 - 기존 조달방식의 한계) — 3~4줄
Ⅱ. 법적근거 및 디지털서비스 정의 (본론①)
Ⅲ. 선정·계약 절차 (본론②, 도식 1개 필수)
Ⅳ. 계약방식 2종 비교 (본론③)
Ⅴ. 결론
```

포인트: 개요에서 \*\*"기존 일반경�쟁입찰은 계약까지 평균 80일 소요 → 클라우드처럼 빠르게 변하는 서비스에는 안 맞음 → 사전검증+수의계약으로 1\~2주로 단축"\*\*이라는 인과관계를 먼저 던지면, 왜 "전문"계약제도인지 논리가 섭니다.

### Ⅱ. 법적근거 — "클·국·조" 3법 연계 (앞서 다룬 CSAP·감리와 같은 위계패턴)

**함정 방지: 이 제도는 특이하게 하나의 법이 아니라 3개 시행령이 동시에 개정되어 만들어졌다는 점이 핵심 출제포인트입니다.**

| 근거법(시행령)                                            | 역할                                    |
| :-------------------------------------------------- | :------------------------------------ |
| **클라우드컴퓨팅법 시행령** 제8조의2·8조의3                         | **디지털서비스 정의 신설** + 디지털서비스 심사위원회 구성 근거 |
| **국가계약법 시행령** 제26조제1항제5호아목 (지방계약법 시행령 제25조제1항제8호차목) | 심사위 선정 서비스에 대한 **수의계약** 근거            |
| **조달사업법 시행령** 제16조                                  | **카탈로그계약** 방식 도입 근거                   |

→ 암기: **"클라우드법에서 정의하고 심사하고, 국가계약법에서 수의계약을 허용하고, 조달사업법에서 카탈로그계약을 열어준다"** — 3법이 각자 역할을 나눠 하나의 제도를 완성한다는 게 핵심입니다.

**디지털서비스 정의 (클라우드컴퓨팅법 시행령 제8조의2)** — 3유형

| 유형           | 내용                        |
| :----------- | :------------------------ |
| ① 클라우드컴퓨팅서비스 | 순수 클라우드 인프라/SW 서비스        |
| ② 지원서비스      | 클라우드컴퓨팅서비스를 지원하는 서비스      |
| ③ 융합서비스      | 지능정보기술 등과 클라우드기술이 융합된 서비스 |

### Ⅲ. 선정·계약 절차 — "심·등·검·계" 4단계

| 단계            | 담당                      | 내용                                   |
| :------------ | :---------------------- | :----------------------------------- |
| ① **심사신청·선정** | **디지털서비스 심사위원회**(과기정통부) | 디지털서비스 해당여부, 경영상태(적격성), 보안성·운영안정성 심사 |
| ② **서비스등록**   | 이용지원시스템                 | 선정된 서비스를 상세규격 포함하여 등록                |
| ③ **카탈로그 검토** | 조달청                     | 상품 기능·가격 등을 담은 카탈로그의 적정성 검토          |
| ④ **계약체결**    | 수요기관                    | 수의계약 또는 카탈로그계약으로 최종 계약               |

### 도식화 제안

```
[디지털서비스 심사위원회] (과기정통부)
     ↓ 선정(해당성/적격성/보안성)
[이용지원시스템 등록] (상세규격)
     ↓
[조달청 카탈로그 검토]
     ↓
┌──────────┴──────────┐
[수의계약]              [카탈로그계약]
직접 수요기관-업체        조달청 개설 종합쇼핑몰
```

→ "기존 계약(조달요청→사전규격공개→입찰공고→입찰→낙찰자선정→계약체결, 수개월)"과 대비해서 "심사→등록→검토→계약(1\~2주)"으로 얼마나 단축됐는지 화살표로 비교하면 임팩트가 커집니다.

### Ⅳ. 계약방식 2종 비교 — 핵심 변별 포인트

| 계약주체 | 수요기관 ↔ 업체 **직접**   | **조달청**이 업체와 카탈로그계약 체결 → 수요기관은 종합쇼핑몰에서 선택 |
| 특징   | 신속, 개별협상           | 표준화된 카탈로그 기반, 대량구매 효율                     |

### Ⅴ. 결론 포인트 (차별화 한 줄)

이 제도의 법적 특이성은, 원래 \*\*공공조달계약(국가계약법 영역)의 예외를 클라우드컴퓨팅법이라는 산업진흥법에서 정의·선정 근거를 만든 "입법기술적 결합"\*\*이라는 점입니다 — 앞서 다룬 CSAP(보안인증)·감리(품질검증)와 마찬가지로 \*\*"제3자 사전검증을 통해 규제를 완화한다"\*\*는 큰 흐름의 연장선이라는 논리로 마무리하면, 오늘 다룬 여러 공공IT 제도 답안들이 하나로 꿰어집니다.

### **1. 답안 전개 스토리 (머릿속 핵심 흐름)**

> "기존 공공기관의 조달 방식은 '공고 띄우고 → 경쟁 입찰하고 → 심사해서 → 계약하기'까지 무려 수개월(평균 80일)이 걸리는 거북이 방식이었다. 코로나19 당시 하루아침에 클라우드 서버를 증설해야 하는 위기 상황에서 기존 조달법으로는 속수무책이었다. 이 낡은 시스템을 타파하기 위해 등장한 혁신이 \*\*'디지털서비스 전문계약제도'\*\*이다. 전문가 위원회가 보안(CSAP)과 품질을 미리 검증해 둔 '전용 쇼핑몰(디지털서비스몰)'에서, 공공 담당자가 \*\*금액에 상관없이 원하는 클라우드를 장바구니에 담아 바로 결제(수의계약)\*\*할 수 있도록 법을 뜯어고친 것이다. 이로 인해 공공 클라우드 도입이 로켓처럼 빨라졌다."

***

### **2. 실제 답안에 쓸 핵심 내용 (암기용)**

#### **I. \[도입] 공공 클라우드 조달의 패러다임 전환, 디지털서비스 전문계약제도 개요**

* **정의:** 공공기관이 클라우드 등 디지털 서비스를 도입할 때, 기존의 장기 소요 입찰 방식을 벗어나 **사전 심사된 서비스를 금액 제한 없이 '수의계약'으로 신속하게 구매**할 수 있도록 신설된 조달 혁신 제도 (2020년 시행).
* **도입 대상:** 클라우드 컴퓨팅 서비스(IaaS, SaaS, PaaS), 클라우드 지원 서비스(마이그레이션, 컨설팅), 클라우드 융합 서비스(AI, IoT 접목 서비스).

#### **II. \[본론 1] 기존 국가 조달 방식 vs 디지털서비스 전문계약제도 비교**

이 제도가 왜 혁신적인지 채점관에게 어필하려면, 기존 방식과의 명확한 비교표가 필수입니다.

| **구분**    | **기존 국가계약 (일반 조달)**                          | **디지털서비스 전문계약제도**                           |
| :-------- | :------------------------------------------- | :------------------------------------------ |
| **적용 대상** | 일반적인 물품 구매 및 SI 구축 사업                        | 클라우드 인프라(IaaS) 및 소프트웨어(SaaS)                |
| **계약 방식** | **경쟁 입찰 필수** (절차 복잡)                         | 🛒 **수의 계약 허용** (원하는 벤더 직접 선택)              |
| **소요 기간** | **수개월 소요 (평균 80일)** (사전규격 공개 → 공고 → 입찰 → 낙찰) | 🚀 **1\~2주 이내 초고속 도입** (검색 → 바로 선택 및 계약 체결) |
| **요금 산정** | 총액 확정 계약 (도입 시 일시불)                          | **구독형(종량제) 요금 체계 지원**                       |

#### **III. \[본론 2] 제도를 떠받치는 3대 핵심 메커니즘 (채점 포인트)**

그렇다면 어떻게 입찰 없이 바로 계약이 가능한 것일까요? 아래 3가지 안전장치 덕분입니다.

1. 👨‍⚖️ **디지털서비스 심사위원회 (사전 필터링)**
   * 과기부, 기재부, 조달청 전문가들로 구성된 심사위원회가 신청 업체의 보안성(CSAP 인증 필수)과 기술력을 **사전에 엄격히 심사하여 전용 몰(Mall)에 등록**. (입찰 경쟁을 사전 검증으로 대체한 것)
2. 🤝 **금액 제한 없는 '수의 계약' 허용**
   * 일반적으로 국가 계약에서 수의계약은 비리 방지를 위해 소액(2천만 원 등)으로 제한되나, 본 제도를 통해 심사위를 통과한 서비스는 **도입 금액의 상한선 없이 합법적으로 수의계약이 가능**토록 특례 부여.
3. 📖 **카탈로그(Catalog) 계약 방식 도입**
   * 요구사항(RFP)을 처음부터 끝까지 다 적어내는 방식이 아니라, CSP(클라우드 벤더)가 제공하는 카탈로그(메뉴판)를 보고 수요 기관이 필요한 옵션(서버 스펙, SaaS 기능 등)만 골라 유연하게 조립하고 구독형으로 결제하는 방식.

#### **IV. \[결론/제언] 민간 클라우드 활성화와 '디지털 플랫폼 정부(DPG)'의 견인차**

* **(키워드 위주 2줄 마무리)** "디지털서비스 전문계약제도의 도입으로 중소 SaaS 기업들의 공공 시장 진출 빗장이 완전히 열렸습니다. 향후 성공적인 **디지털 플랫폼 정부(DPG)** 완성을 위해서는 이 제도를 단순 클라우드 구매를 넘어 인공지능(AI), 빅데이터 결합 서비스까지 폭넓게 수용하는 \*\*'혁신 기술 조달 플랫폼'\*\*으로 고도화해야 합니다."
