## Ⅱ. ISP(Information Strategy Planning)

**정의**
조직의 비전·목표에 부합하는 정보시스템 구축 방향과 중장기 로드맵을 수립하는 전략 계획 활동.
**"What·When(무엇을·언제)"** 을 결정하는 전략적 계획 도구.

**수행 단계 및 산출물**

| 단계 | 활동 | 산출물 |
|---|---|---|
| 1단계 현황 분석 | 내·외부 환경 분석 / As-Is 업무·시스템 분석 | 현황 분석 보고서 |
| 2단계 미래 모델 설계 | To-Be 업무·정보·기술 모델 설계 | 미래 모델 정의서 |
| 3단계 이행 계획 수립 | 과제 도출·우선순위·로드맵 수립 | 이행계획서·마스터플랜 |

**핵심 키워드**
- **CSF(Critical Success Factor)**: 핵심 성공요인 도출
- **Value Chain**: 업무 프로세스 가치 흐름 분석
- **As-Is / To-Be**: 현재→목표 모델 비교
- **로드맵(Roadmap)**: 중장기 정보화 이행 계획
- **아키텍처 모델링**: 업무·데이터·응용·기술 아키텍처 설계

---

## Ⅲ. ISMP(Information System Master Plan)

**정의**
ISP 결과를 토대로 특정 정보시스템의 **구체적 구현 방법(How)** 을 설계하는 마스터플랜.
RFP(제안요청서) 작성의 직전 단계.

**수행 단계 및 산출물**

| 단계 | 활동 | 산출물 |
|---|---|---|
| 1단계 준비 | 사업 범위 확정 / 현행 시스템 분석 | 사업 수행 계획서 |
| 2단계 현황 분석 | 기능·데이터·인터페이스 현황 파악 | 현황 분석서 |
| 3단계 요구사항 정의 | 기능·비기능 요구사항 도출 | 요구사항 정의서 ★ |
| 4단계 미래 모델 설계 | 논리 설계·인터페이스·데이터 설계 | 논리 설계서 ★ |
| 5단계 이행 계획 | 사업비·일정·위험 계획 | 사업 추진 계획서 ★ |

**핵심 키워드**
- **요구사항 정의서**: ISMP 3대 핵심 산출물 ①
- **논리 설계서**: ISMP 3대 핵심 산출물 ②
- **사업 추진 계획서**: ISMP 3대 핵심 산출물 ③ — RFP 작성 기반
- **기능·비기능 요구사항**: 기능(What) + 성능·보안·가용성(How well)
- **RFP(제안요청서)**: ISMP 산출 후 개발 발주 수단
- **투입공수 기반 대가산정**: ISMP 수립비 = 투입인력 × 단가 × 기간

## Ⅳ. EA(Enterprise Architecture)

**정의**
조직 전체의 업무·서비스·데이터·기술을 통합적으로 분석·설계하는 청사진(Blueprint).
**Why·Where(왜·어디서)** — 조직 전체 구조와 정렬 관계를 표현하는 지속 관리 체계.

**4대 아키텍처 계층 (참조모형)**

| 계층 | 내용 | 참조모형 |
|---|---|---|
| **업무(BA)** | 조직 기능·프로세스·역할 | BRM(업무 참조모형) |
| **서비스(SA)** | 정보서비스·응용 시스템 | SRM(서비스 참조모형) |
| **데이터(DA)** | 데이터 구조·표준·흐름 | DRM(데이터 참조모형) |
| **기술(TA)** | HW·SW·네트워크·보안 표준 | TRM(기술 참조모형) |

**범정부 EA 메타모델 3계층** (134회 응용 3교시 1번 기출)
- **현행(As-Is) 아키텍처**: 현재 운영 중인 정보시스템 현황
- **목표(To-Be) 아키텍처**: 개선 목표 상태
- **이행(Transition) 아키텍처**: 현행→목표 전환 계획

**EA 성숙도 모델 5단계** (134회 응용 3교시 1번 기출)

| 단계 | 수준 | 특징 |
|---|---|---|
| 1단계 | 초기(Initial) | EA 인식·시작 단계 |
| 2단계 | 개발(Under Development) | EA 프레임워크 구축 |
| 3단계 | 정의(Defined) | EA 문서화·표준화 완료 |
| 4단계 | 관리(Managed) | EA 기반 의사결정 활용 |
| 5단계 | 최적화(Optimizing) | EA 지속 개선·고도화 |

**핵심 키워드**
- **청사진(Blueprint)**: 조직 전체 정보화 구조 설계도
- **4대 참조모형(BRM·SRM·DRM·TRM)**: EA 구성의 핵심
- **현행·목표·이행 아키텍처**: EA 메타모델 3계층
- **정보 사일로(Information Silo)**: EA 없이 ISP 수립 시 발생하는 부작용
- **ITA(정보기술 아키텍처)**: EA의 국내 공식 명칭 (전자정부법 기반)

## Ⅴ. ISP vs ISMP vs EA 3자 비교표

| 구분 | ISP | ISMP | EA |
|---|---|---|---|
| **목적** | 중장기 정보화 전략 방향 | 특정 시스템 구현 계획 | 조직 전체 아키텍처 청사진 |
| **핵심 질문** | What·When | How | Why·Where |
| **범위** | 조직 전체 정보화 | 특정 정보시스템 단위 | 조직 전체 (업무·서비스·데이터·기술) |
| **수행 주기** | 3~5년 주기 재수립 | 개발 사업 전 1회 | 지속적 관리·갱신 |
| **주요 산출물** | 이행계획서·마스터플랜·로드맵 | 요구사항 정의서·논리 설계서·RFP | 아키텍처 뷰·참조모형·성숙도 평가 |
| **활용** | 사업 우선순위·예산 계획 | RFP 작성·개발 사업 발주 | 정보화 투자 관리·중복 방지 |
| **법적 근거** | 전자정부법(공공기관) | NIA 공통가이드 | 전자정부법 제64조 |
| **수행 주체** | 외부 컨설팅·내부 기획팀 | 외부 전문기관 | 내부 EA팀+외부 지원 |
| **상호 관계** | EA 기반으로 수립 | ISP 결과 기반으로 수행 | ISP·ISMP 수행의 구조적 기반 |

## Ⅵ. 상호 연계 활용 방안

**통합 추진 흐름**
```
EA 수립·관리
    ↓ (아키텍처 원칙·참조모형 제공)
ISP 수립 (전략 방향·로드맵)
    ↓ (개별 사업 선정·우선순위)
ISMP 수행 (구체적 구현 계획)
    ↓ (요구사항·논리 설계·RFP)
개발 사업 발주·수행
    ↓ (결과 반영)
EA 갱신·고도화
```

**EA → ISP 연계**
- EA의 To-Be 아키텍처·참조모형이 ISP 방향 설정의 기준 프레임워크 제공
- EA 없이 ISP 수립 시 → **정보 사일로(Silo)** 발생

**ISP → ISMP 연계**
- ISP에서 도출된 정보화 과제가 ISMP의 분석 대상으로 연결
- ISP의 정보 모델·로드맵이 ISMP의 현황 분석·요구사항 정의의 **입력물**

**ISMP → EA 환류**
- ISMP 수행 결과(구현 아키텍처)가 EA 현행 아키텍처 갱신 자료로 환류
- 정확한 현행 아키텍처 유지를 위한 **지속 관리 체계** 완성
