# IT 프로젝트 일정/비용/리스크 관리 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 정의 → 계산공식 적용(수치대입) → 결과해석/대응전략

---

## 1. WBS (Work Breakdown Structure, 작업분류체계)

**정의**
> 프로젝트 전체범위를 더 작고 관리가능한 작업단위(Work Package)로 계층적으로 분해한 구조 — "프로젝트범위관리의 근간"이 되는 핵심 산출물

**작성원칙**
```
①100% 원칙: 상위작업은 하위작업들의 합과 정확히 일치(빠짐없이, 중복없이=MECE)
②점진적 상세화(Progressive Elaboration): 상위레벨은 개략적, 하위레벨로 갈수록 구체화
③작업패키지(최하위단위)는 독립적으로 산정·배정 가능한 크기로 분할
④8/80 규칙(권고): 최하위 작업패키지는 8시간~80시간 사이의 작업량으로 분할
⑤성과측정이 가능한 단위(완료여부를 명확히 판단할수있는 결과물 기준)로 분할
```

**계산공식 적용(WBS 기반 일정산정 — 작업패키지 합산 예시)**
```
[상위작업: 시스템개발] = [요구분석(40h)] + [설계(80h)] + [구현(160h)] + [테스트(60h)]
   = 340시간(100%원칙 검증: 하위작업 합 = 상위작업 전체)
```

**일정지연 시 만회대책(129회 기출패턴)**
| 대책 | 방식 |
|---|---|
| **크래싱(Crashing)** | 추가인력·자원을 투입해 작업기간을 단축(비용증가 수반) |
| **패스트트래킹(Fast Tracking)** | 순차적으로 진행하려던 작업을 일부 병행수행(리스크증가 수반) |
| **범위조정** | 후순위기능을 차기단계로 이연(Scope 축소) |
| **자원재배치** | 여유있는 작업의 인력을 지연작업에 재배치 |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| EVM | WBS의 작업패키지가 EVM 측정의 기본단위(PV/EV 산정 기준, 다음 키워드와 직결) |
| CPM/PERT(주공정법) | WBS로 분해된 작업들의 선후행관계를 분석해 임계경로를 도출하는 일정관리기법 |
| RTM(요구사항추적매트릭스) | WBS의 작업패키지와 요구사항을 매핑해 추적관리(SW공학 도메인과 연결) |

## 2. EVM (Earned Value Management) — EV/PV/AC 및 SV/CV/SPI/CPI

**정의**
> 프로젝트의 **일정**과 **비용** 성과를 동시에, 그리고 객관적으로 측정하는 프로젝트관리 기법 — "계획(PV)", "실제투입비용(AC)", "실제완료한 작업의 가치(EV)" 3가지를 비교

**구성요소(기본용어)**
| 용어 | 정의 |
|---|---|
| **PV(Planned Value)** | 특정시점까지 계획상 완료**했어야 할** 작업의 가치(예산) |
| **EV(Earned Value)** | 특정시점까지 실제로 완료한 작업의 **계획된 가치**(획득가치) |
| **AC(Actual Cost)** | 특정시점까지 실제로 투입한 비용 |

**계산공식 적용(125회 기출패턴 — EV=500만원, PV=600만원, AC=450만원)**

```
①일정편차(SV, Schedule Variance) = EV - PV = 500 - 600 = -100만원
   → 음수(-) = 일정지연(계획보다 100만원어치 작업을 덜 완료)

②비용편차(CV, Cost Variance) = EV - AC = 500 - 450 = +50만원
   → 양수(+) = 비용절감(계획된 가치 500만원어치 작업을 450만원만 써서 완료 = 효율적)

③일정성과지수(SPI, Schedule Performance Index) = EV/PV = 500/600 = 0.833
   → 1보다 작음 = 계획보다 느리게 진행중(83.3%속도)

④비용성과지수(CPI, Cost Performance Index) = EV/AC = 500/450 = 1.111
   → 1보다 큼 = 비용효율적으로 진행중(투입1원당 1.111원의 가치창출)
```

**결과해석 및 대응전략**
> **종합해석**: "일정은 지연되고 있으나(SV<0, SPI<1), 비용은 효율적으로 사용중(CV>0, CPI>1)" — 즉 **계획보다 적은 자원으로 일하고 있어 진도가 늦다**는 의미

**일정·비용에 대한 위험요소**: 일정지연이 지속되면 후속 마일스톤 연쇄지연 위험, 단 비용효율은 양호하므로 "인력을 더 투입해 일정을 만회(크래싱)"할 여유예산이 있다고 해석가능

**부정적 위험대응 방안(일정·비용 위험 예시로 적용)**
- 일정위험 대응전략: **완화(Mitigate)** — 크래싱으로 인력 추가투입해 SPI를 1.0으로 끌어올림(단, 이렇게되면 비용이 증가해 CPI는 낮아질 가능성 — 일정·비용 트레이드오프 인식 필요)
- 비용위험 대응전략: 현재 CPI가 양호하므로 **수용(Accept)**하며 모니터링만 지속

**추가지표(예측)**: EAC(완료시점예상비용) = BAC/CPI, ETC(잔여작업예상비용) = EAC-AC — 현재 추세가 지속될 경우의 최종비용 예측에 활용

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| WBS | EVM의 PV/EV 측정단위가 되는 작업패키지의 출처 |
| CPM/PERT | 일정지연(SV<0) 발생시 임계경로(Critical Path) 분석으로 만회대책의 우선순위 결정 |
| EAC/ETC/BAC | EVM의 미래예측 확장지표(완료시점 비용예측) |

## 3. 리스크관리 (부정적 위험 대응전략)

**정의**
> 프로젝트에 영향을 줄 수 있는 불확실한 사건(리스크)을 사전에 식별·분석해 대응계획을 수립하는 프로세스 — 부정적위험(위협, Threat)과 긍정적위험(기회, Opportunity)을 모두 다루나, 통상 "위협" 대응이 핵심

**리스크 대응 계획수립 절차**
```
①리스크식별(Risk Identification) — 체크리스트,브레인스토밍,전문가인터뷰로 위험요소 목록화
   → ②정성적분석(발생가능성×영향도로 등급화, 리스크매트릭스) 
   → ③정량적분석(EMV, 기대화폐가치=발생가능성×영향금액)
   → ④대응계획수립(아래 전략선택) → ⑤리스크모니터링(지속 추적·재평가)
```

**위협(부정적위험)에 대한 4대 대응전략**

| 전략 | 내용 | 적용예시 |
|---|---|---|
| **회피(Avoid)** | 리스크의 원인 자체를 제거(계획변경) | 신기술리스크 회피를 위해 검증된 기존기술로 변경 |
| **완화(Mitigate)** | 발생가능성 또는 영향도를 낮춤 | 핵심인력 이탈리스크에 대비해 백업인력 사전교육 |
| **전이(Transfer)** | 리스크의 책임·영향을 제3자에게 이전 | 보험가입, 외부업체와 고정가계약(초과비용은 업체부담) |
| **수용(Accept)** | 리스크를 받아들이고 대응계획만 준비(능동적수용=우발사태예비비 확보, 소극적수용=그냥감내) | 발생가능성·영향이 낮은 리스크는 별도조치없이 모니터링만 |

**계산공식 적용(EMV 기반 의사결정 예시)**
```
[리스크A] 발생가능성 30%, 발생시 영향 -1000만원 → EMV = 0.3×(-1000) = -300만원
[리스크B] 발생가능성 60%, 발생시 영향 -200만원   → EMV = 0.6×(-200)  = -120만원

→ 우발사태예비비(Contingency Reserve) = |EMV합| = 300+120 = 420만원을 사전확보
```

**결과해석/대응전략**: EMV가 큰 리스크A(-300만원)에는 적극적 대응전략(회피/완화)을 우선투입하고, EMV가 작은 리스크B(-120만원)는 수용(예비비 확보)으로 대응하는 것이 자원배분상 효율적

**(기회=긍정적위험)에 대한 대응전략 비교**: 활용(Exploit, 기회를 반드시 실현), 공유(Share, 더 잘다룰수있는 제3자와 협력), 증대(Enhance, 발생가능성·긍정영향 확대), 수용(Accept)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| ISO 31000 | 리스크관리 4대전략(회피/완화/전이/수용)이 ISO31000의 "리스크대응" 단계를 IT프로젝트관리에 구체화한 사례(IT전략기획 도메인과 연결) |
| EMV(기대화폐가치) | 정량적 리스크분석의 핵심 계산기법(의사결정나무분석과 결합활용) |
| 나선형모델(Spiral Model) | 매 반복마다 리스크분석을 명시적으로 수행하는 SDLC모델(SW방법론 도메인과 연결) |
| EVM(CV/SV) | 리스크가 실제로 발생했을 때 그 영향을 정량적으로 드러내는 후행지표로 연계해석 가능 |

## 종합 흐름도

```
[범위분해] WBS(작업분류, 100%원칙) — 모든 프로젝트관리의 기초단위
        │
        ▼
[성과측정] EVM(PV/EV/AC → SV/CV/SPI/CPI) — WBS 작업패키지 단위로 측정
        │  (해석: 일정·비용 성과를 동시진단)
        │
[사전 대비] 리스크관리(EMV 정량화 → 회피/완화/전이/수용 4대전략)
        │
[지연 발생시] WBS재구성(크래싱/패스트트래킹) ←→ 리스크대응전략 재가동
```

### 한 줄 비교 암기
| 키워드 | 핵심 한 줄 |
|---|---|
| WBS | "100%원칙으로 빠짐없이 중복없이 분해" |
| EVM | "EV-PV=일정편차(SV), EV-AC=비용편차(CV)" |
| 리스크관리 | "EMV로 정량화하고, 회피·완화·전이·수용 중 선택" |
