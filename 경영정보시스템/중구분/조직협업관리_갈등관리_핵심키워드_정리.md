## 1. 갈등관리 — 터크만(Tuckman) 5단계 팀발달모델

**개념**
> Bruce Tuckman이 제시한 모델로, 프로젝트팀이 결성되어 해체될때까지 거치는 **예측가능한 5단계의 팀발달 과정**을 설명 — 갈등은 팀발달의 자연스러운(필수적) 단계로 간주

**단계별 특징**

| 단계 | 명칭 | 특징 |
|---|---|---|
| **1단계** | **형성기(Forming)** | 팀원들이 처음 모여 서로 어색하고 탐색적, 역할·목표가 불명확, 정중하고 형식적인 분위기 |
| **2단계** | **격동기(Storming)** | **갈등이 본격화**되는 단계 — 역할경쟁, 리더십에 대한 도전, 의견충돌, 작업방식에 대한 이견발생 |
| **3단계** | **규범기(Norming)** | 갈등을 거치며 팀 운영규칙·역할분담에 합의 형성, 신뢰구축, 협력적 분위기 정착 |
| **4단계** | **성취기(Performing)** | 팀이 최고효율로 작동, 자율적·상호보완적으로 목표달성에 집중, 갈등이 있어도 건설적으로 빠르게 해소 |
| **5단계** | **해체기(Adjourning)** | 프로젝트종료에 따라 팀이 해산, 성과정리·이별의 감정처리(회고/포상 등) |

**PM 관점 해결전략(단계별 PM의 역할)**

| 단계 | PM의 역할 |
|---|---|
| 형성기 | 명확한 목표·역할 제시로 불안감 해소(킥오프미팅, R&R정의) |
| 격동기 | **갈등을 회피하지않고 정면으로 중재** — 그라운드룰 수립, 1:1면담으로 갈등원인 파악 |
| 규범기 | 합의된 규칙을 문서화·정착, 팀워크강화활동으로 신뢰관계 공고화 |
| 성취기 | 권한위임 확대(자율성 부여), 성과를 지속할 수 있도록 장애물 제거에 집중 |
| 해체기 | 회고(Retrospective)로 교훈도출, 팀원의 성과를 공식적으로 인정·다음프로젝트 배치지원 |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 스프린트 회고(Retrospective) | 해체기뿐아니라 애자일에서는 매스프린트마다 작은 규모의 "해체기적 성찰"을 반복 수행(SW방법론 도메인과 연결) |
| 자기조직화팀(Self-organizing Team) | 성취기(Performing)에 도달한 팀의 이상적 상태와 애자일이 추구하는 팀 형태가 일치 |
| 변화관리(Change Management) | 격동기의 갈등을 조직 차원에서 관리하는 더 넓은 개념(AX추진의 장애요인 대응과 연결) |

## 2. 갈등요인과 해결전략

**개념**
> IT프로젝트에서 갈등은 일정·자원·우선순위 등 다양한 원인으로 발생하며, 갈등 자체가 부정적인 것이 아니라 **건설적으로 관리되면 팀성과를 향상**시킬 수 있음(갈등과 프로젝트성과의 관계는 역U자형 — 너무없으면 정체, 너무많으면 붕괴, 적정수준이 최선)

**단계별 특징(갈등의 주요요인 분류)**

| 요인유형 | 구체적 갈등원인 |
|---|---|
| **일정(Schedule)** | 작업순서·우선순위에 대한 이견(프로젝트 갈등 중 가장 빈번) |
| **자원(Resource)** | 인력·예산·장비배분에 대한 부서간 경쟁 |
| **기술적 의견(Technical)** | 설계방식·기술스택 선택에 대한 전문가간 이견 |
| **개인적 업무스타일** | 의사소통방식·성격차이로 인한 갈등 |
| **권력/역할** | 의사결정권한·책임범위의 모호함 |

**PM 관점 해결전략(5가지 갈등해결방식 — Thomas-Kilmann 모델 기준)**

| 전략 | 방식 | 적용상황 |
|---|---|---|
| **협력(Collaborating)** | 양측 모두 만족하는 해법을 함께 모색(Win-Win) | 시간이 충분하고 관계가 중요할 때(가장 이상적이나 시간소요) |
| **타협(Compromising)** | 양측이 일부씩 양보(Lose-Lose지만 빠름) | 시간이 부족하고 동등한 힘을 가진 당사자일 때 |
| **수용(Accommodating)** | 상대방의 요구를 수용(자신의입장양보) | 관계유지가 더 중요하거나 자신의 주장이 틀렸을때 |
| **경쟁/강압(Competing/Forcing)** | PM의 권한으로 일방적 결정 강제 | 긴급상황, 시간이 절대적으로 부족할 때 |
| **회피(Avoiding)** | 갈등상황을 일단 미루거나 무시 | 사소한 문제이거나 감정이 격해져 냉각기간 필요시 |

**해결절차(실무적용)**: ①갈등의 근본원인 파악(일정vs자원vs기술vs개인) → ②당사자간 1:1 경청(객관적 사실확인) → ③5가지 전략 중 상황에 맞는 방식 선택(보통 협력→타협 순으로 시도, 긴급시는 강압) → ④해결안 문서화 및 재발방지(그라운드룰 보완)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 터크만 모델(격동기) | 갈등이 가장 빈번하게 표출되는 팀발달 단계(위 키워드와 직결) |
| 리스크관리(부정적위험 대응전략) | 갈등을 "인적자원 리스크"로 분류해 회피/완화/전이/수용 전략으로 사전대응 가능(이전파일과 연결) |
| RACI매트릭스(역할책임매트릭스) | 권력/역할 갈등의 원인이 되는 역할모호성을 사전에 명확히 정의하는 예방도구 |
| 의사소통관리계획(Communication Management Plan) | 개인적 업무스타일 갈등을 줄이기 위한 프로젝트 차원의 소통규칙 수립 |

## 종합 흐름도

```
[팀 발달의 자연스러운 과정] 터크만모델
형성기(어색) → 격동기(갈등표출) → 규범기(합의) → 성취기(고성과) → 해체기(마무리)
                  │
                  ▼
[격동기에서 실제 발생하는] 갈등요인(일정/자원/기술/개인/권력)
                  │
                  ▼
[PM의 해결전략 선택] 협력 > 타협 > 수용 > 경쟁(강압) > 회피
   (상황의 긴급성·관계중요도에 따라 5가지 전략 중 선택)
```
