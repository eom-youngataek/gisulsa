## 1. ESG경영 (지표/IT역할)

**정의**: 기업의 지속가능성을 환경(Environment)·사회(Social)·지배구조(Governance) 3대측면에서 평가·관리하는 경영패러다임 — 재무성과뿐아니라 비재무적가치를 경영의 핵심축으로 통합

**IT 연계 지표/방법**

| 영역 | 주요지표 | IT의 역할 |
|---|---|---|
| **환경(E)** | 탄소배출량, 에너지효율 | IoT센서로 실시간 에너지모니터링, 데이터센터 전력효율화(PUE측정) |
| **사회(S)** | 정보보호사고건수, 개인정보침해구제 | 정보보호시스템 구축현황·ISMS-P인증여부가 사회적책임 지표화 |
| **지배구조(G)** | IT거버넌스 투명성 | 의사결정과정의 데이터기반 투명화(전자결재,감사로그) |

**사례 적용**: ESG공시 의무화에 대응해 ERP·BI시스템에 ESG데이터 수집·집계모듈 구축, AI를 활용한 ESG리스크 예측(공급망 내 ESG위반 협력사 사전탐지)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 정보보호 시점별 보안활동 / 개인정보침해구제 | ESG의 "사회(S)"영역과 직결되는 보안 도메인 키워드 |
| 데이터센터(IDC) PUE | 환경(E)지표를 직접 측정하는 인프라 효율성 척도(경영정보시스템/컴퓨터구조 도메인과 연결) |
| IT거버넌스 | 지배구조(G)영역의 핵심 평가대상(IT전략기획 도메인과 연결) |

## 2. SCM (수요예측 7단계/안전재고 산정)

**정의**: 원재료조달부터 생산·유통·고객전달까지 공급망 전체를 통합관리해 효율성과 고객만족을 동시추구하는 경영기법

**IT 연계 지표/방법(128회 기출패턴)**

**수요예측 7단계**
```
①목적·범위설정 → ②자료수집(과거판매·시장데이터) → ③예측방법선정(시계열/회귀/AI모델)
   → ④예측수행 → ⑤예측결과검증(실제값과 비교) → ⑥예측오차분석
   → ⑦지속적 모니터링·재예측(피드백반영)
```

**안전재고 산정공식**
```
안전재고 = Z × σ × √리드타임
(Z=서비스수준에 대응하는 표준정규분포값, σ=수요의 표준편차)

예시: 서비스수준95%(Z=1.65), 일일수요표준편차σ=10개, 리드타임4일
   안전재고 = 1.65 × 10 × √4 = 1.65×10×2 = 33개
```

**사례 적용**: AI기반 수요예측(시계열딥러닝)으로 예측정확도를 높여 안전재고를 최적화 → 과잉재고비용과 품절리스크를 동시감소(139회 기출의 VPP전력수요예측과 동일한 시계열예측 원리)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| AR/MA(시계열모형) | 수요예측방법의 통계적 기법(AI/데이터 도메인과 연결) |
| 시계열딥러닝 / 강화학습 | VPP전력수요예측 등 AI기반 수요예측의 최신기법(AI도메인과 연결) |
| 공급망보안(SBOM) | SCM의 물리적 공급망 관리가 SW공급망보안과 동일한 "전체사슬 가시성확보" 철학을 공유(보안 도메인과 연결) |

## 3. CoE (Center of Excellence)

**정의**: 조직 내 특정 전문역량(디지털혁신,데이터분석,AI 등)을 집중시킨 전담조직 — 분산된 역량과 사례를 통합·표준화해 전사적으로 확산시키는 거점역할

**IT 연계 지표/방법**: CoE 성과지표(전사 확산된 모범사례 수, 타부서 지원건수, 표준화된 도구·방법론 채택률), Digital CoE의 경우 디지털혁신 프로젝트 성공률·ROI를 추적관리

**사례 적용**: AI CoE를 신설해 각 사업부의 AI도입 요청을 중앙집중 지원(데이터파이프라인,모델 거버넌스 표준제공) → 부서별 중복투자 방지 및 AI역량의 전사적 빠른 확산

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 디지털혁신 / DX전환 | CoE가 전사 디지털혁신을 견인하는 조직적 메커니즘(아래 키워드와 연결) |
| AX(AI Transformation) | 최근 CoE가 "AI CoE" 형태로 AX추진의 핵심거점역할 수행(IT전략기획 도메인과 연결) |
| SAFe(대규모애자일) | CoE와 유사하게 여러팀의 모범사례를 표준화·확산하는 애자일 거버넌스 메커니즘(SW방법론 도메인과 연결) |

## 4. BPR (Business Process Reengineering)

**정의**: 기존 업무프로세스를 근본적으로 재설계해 **급진적 성과개선**(비용,품질,서비스,속도)을 달성하는 경영혁신기법 — 기존프로세스의 점진적개선이 아니라 "원점에서 다시설계"하는 것이 핵심

**IT 연계 지표/방법**
```
[ISP-BPR 상호보완 관계(131회 기출패턴)]
①ISP가 "정보화비전·전략방향"을 제시 → ②BPR이 "그 비전을 실현할 업무프로세스"를 재설계
③재설계된 프로세스를 ④ISP의 정보시스템 구축계획에 반영(상호 피드백)
```

**지표**: 프로세스리드타임 단축률, 업무처리비용 절감률, 프로세스단계수 감소(예: 7단계→3단계)

**사례 적용**: ERP도입을 계기로 부서별로 분산된 수작업 승인프로세스를 전자결재 단일프로세스로 재설계(업무단계 70%단축), BPR 없이 ERP만 도입하면 "기존의 비효율적 프로세스를 그대로 전산화"하는 한계 발생

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| ISP/ISMP/EA | BPR과 상호보완적으로 결합되는 정보화전략체계(IT전략기획 도메인과 연결) |
| 프로세스마이닝(Process Mining) | BPR 대상 프로세스의 실제 실행로그를 분석해 비효율구간을 데이터기반으로 식별하는 현대적 기법 |
| ERP | BPR이 가장 빈번하게 결합되는 시스템도입 사례 |

## 5. 디지털세 (Digital Tax)

**정의**: 구글·아마존 등 다국적 디지털기업이 실제사업장(고정사업장) 없이도 디지털서비스로 특정국가에서 막대한 수익을 창출하는 것에 대해, 그 국가에 세금을 부과하는 제도(OECD 필라1/필라2 합의기반, 126회 기출패턴)

**IT 연계 지표/방법**: 디지털서비스 매출의 사용자위치 추적(IP주소·결제정보기반 매출귀속국가 산정), 글로벌최저한세(필라2)는 다국적기업 그룹의 실효세율을 국가별로 산정·관리하는 IT시스템 필요

**사례 적용**: 글로벌 IT기업이 매출발생국가별 디지털서비스 이용현황을 추적·신고하는 컴플라이언스시스템 구축, 국내기업도 해외매출에 대한 디지털세 영향분석체계 마련 필요

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 플랫폼경제 / 슈퍼앱 | 디지털세 부과대상이 되는 대표적 비즈니스모델(아래 키워드와 연결) |
| OECD 필라1/필라2 | 디지털세의 국제적 합의체계(추가 학습포인트) |

## 6. 디지털 트랜스포메이션 (DX)

**정의**: 디지털기술(클라우드,AI,빅데이터,IoT등)을 활용해 비즈니스모델·프로세스·조직문화를 근본적으로 혁신하는 경영전략(131회 기출패턴 — 도입배경/개념/특징/요소)

**IT 연계 지표/방법**: DX성숙도모델(디지털화→디지털최적화→디지털혁신 단계별 평가), 디지털매출비중, 데이터기반 의사결정비율

**사례 적용**: 제조기업이 디지털트윈+IoT센서로 생산설비를 실시간 모니터링하며 예지정비체계로 전환(전통적 정기점검에서 데이터기반 예측정비로 비즈니스모델 자체가 변화) — 단순 IT도입(전산화)과 DX의 차이는 "비즈니스모델 자체의 변화여부"

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| AX(AI Transformation) | DX의 최신 진화형, AI중심으로 더 심화된 전환(IT전략기획 도메인과 연결) |
| 디지털플랫폼정부 | 공공부문의 대표적 DX추진사례 |
| 설비예지정비(Predictive Maintenance) | DX의 구체적 실현사례(132회 기출 LangChain 활용 예지정비와 연결, AI도메인과 연결) |

## 7. 슈퍼앱 vs 멀티앱 비교 (132·133회 기출패턴)

**정의**: 슈퍼앱=하나의 앱안에서 결제,쇼핑,메신저 등 **여러 서비스(미니앱)를 통합 제공**하는 플랫폼 / 멀티앱=서비스마다 **별도의 개별앱**을 운영하는 전통적방식

**IT 연계 지표/방법**

| 구분 | 슈퍼앱 | 멀티앱 |
|---|---|---|
| 아키텍처 | 단일앱+미니앱(플러그인형) 구조 | 서비스별 독립앱(각자 개발·배포) |
| 사용자데이터 | 통합ID로 단일 사용자행동데이터 확보(데이터연계용이) | 앱마다 데이터 분산(통합분석 어려움) |
| 개발/유지보수 | 미니앱 SDK·플랫폼표준 필요(초기구축비용 큼) | 앱별 독립개발(단순하나 중복투자) |

**사례 적용**: 중국 위챗(메신저+결제+쇼핑+공공서비스 통합), 국내 카카오톡(메신저기반으로 결제,쇼핑,인증 등 미니앱 확장) — 사용자 락인효과(Lock-in)와 데이터통합분석이 강점, 단 단일앱 장애시 전체서비스 영향이라는 단일장애점 리스크 존재

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| MSA(마이크로서비스아키텍처) | 슈퍼앱 내부 미니앱들이 실제로는 MSA구조로 구현되는 경우가 많음(SW아키텍처 도메인과 연결) |
| NFC / 오픈뱅킹 | 슈퍼앱의 결제·금융 미니앱이 활용하는 핵심 기반기술(네트워크 도메인 및 아래키워드와 연결) |
| API Gateway | 슈퍼앱의 여러 미니앱을 라우팅·통합하는 핵심 인프라(SW아키텍처 도메인과 연결) |

## 8. POP (Point Of Production)

**정의**: 생산현장(공장)에서 발생하는 데이터를 실시간으로 수집·관리하는 시스템 — POS(Point Of Sale, 판매시점)의 제조업버전으로, "생산이 일어나는 시점"의 데이터를 즉시 포착

**IT 연계 지표/방법**: 생산실적(가동률,불량률,생산량)을 실시간 집계, MES(제조실행시스템)와 연계해 현장설비-경영진 의사결정 간 데이터격차(Data Gap) 해소

**사례 적용**: 공장의 각 생산라인에 IoT센서·바코드스캐너를 설치해 POP시스템으로 실시간 생산현황 수집 → MES가 이를 분석해 병목라인 즉시식별 → 경영진은 실시간 대시보드로 생산효율 모니터링(전통적 일일/주간보고 대비 의사결정속도 극대화)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| MES(제조실행시스템) / 퍼듀모델(Level2~3) | POP데이터가 수집되어 활용되는 상위 제조운영시스템(보안 도메인의 산업제어시스템과 연결) |
| 디지털트윈 | POP의 실시간데이터가 디지털트윈의 실세계 동기화 원천데이터로 활용 |
| MODBUS | POP시스템이 현장설비로부터 데이터를 수집하는 데 사용하는 산업통신프로토콜(보안 도메인과 연결) |

## 9. 오픈뱅킹 / 오픈API (핀테크 플랫폼, 125회 기출패턴)

**정의**: 은행들이 표준화된 API를 통해 자사의 계좌·결제기능을 외부(핀테크기업 등)에 개방함으로써, 하나의 앱에서 여러은행의 계좌를 조회·이용할 수 있게하는 금융인프라

**IT 연계 지표/방법(오픈플랫폼 구성)**
```
[오픈 플랫폼 핵심구조]
①Open API(표준화된 인터페이스 — 계좌조회,이체,결제 등 표준화된 API 규격)
②API Gateway(인증,트래픽제어,사용량과금 관리)
③참가기관 인증체계(핀테크기업의 API이용권한 심사·발급)
④정산시스템(은행간 수수료 정산)
```

**제공기능**: 잔액조회, 거래내역조회, 입금·출금이체, 다수은행 통합조회(마이데이터와 결합시 자산통합관리)

**사례 적용**: 토스·카카오페이 등 핀테크앱이 오픈뱅킹API로 여러은행 계좌를 한 화면에서 통합조회·이체 — 사용자는 은행앱을 여러개 설치할 필요없이 하나의 앱으로 모든은행 거래 가능

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 마이데이터 사업 | 오픈뱅킹이 금융분야에 특화된 반면, 마이데이터는 금융+통신+공공정보까지 확장한 상위개념(DB도메인과 연결) |
| API Gateway / MSA | 오픈뱅킹 플랫폼의 기술적 구현기반(SW아키텍처 도메인과 연결) |
| 슈퍼앱 | 오픈뱅킹API를 활용해 금융기능을 미니앱으로 통합하는 슈퍼앱의 구체적 사례(위 키워드와 연결) |
