# 클라우드 정책 거버넌스 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 가이드 근거 → 원칙/기준 → 검토항목

---

## 1. 클라우드 SLA (구성요소/지표)

**가이드 근거**
> 클라우드컴퓨팅법 및 「클라우드컴퓨팅서비스 SLA 가이드」(과기정통부) — 클라우드서비스제공자(CSP)와 이용기관 간 서비스품질을 명문화한 계약기준

**원칙/기준(SLA 구성요소)**
```
①서비스정의(SLA 적용범위·대상서비스 명시)
②서비스수준목표(SLO, Service Level Objective) — 가용성·성능 등 구체적 수치목표
③측정방법(어떤 도구·주기로 측정할지)
④위반시 보상(서비스크레딧 등 패널티 조항)
⑤예외조항(천재지변,예정된정비 등 SLA미적용 상황)
```

**검토항목(핵심 SLA 지표 — 가용률·장애조치시간 등)**

| 지표 | 정의 | 예시기준 |
|---|---|---|
| **가용률(Availability)** | 전체시간 중 정상서비스 제공 비율 | 99.9%(연간 다운타임 약8.76시간 이내) |
| **장애조치시간(MTTR)** | 장애발생부터 복구까지 평균소요시간 | 등급별 차등(긴급4시간/일반24시간 등) |
| **응답시간(Response Time)** | 요청부터 첫 응답까지 시간 | 99%요청이 200ms이내 등 |
| **위약금체계** | SLA미달성시 서비스이용료 환급비율 | 가용률 99.9%미달시 이용료의 N% 환급 |

**(139회 기출 — 공공 SLA 의무화 연계)**: 전자정부법 개정에 따라 2027년부터 행정·공공기관 정보시스템에 등급제+공공SLA표준 적용 의무화 — 정보시스템 등급분류기준에 따라 등급별 SLA(가용률·장애조치시간) 차등적용

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| TIA-942 품질등급 | 클라우드SLA의 가용률 목표를 물리적으로 보장하는 데이터센터 등급기준(컴퓨터구조 도메인과 연결) |
| 고가용성(HA)/고장허용시스템(FTS) | SLA가용률 달성을 위한 기술적 구현방식 |
| 정보시스템 등급제 | 139회 기출의 최신 정책변화, SLA적용수준을 결정하는 분류기준 |

## 2. CSAP 절차 (Cloud Security Assurance Program)

**가이드 근거**
> 클라우드컴퓨팅법 제23조의2 및 「클라우드서비스 보안인증제 운영에 관한 고시」(과기정통부/KISA) — 공공기관이 민간클라우드서비스를 이용하기 전 보안성을 인증받도록 하는 제도

**원칙/기준(인증등급 체계)**
```
[등급분류 — 처리정보의 중요도에 따라]
①상급(가장엄격, 국가기밀급) → ②중급 → ③하급(상대적으로 완화된 기준)
(2023년 등급제 개편으로, 기존 단일기준에서 정보중요도별 차등인증으로 전환)
```

**검토항목(인증절차)**
```
①신청(CSP가 인증신청서·증빙자료 제출)
   → ②서면심사(보안관리체계·기술적 보호조치 검토)
   → ③현장심사(실제 데이터센터·운영현황 점검)
   → ④인증위원회 심의(통과여부 결정)
   → ⑤인증서발급(유효기간 통상 3년, 매년 사후심사)
```

**검토 핵심영역**: 물리적보안(데이터센터접근통제), 네트워크보안(망분리,침입탐지), 시스템보안(접근권한관리), 운영보안(보안사고대응체계), 법규준수(개인정보보호 등)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| ISMS-P | CSAP와 유사한 인증제도 구조(체계심사+현장심사)를 공유하는 정보보호 인증제(보안 도메인과 연결) |
| CC(Common Criteria) | 보안제품 자체의 평가체계로, CSAP(서비스 전체)와는 평가대상이 다른 인접제도 |
| 클라우드 정보화사업 감리 점검가이드 | CSAP 인증과 별도로, 실제 클라우드 사업추진과정을 감리관점에서 점검하는 절차(138회 기출) |

## 3. 공공SaaS이용가이드라인 (위험관리원칙/보안성검토)

**가이드 근거**
> 「공공부문 SaaS 이용 가이드라인」(행정안전부/NIA) — 국가기관·지자체·공공기관이 안전하고 효율적으로 SaaS(서비스형소프트웨어)를 도입·이용할 수 있도록 마련된 지침(134회 기출)

**원칙/기준(클라우드서비스 위험관리 원칙)**
```
①정보자산 중요도에 따른 위험기반 접근(모든 SaaS에 동일기준 적용X, 처리정보 민감도별 차등관리)
②공급자(CSP) 관리책임과 이용기관 책임의 명확한 분리(공동책임모델, Shared Responsibility)
③지속적 모니터링 원칙(도입 후에도 정기적 위험재평가)
```

**검토항목(보안대책 수립 및 보안성 검토)**
| 검토영역 | 세부내용 |
|---|---|
| 계약전 검토 | CSAP인증여부 확인, SLA수준 검토, 데이터 보관위치(국내/해외) 확인 |
| 보안성 검토 | 접근통제방식, 암호화수준(전송/저장), 데이터백업·복구체계 |
| 서비스수준협약 | 가용성·장애대응 기준 명시여부 |
| 종료/이전 대응 | 서비스종료시 데이터반환·삭제 절차 사전확보(Vendor Lock-in 방지) |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| CSAP | 공공SaaS이용가이드라인에서 1차적으로 요구하는 핵심 보안성검증 수단(위 키워드와 직결) |
| 클라우드서비스 유형(IaaS/PaaS/SaaS) | 가이드라인이 SaaS에 특화된 이유(인프라/플랫폼은 별도 가이드, SaaS는 공급자 의존도가 가장높음) |
| 데이터안심구역 / 개인정보안심구역 | 민감정보 처리시 SaaS이용 대신 검토되는 대안적 통제환경(보안/DB 도메인과 연결) |

## 4. 멀티클라우드 (MultiCloud)

**가이드 근거**: 특정 클라우드사업자(CSP)에 대한 종속(Vendor Lock-in) 위험과 단일사업자 장애시 전체서비스 중단 리스크를 완화하기 위해, 여러 CSP를 동시활용하는 전략 — 클라우드 보안인증제·관리체계 차원에서 별도 관리원칙 필요

**원칙/기준(개념 및 필요성)**
```
[개념] 2개이상의 서로다른 CSP(AWS,Azure,GCP,국내CSP 등)를 동시에 활용하는 전략
[필요성] ①Vendor Lock-in 방지 ②CSP별 강점서비스 선택적 활용(Best-of-Breed)
        ③재해복구(한CSP장애시 다른CSP로 전환) ④데이터주권·법규준수(국가별 규제대응)
```

**검토항목(시스템 요구사항 및 주요기술)**

| 요구사항 | 내용 |
|---|---|
| 워크로드 이동성 | 컨테이너/쿠버네티스 기반으로 CSP간 애플리케이션 이전 용이성 확보 |
| 통합관리체계 | 여러CSP를 하나의 대시보드에서 통합모니터링(클라우드관리플랫폼, CMP) |
| 네트워크연동 | CSP간 데이터교환을 위한 VPN/전용선 연결, VXLAN등 가상망 통합기술 활용 |
| 보안정책 일관성 | CSP마다 다른 보안설정을 표준화된 정책으로 일괄적용 |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 클라우드관리플랫폼(CMP) | 멀티클라우드를 통합관리하는 핵심 솔루션(132회 기출과 연결) |
| 컨테이너/쿠버네티스 | 멀티클라우드 간 워크로드 이동성을 보장하는 표준 기반기술(SW아키텍처 도메인과 연결) |
| VXLAN | 여러 CSP의 가상망을 통합연동하는 네트워크 가상화 기술(네트워크 도메인과 연결) |

## 5. 디지털 리터러시 (Digital Literacy)

**가이드 근거**: 디지털전환이 가속화되며 국민 누구나 디지털기술을 이해·활용할 수 있는 역량격차(Digital Divide)가 사회문제로 부각 — 과기정통부 등 「디지털 포용 정책」의 핵심 정책목표로 채택(132회 기출)

**원칙/기준(디지털 리터러시 구성요소)**
```
①기술적 활용능력(디바이스·소프트웨어를 다루는 기본기능)
②정보활용능력(필요정보를 검색·평가·판단하는 능력, 가짜뉴스 식별력 포함)
③디지털 시민의식(온라인에서의 윤리적 행동, 개인정보보호 의식)
④창조적 활용능력(디지털도구로 콘텐츠를 직접 생산·공유하는 능력)
```

**검토항목(정책 추진영역)**: 취약계층(고령층 등) 디지털교육 프로그램, 공공서비스의 디지털접근성 보장(웹접근성 표준준수), AI리터러시(생성형AI 시대의 새로운 역량요구) 확대

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 전자정부발전지수(UN, HCI) | 디지털리터러시가 EGDI의 인적자본지수(HCI) 구성요소로 직접 반영(IT전략기획 도메인과 연결) |
| 웹접근성(KWCAG) | 디지털리터러시가 낮은 취약계층도 공공서비스에 접근가능하도록 보장하는 기술표준 |
| AI윤리기준 / AI리터러시 | 생성형AI 시대에 새롭게 요구되는 디지털리터러시의 확장영역(AI도메인과 연결) |

## 종합 흐름도

```
[클라우드 도입 전 검증] CSAP(보안인증, 공급자 자격검증)
        │
[도입 가이드라인] 공공SaaS이용가이드라인(위험관리원칙+보안성검토) — CSAP인증여부가 핵심검토항목
        │
[운영 중 품질관리] 클라우드SLA(가용률/장애조치시간 등 지표로 서비스품질 보장)
        │
[전략적 확장] 멀티클라우드(Vendor Lock-in 방지, 여러CSP 통합관리)
        │
[국민 역량기반] 디지털 리터러시 — 위 모든 클라우드정책이 효과를 발휘하기 위한 사용자측 전제조건
```
