### **공공 SaaS 도입의 품질 검증: SaaS 도입 감리**

***

#### 답안 전체 스토리 흐름 (목차)

```
Ⅰ. 개요 (왜 SaaS 도입에도 별도의 감리가 필요한가)
Ⅱ. SaaS 도입 감리 핵심 영역
Ⅲ. 비교 및 적용 체계
Ⅳ. 결론
```

포인트: 개요에서 \*\*"앞서 다룬 BMT 제도가 '도입 전 성능 검증'이라면, SaaS 도입 감리는 '전자정부법 제64조·정보시스템 감리기준에 근거해 SaaS 도입 사업 전 과정의 적정성을 제3자 독립 기관이 검증하는 공공 IT 조달 품질 보증 절차'다 — 기존 정보시스템 감리가 자체 구축(On-premise) SW 개발의 요구사항 정의·설계·구현·테스트를 검증하는 데 최적화됐다면, SaaS는 '이미 만들어진 서비스를 구독'하는 방식이므로 감리 관점이 개발 품질에서 앞서 다룬 공공 SaaS 거버넌스 4대 위험관리 원칙(데이터 주권·공급자 종속·서비스 연속성·컴플라이언스)과 CSAP 등급 적합성·SLA 계약 조건 검증으로 전환되는 것이 SaaS 도입 감리의 핵심 특징"\*\*이라는 한 줄로 시작하면 전체 맥락이 드러납니다.

***

#### Ⅱ. SaaS 도입 감리 핵심 영역

**가. 감리 단계별 구분**

| 감리 유형         | 시점         | 핵심 검토 사항                     |
| :------------ | :--------- | :--------------------------- |
| **사업 착수 감리**  | SaaS 선정 이전 | 요구사항 정의·CSAP 등급 요건 적정성       |
| **중간 감리**     | 계약·이행 중간   | 커스터마이징·데이터 이관 계획 적정성         |
| **완료(사후) 감리** | 서비스 오픈 전후  | SLA 이행·보안 설정·데이터 검증          |
| **운영 감리**     | 운영 중 정기    | 앞서 다룬 **CASB·접속기록** 운영 실태 점검 |

***

**나. SaaS 도입 감리 8대 핵심 점검 영역**

| 점검 영역                | 핵심 점검 내용                            |
| :------------------- | :---------------------------------- |
| **①CSAP 등급 적합성**     | 처리 데이터 민감도에 맞는 CSAP 등급(하·중·상) 선정 여부 |
| **②데이터 주권**          | 데이터 저장 위치(국내·해외)·국외 이전 요건 준수        |
| **③계약·SLA 조건**       | 가용성·응답시간·손해배상·해지 조건 명시 여부           |
| **④서비스 연속성**         | 공급자 파산·서비스 종료 시 데이터 반환·이관 계획        |
| **⑤개인정보 안전조치**       | 앞서 다룬 **암호화·접근통제·접속기록** 이행 여부       |
| **⑥공급자 종속(Lock-in)** | 데이터 내보내기 표준 형식 지원·API 개방성           |
| **⑦연계·통합**           | 기존 시스템과의 API 연계·SSO 통합 적정성          |
| **⑧예산·대가산정**         | 앞서 다룬 **AI 서비스 대가산정** 기준 적용 여부      |

***

#### Ⅲ. 비교 및 적용 체계

**가. 기존 SW 감리 vs SaaS 도입 감리 비교**

| 비교 항목       | 기존 정보시스템 감리   | SaaS 도입 감리           |
| :---------- | :------------ | :------------------- |
| **검증 대상**   | 자체 개발 SW 산출물  | 이미 존재하는 상용 서비스       |
| **핵심 관점**   | 요구사항 충족·설계 품질 | 계약 조건·보안 등급·종속성      |
| **소스코드 검토** | 필수            | 불필요(공급자 소유)          |
| **테스트 방식**  | 기능·성능 테스트     | 앞서 다룬 **BMT**·SLA 검증 |
| **보안 검증**   | 자체 보안 설계 검토   | **CSAP 인증 확인**으로 대체  |
| **법적 근거**   | 전자정부법 제58조    | 전자정부법 제64조·CSAP 고시   |

***

**나. 감리 영역별 세부 점검 항목**

| 감리 영역      | 세부 점검 항목                                 |
| :--------- | :--------------------------------------- |
| **계약 관리**  | 표준계약서 사용 여부·과업 범위 명확성·변경 관리 절차           |
| **데이터 관리** | 앞서 다룬 **가명정보 결합** 필요성 검토·데이터 이관 시 무결성 검증 |
| **보안 관리**  | 앞서 다룬 **개인정보 안전조치 기준** 유형별 의무 이행         |
| **성능 관리**  | 앞서 다룬 **BMT** 결과와 실제 서비스 성능 일치 여부        |
| **운영 관리**  | 장애 대응 체계·앞서 다룬 **RTO·RPO** 목표 명시         |

***

**다. 앞서 다룬 개념과의 연결**

| 연계 개념                  | 연결 내용                                    |
| :--------------------- | :--------------------------------------- |
| **공공 SaaS 거버넌스 4대 원칙** | 감리의 핵심 판단 기준(데이터주권·종속·연속성·컴플라이언스)        |
| **BMT 제도**             | 감리 이전 단계의 기술 성능 검증 결과를 감리에서 재확인          |
| **CSAP·CASB**          | CSAP 등급 확인 + CASB로 운영 중 실제 준수 여부 지속 모니터링 |
| **개인정보 안전조치 기준**       | 유형별(1\~3) 의무 이행 여부가 감리 체크리스트 핵심          |
| **AI 서비스 대가산정**        | AI SaaS 도입 시 대가산정 기준 적정성도 감리 범위 포함       |
| **디지털서비스 전문계약**        | 계약 특례 적용 여부·표준계약서 사용 검증                  |

***

**라. SaaS 도입 감리 시 주요 리스크 및 대응**

| 리스크                  | 내용                        | 대응 방향                      |
| :------------------- | :------------------------ | :------------------------- |
| **감리인의 SaaS 전문성 부족** | 기존 감리인이 개발 중심 검증에만 익숙     | SaaS·클라우드 특화 감리 교육·전담 인력   |
| **표준 감리 기준 미비**      | SaaS 특화 감리 기준 상세 지침 부족    | NIA SaaS 감리 가이드라인 지속 보완 필요 |
| **공급자 비협조**          | 해외 SaaS 사업자의 감리 자료 제공 거부  | 계약 시 감리 협조 의무 명문화          |
| **지속적 변경 반영**        | SaaS는 지속 업데이트되어 최초 감리와 괴리 | 정기 운영 감리·변경 관리 프로세스 연계     |

***

**(제언)** "SaaS 도입 감리는 '무엇을 잘 만들었는가'를 검증하던 전통적 감리에서 '무엇을 얼마나 안전하고 유리한 조건으로 구독하는가'를 검증하는 방식으로 감리의 본질이 전환됨을 보여줍니다. **앞서 다룬 공공 SaaS 거버넌스 4대 위험관리 원칙을 감리 체크리스트의 뼈대로 삼고, CSAP 등급 적합성과 개인정보 안전조치 기준 이행 여부를 핵심 보안 검증 항목으로, BMT 결과와 SLA 계약 조건의 일치 여부를 성능 검증 항목으로 구성하며, 공급자 종속 방지를 위한 데이터 내보내기 표준·해지 시 이관 계획을 필수 확인하는 것이 SaaS 시대 공공 IT 조달 감리의 핵심 전략입니다.**"
