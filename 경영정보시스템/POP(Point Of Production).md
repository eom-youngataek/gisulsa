포인트: 개요에서 \*\*"POP는 생산현장(기계·설비·작업자)에서 발생하는 정보를 그 시점(Point)에서 실시간 수집·처리하는 시스템이고, MES는 그 POP 데이터를 활용해 생산 전체를 통제·관리하는 상위시스템"\*\*이라는 위계관계를 먼저 잡으면, 뒤에 나올 비교표가 자연스럽게 이어집니다.

### Ⅱ. POP 시스템 구성 — "현·수·서·연" (4대 구성요소)

| 구성요소                      | 내용                                        |
| :------------------------ | :---------------------------------------- |
| **현장단말(Client)**          | 각 생산현장(라인/설비)에 설치된 PC·바코드/RFID 리더·PLC연동장치 |
| **수집장치(Data Collector)**  | 설비신호(가동/정지/생산수량/온도 등)를 실시간 획득             |
| **서버(Host Computer)**     | 현장 데이터를 집계·저장·처리                          |
| **연계(Network/Interface)** | 현장 PC들을 호스트에 연결하는 네트워크, **ERP/MES와의 연동**  |

→ 암기: **"현장에서 걷어서(현장단말), 신호를 받아서(수집장치), 서버에 모으고(서버), 위아래로 연결한다(연계)"** — POP는 결국 **"현장(Shop Floor)과 관리시스템(ERP/MES) 사이의 다리"** 역할이라는 게 핵심입니다.

### 도식화 제안

```
[생산현장] 기계/설비/작업자
     ↓ 실시간 신호(생산수량/가동시간/온도 등)
[POP: 현장단말+수집장치]
     ↓ 집계
[POP 서버] → 생산진도관리/재공품관리/설비가동관리/품질관리
     ↓ 연계
[상위시스템: MES → ERP]
```

### Ⅲ. POP 핵심기능 — "진·재·가·품·원" (5대 기능)

| 기능             | 내용                              |
| :------------- | :------------------------------ |
| **생산진도관리**     | 계획 대비 실제 생산진행률 실시간 파악           |
| **재공품재고관리**    | 공정 간 이동 중인 재고(WIP) 추적           |
| **기계가동관리**     | 설비 가동률·정지시간(Downtime) 모니터링      |
| **품질관리**       | 공정별 불량 데이터 수집 (온도·압력 등 품질변수 연계) |
| **원가관리(개별원가)** | 실제 투입시간·자재를 기반한 실시간 원가 산출       |

→ 앞서 다룬 "EVM(SV/CV/SPI/CPI)"과 유사한 논리로, \*\*"계획(PV) 대비 실적(EV)을 실시간으로 비교"\*\*한다는 점에서 제조현장판 EVM이라고 볼 수 있다는 유추가 심화 포인트입니다.

### Ⅳ. POP vs MES 비교 — 변별력 핵심

**함정 방지: "POP=MES의 하위개념"이라고만 답하면 절반. 목적과 범위 차이를 명확히.**

| 구분     | **POP**                   | **MES**                                     |
| :----- | :------------------------ | :------------------------------------------ |
| **목적** | 생산현장 데이터의 **실시간 수집·가시화**  | 수집된 데이터를 활용한 **생산 전체의 실행·제어**               |
| **범위** | 생산진도 파악 **위주**(단위공정 중심)   | 실시간 모니터링+**제어**, 물류·작업추적, 불량관리까지 확장         |
| **위상** | **하위계층**(Data Layer)      | **상위계층**(Execution/Control Layer) — POP를 총괄 |
| **관계** | POP가 생산한 데이터를 MES가 **활용** | ERP까지 연계해 경영정보로 확장                          |

→ 암기: **"POP는 걷어오고(수집), MES는 걷은 걸로 지휘한다(제어)"** — 앞서 다룬 "PMO vs 상주감리" 답안의 "역할이 위계로 나뉜다"는 논리구조와 유사하게 대비하면 이해가 쉬워집니다.

### Ⅴ. 결론 포인트 (차별화 한 줄)

POP의 진짜 가치는 데이터를 모으는 것 자체가 아니라, \*\*"생산시점(Point)에서 발생하는 데이터를 지연 없이(Real-time) 확보해야만, 그 위의 MES·ERP가 정확한 의사결결정을 할 수 있다"\*\*는 데 있습니다 — 이는 앞서 다룬 EVM의 "정확한 성과측정이 있어야 정확한 예측(EAC)이 가능하다"는 논리와 같은 구조이며, \*\*"현장 데이터의 정합성이 전체 제조 디지털전환(스마트팩토리)의 출발점"\*\*이라는 결론으로 마무리하면 좋습니다.

### **1. 답안 전개 스토리 (머릿속 핵심 흐름)**

> "사무실에 앉아있는 공장장은 엑셀 보고서가 올라오기 전까지는, 지금 라인에서 불량이 몇 개 났고 3번 설비가 멈춰있는지 알 길이 없는 '깜깜이' 상태다. 이 현장에 빛을 밝혀주는 것이 바로 \*\*'POP(생산시점 관리)'\*\*다. POP는 현장에서 물건이 만들어지는 '바로 그 시점'에 바코드나 센서로 데이터를 실시간 빨아들인다. 윗선(ERP)에서 아무리 치밀한 생산 계획을 짜고 MES가 지시를 내려도, 밑바닥 현장에서 가짜 데이터나 쓰레기 데이터가 올라오면(GIGO) 아무 소용이 없다. 즉, **POP는 상위 시스템을 떠받치는 가장 핵심적인 데이터의 뿌리**이며, 최근에는 작업자의 수동 스캔을 넘어 IoT 센서와 설비(PLC) 통신을 통해 알아서 데이터를 긁어모으는 지능형 엣지(Edge) 단말로 진화하고 있다."

### **2. 실제 답안에 쓸 핵심 내용 (암기용)**

#### **I. \[도입] 스마트 팩토리 데이터의 뿌리, POP 개요**

* **정의:** 공장 생산 라인에서 발생하는 각종 정보(생산량, 불량률, 설비 가동 상태, 투입 인력 등)를 **발생하는 즉시(Real-time) 바코드나 센서 등을 통해 수집**하여 상위 시스템에 전달하는 현장 정보 수집 통제 시스템.
* **도입 목적:** 현장 정보의 실시간(Real-time) 가시성 확보, 작업자의 수기 기록에 의한 휴먼 에러(오류) 완벽 차단, '종이 없는 공장(Paperless Factory)' 구현.

#### **II. \[본론 1] POP의 4대 핵심 기능 및 데이터 수집 인프라**

* **POP의 핵심 관리 영역 4가지 (외우기:** 생/설/품/작\*\*)\*\*
  1. **생산 실적 관리:** 자재의 투입, 반제품/완제품의 생산 수량 자동 카운팅 및 공정 이동 처리.
  2. **설비 상태 모니터링:** 각 설비의 가동/비가동, 속도, 고장(Error) 상태 실시간 추적.
  3. **품질(불량) 관리:** 불량 발생 시점과 유형(스크래치, 치수 불량 등)을 현장에서 즉시 입력.
  4. **작업자 관리:** 작업자 바코드 스캔을 통한 현장 출퇴근 및 특정 공정 투입 시간 기록.
* **실시간 데이터 수집(Data Gathering) 인프라 기술:**
  * **Auto-ID 기술:** 바코드 스캐너, QR코드, RFID 태그 인식.
  * **설비 연동 통신:** 기계(설비)의 두뇌인 PLC(Programmable Logic Controller)와 직접 통신하여 센서 데이터를 긁어모음.
  * **인터페이스:** 작업자가 장갑을 끼고도 조작할 수 있는 터치스크린 기반의 HMI(Human Machine Interface) 단말기 배치.

#### **III. \[본론 2] 공장 정보화 피라미드: POP, MES, ERP의 관계 (필수 도식화)**

#### **IV. \[결론/제언] 수동형 POP에서 지능형 IoT-POP (엣지 컴퓨팅)로의 진화**

* **(키워드 위주 2줄 마무리)** "과거의 POP는 작업자가 일일이 바코드를 스캔해야 하는 '수동 개입형'의 한계가 있었습니다. 진정한 스마트 팩토리로 나아가기 위해서는 수백 개의 설비 센서가 OPC-UA 통신 표준을 통해 스스로 데이터를 뿜어내고, 중앙 서버(클라우드)로 가기 전 단말에서 1차 가공을 끝내는 \*\*'지능형 IoT 엣지 컴퓨팅(Edge Computing) 기반의 POP'\*\*로 인프라를 전면 고도화해야 합니다."
