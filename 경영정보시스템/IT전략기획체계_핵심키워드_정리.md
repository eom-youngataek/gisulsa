# IT 전략 및 기획체계 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 개념비교표 → 수행절차/단계별 산출물 → 추진전략

## 1. ISP vs ISMP vs EA (상호비교)

**개념비교표**

| 구분 | ISP(정보전략계획) | ISMP(정보시스템 마스터플랜) | EA(엔터프라이즈 아키텍처) |
|---|---|---|---|
| 목적 | 경영전략과 연계한 **중장기 정보화 방향** 수립 | ISP에서 도출된 사업의 **구축 이행방안 구체화**(발주前) | 조직전체의 정보자원을 **체계적으로 구조화**해 지속관리 |
| 시점 | 정보화전략 수립단계(3~5년 단위) | 개별사업 발주직전(상세설계 전) | 상시적·지속적(전사 거버넌스 차원) |
| 산출물 | 정보화비전, 추진과제 로드맵 | 사업범위, 일정, 예산, 발주규격서(RFP기반) | 참조모델(업무/데이터/응용/기술), 아키텍처원칙 |
| 관계 | EA·ISMP의 상위 전략적 입력 | ISP과제를 실행가능한 사업단위로 구체화 | ISP/ISMP 수립 시 일관성 검증의 기준틀 제공 |

**수행절차/단계별 산출물(통합관점)**
```
①현황분석(As-Is) → ②목표모델수립(To-Be, EA참조모델 활용)
   → ③ISP: 정보화전략·로드맵 수립(전사차원)
   → ④ISMP: 개별과제별 이행계획·RFP 구체화(사업단위)
   → ⑤EA: 전체 산출물의 일관성·표준준수 여부를 거버넌스 차원에서 지속관리
```

**추진전략**: ISP없이 ISMP만 수립하면 "나무는 보되 숲을 못보는" 개별사업 산출 위험 → ISP(전사방향)→ISMP(사업구체화)→EA(지속거버넌스)의 계층적 연계가 핵심, NIA의 "ISP 및 ISMP 수립 공통가이드"로 양자의 절차·산출물을 표준화(129회 기출패턴)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| BPR(Business Process Reengineering) | ISP와 상호보완적으로 활용되는 업무프로세스 재설계 기법(131회 기출 — ISP-BPR 비교패턴) |
| 정보시스템 감리 / PMO | ISMP 이후 실제 구축단계에서 품질·일정을 관리하는 후속 메커니즘 |
| 범정부 EA 참조모형 / EA성숙도모델 | EA의 구체적 표준체계(134회 기출, "정보기술아키텍처 도입운영지침") |

## 2. IT거버넌스 (구성요소/효과측정 방법론)

**개념비교표(IT거버넌스 5대 의사결정영역, Weill&Ross 모델 기준)**

| 영역 | 내용 |
|---|---|
| IT원칙(Principle) | IT투자의 역할·방향에 대한 최상위 의사결정원칙 |
| IT아키텍처(Architecture) | 기술표준·통합방식에 대한 결정 |
| IT인프라전략(Infrastructure) | 공유서비스 범위·중앙화수준 결정 |
| 업무애플리케이션요구(Application) | 어떤 업무시스템을 구축할지 결정 |
| IT투자·우선순위(Investment) | 예산배분과 프로젝트 우선순위 결정 |

**수행절차/단계별 산출물(효과측정 방법론)**
```
①거버넌스 구조설계(의사결정권한을 누가(경영진/IT부서/현업) 갖는지 매트릭스화)
   → ②지표설정(예: COBIT 프레임워크의 성과지표, Balanced IT Scorecard)
   → ③정량측정(IT투자대비 비즈니스가치, 거버넌스 성숙도 평가)
   → ④개선(거버넌스 구조 재조정)
```

**추진전략**: IT거버넌스는 "IT부서만의 일"이 아니라 경영진의 의사결정구조 설계이므로, CEO/CIO 차원의 의사결정권한 매트릭스(누가 결정,누가 입력,누가 실행)를 명문화하는 것이 출발점

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| COBIT | IT거버넌스의 가장 널리쓰이는 국제 프레임워크 |
| CBAM / IT-ROI | 거버넌스 효과측정에 활용되는 정량적 비용효익분석 기법(SW아키텍처 도메인과 연결) |
| ISO 31000 | IT거버넌스의 투자우선순위 결정에 리스크관리 관점을 결합하는 표준(아래 키워드와 연결) |

## 3. AHP (Analytic Hierarchy Process, 계층화분석법)

**개념비교표(AHP 절차)**
```
①문제를 계층구조로 분해(최상위목표 → 평가기준들 → 대안들)
②각 계층에서 쌍대비교(Pairwise Comparison)로 상대적 중요도 평가(1~9점 척도)
③비교행렬의 고유벡터를 계산해 각 기준·대안의 가중치 산출
④일관성검증(Consistency Ratio, CR<0.1이면 신뢰가능)
⑤최종 종합점수로 대안 우선순위 결정
```

**비교(타 의사결정기법과 비교)**

| 구분 | AHP | 단순가중합(Weighted Sum) |
|---|---|---|
| 가중치산정 | 쌍대비교+수학적(고유벡터) 도출, 일관성검증포함 | 평가자가 직접 임의부여(주관적, 검증없음) |
| 신뢰성 | 높음(일관성검증으로 오류 자체발견) | 낮음 |
| 복잡도 | 높음(계산과정 복잡) | 단순 |

**추진전략**: ERP패키지 선정, IT투자대안 우선순위결정, 정보시스템감리에서 "사업유형별 감리비중" 결정 등 **복수기준·복수대안 의사결정**상황에 광범위 활용 — 평가자간 쌍대비교 결과편차가 크면 워크숍으로 합의도출 필요

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| CBAM | 비용효익까지 정량화하는 AHP의 보완기법(SW아키텍처 도메인과 연결) |
| BSC(균형성과기록표) | AHP로 도출한 우선순위를 BSC의 전략맵에 반영하는 연계활용(아래에서 별도정리) |
| 다기준의사결정(MCDM) | AHP가 속하는 상위 의사결정이론 범주 |

## 4. TAM-SAM-SOM (시장규모 추정 프레임워크)

**개념비교표**

| 구분 | TAM(Total Addressable Market) | SAM(Serviceable Addressable Market) | SOM(Serviceable Obtainable Market) |
|---|---|---|---|
| 정의 | 해당산업의 **전체** 시장규모(이론적최대) | TAM중 **우리비즈니스모델로 실제 도달가능한** 시장 | SAM중 **현실적으로 우리가 점유가능한(경쟁고려)** 시장 |
| 범위 | 가장넓음 | TAM의부분집합 | SAM의부분집합(가장좁음) |
| 활용목적 | 산업의 성장가능성·매력도 제시 | 사업모델의 실제 타겟범위 정의 | 단기(1~3년) 매출목표·투자유치 근거 |

**수행절차/단계별 산출물**
```
①TAM산정(거시통계·산업리포트 활용, 예: "국내 전체 핀테크시장 10조원")
   → ②SAM산정(자사 서비스범위·지역 등으로 필터링, 예: "20~30대 모바일결제 시장 2조원")
      → ③SOM산정(경쟁사점유율·자사역량 고려, 예: "3년내 점유가능 200억원")
```

**추진전략**: 신규사업기획·투자제안서(IR)에서 "시장이 충분히 크다(TAM)"는 비전제시와 "그래서 우리가 실제로 얼마를 가져갈수있는가(SOM)"라는 현실성을 함께 제시해야 투자자·경영진 신뢰확보(TAM만 강조하면 "현실성 없는 장밋빛전망"으로 비판받기 쉬움)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| BCG Matrix | 시장성장률-점유율 기반의 또다른 시장분석 프레임워크(이전 모범답안에서 정리됨) |
| SWOT/3C/PEST | TAM-SAM-SOM과 함께 사업기획서에 활용되는 경영환경분석 기법군 |
| IT-ROI | SOM 추정치가 투자대비 수익률 계산의 기초데이터로 활용 |

## 5. AX (AI Transformation, AI 전환)

**개념비교표(DX와 비교)**

| 구분 | DX(Digital Transformation) | AX(AI Transformation) |
|---|---|---|
| 핵심기술 | 클라우드·모바일·데이터 전반 | **생성형AI/LLM 중심**의 자율적 의사결정·업무수행 |
| 변화수준 | 프로세스의 디지털화·효율화 | 프로세스를 **AI가 직접 수행·판단**하는 수준까지 심화 |
| 인력역할변화 | 디지털도구 활용능력 요구 | AI와의 협업·AI거버넌스 역량까지 요구 |

**추진절차**
```
①AX 비전·목표설정(경영진주도, 어느업무에 AI를 적용할지 우선순위화)
   → ②현황진단(데이터준비도, AI인프라, 인력역량 평가)
   → ③파일럿추진(소규모 PoC로 효과검증)
   → ④확산(검증된 영역을 전사로 확대, 거버넌스체계 동시구축)
   → ⑤내재화(AI활용이 조직문화·프로세스의 기본값이 되도록 정착)
```

**장애요인 3가지 이상과 대응방안(136회 기출패턴)**
| 장애요인 | 대응방안 |
|---|---|
| 데이터 품질·거버넌스 미흡 | AI학습데이터 품질관리체계 우선구축 |
| 조직의 변화저항(일자리불안 등) | 변화관리 프로그램, AI리터러시 교육 |
| AI거버넌스·신뢰성 미확보 | AI기본법·AI RMF 등 거버넌스 프레임워크 선제도입 |
| 레거시시스템과의 통합복잡성 | API/MCP 등 표준연동체계로 단계적 통합 |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 디지털플랫폼정부 | 공공부문의 DX→AX 전환사례(아래에서 연결가능) |
| AI기본법 / AI RMF / ISO42001 | AX 추진시 함께 구축해야하는 거버넌스 기반(AI도메인과 연결) |
| 변화관리(Change Management) | AX의 조직저항 장애요인을 해소하는 핵심 관리기법 |

## 6. ISO 31000 (리스크관리 표준)

**개념비교표(구성요소)**

| 구성 | 내용 |
|---|---|
| **원칙(Principles)** | 가치창출·통합적·구조화된 접근 등 리스크관리의 기본철학 |
| **프레임워크(Framework)** | 리더십·의지표명, 리스크관리 정책·조직체계 |
| **프로세스(Process)** | 범위·상황·기준수립 → 리스크식별 → 리스크분석 → 리스크평가 → 리스크대응 → 모니터링·검토 |

**수행절차/단계별 산출물**
```
①범위·상황·기준수립(어떤 리스크를 다룰지, 평가기준은 무엇인지 정의)
   → ②리스크식별(위험요소 목록화) → ③리스크분석(발생가능성×영향도)
   → ④리스크평가(우선순위화) → ⑤리스크대응(회피/완화/전이/수용 중 선택)
   → ⑥모니터링·검토(지속적 재평가) [전과정에서 의사소통·협의 동시수행]
```

**추진전략**: ISO31000은 특정산업에 국한되지 않는 **범용 리스크관리표준**이므로, IT프로젝트리스크관리·정보보안리스크관리(ISMS-P)·AI리스크관리(AI RMF) 등 각 영역별 표준의 상위 공통 골격으로 활용 — 조직 전체의 리스크관리 언어를 통일하는 효과

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| AI RMF(NIST) | ISO31000의 일반적 리스크관리 프로세스를 AI영역에 특화시킨 사례(AI도메인과 연결) |
| 부정적위험 대응전략 / IT프로젝트 리스크관리 | ISO31000 프로세스를 IT프로젝트관리 영역에 적용한 구체적 사례 |
| 나선형모델(Spiral Model) | "리스크분석을 반복마다 명시적으로 수행"하는 점에서 ISO31000의 철학을 SDLC에 내재화한 사례(SW방법론 도메인과 연결) |

## 7. 전자정부 발전지수 (UN 평가)

**개념비교표(평가지수 구성요소)**

| 지수 | 구성요소 |
|---|---|
| **EGDI(E-Government Development Index)** | 온라인서비스지수(OSI) + 통신인프라지수(TII) + 인적자본지수(HCI) 3개 평균 |
| **OSI(Online Service Index)** | 정부가 제공하는 온라인서비스의 범위·품질 |
| **TII(Telecommunication Infrastructure Index)** | 인터넷보급률·모바일가입률 등 인프라수준 |
| **HCI(Human Capital Index)** | 교육수준·문해율 등 디지털활용 기반역량 |

**평가방법(절차)**: UN(UNDESA)이 **2년마다** 회원국 전체를 대상으로 설문·통계자료 기반평가 → EGDI 순위발표 → 각국은 이를 디지털정부 정책수립의 벤치마킹·국가브랜드 홍보자료로 활용(127회 기출패턴)

**추진전략(한국의 활용사례)**: 한국은 역대 EGDI 최상위권을 지속유지 — 디지털플랫폼정부, 전자정부 웹사이트 UI/UX표준 등 정책의 국제적 정당성·성과지표로 활용, 평가지수 하락요인(예: TII의 모바일인프라 변화)을 선제적으로 정책반영
