BPR은 이미 여러 답안(AX추진절차, CoE)에서 "과업발굴의 근거"로 언급됐던 개념입니다. 오늘은 정면으로 다루되, **"왜 하는가(문제의식) → 어떻게 하는가(절차) → 뭘 조심해야 하는가(실패요인)"** 3단으로 스토리를 짜겠습니다.

### 답안 전체 스토리 흐름 (목차)

```
Ⅰ. 개요 (BPR 정의, Hammer의 원조 개념) — 3~4줄
Ⅱ. BPR 추진절차 (본론①, 도식 1개 필수)
Ⅲ. 핵심 원칙/기법 (본론②)
Ⅳ. 실패요인 및 성공조건
Ⅴ. 결론
```

포인트: 개요에서 \*\*"BPR은 기존 프로세스를 부분개선(TQM처럼 점진적)하는 게 아니라, 원점에서 재설계(Zero-base)하는 근본적 혁신"\*\*이라는 정의를 정확히 잡아야 합니다. Hammer의 정의 — \*\*"비용, 품질, 서비스, 속도 등 핵심성과의 극적 개선을 위해 업무프로세스를 근본적으로 재설계"\*\*하는 것 — 이 한 줄이 개요의 핵심입니다.

### Ⅱ. BPR 추진절차 — "비·현·설·실·평" (5단계)

| 단계                 | 핵심활동                                     |
| :----------------- | :--------------------------------------- |
| ① **비전/목표설정**      | 경영전략과 연계된 혁신목표(비용/품질/속도) 설정              |
| ② **현황분석(As-Is)**  | 현재 프로세스 맵핑, 비효율·중복 진단                    |
| ③ **설계(To-Be)**    | **원점에서 재설계** — 기존 프로세스 답습 지양, 목표 프로세스 설계 |
| ④ **실행(Pilot→확산)** | 시범적용 후 검증, 전사 확산                         |
| ⑤ **평가/정착**        | 성과측정, 지속개선체계 구축                          |

→ 암기: **"비전 세우고, 현재를 진단하고, 백지에서 다시 설계하고, 실행하고, 평가한다"** — 앞서 다룬 "AX 추진절차(진전파확내)"와 거의 동일한 흐름입니다. \*\*"As-Is 분석 후 To-Be를 재설계한다"\*\*는 이 절차 자체가 BPR의 정체성입니다.

### 도식화 제안

```
[As-Is 현황분석] ──────→ [To-Be 재설계]
(기존 프로세스 맵)         (원점에서 재설계, 원칙 적용)
         ↓                        ↓
    비효율/중복 진단          Pilot → 확산 → 정착
```

→ "As-Is에서 To-Be로 가는 화살표가 기존 프로세스를 '따라가는' 게 아니라 '건너뛰는' 것"이라는 시각적 강조가 BPR의 핵심을 보여줍니다.

### Ⅲ. 핵심 원칙 — "통·병·분·최" (Hammer의 재설계 원칙)

| 원칙                            | 내용                                                 |
| :---------------------------- | :------------------------------------------------- |
| **통합** (Integration)          | 여러 사람이 수행하던 작업을 **한 사람/한 프로세스로 통합** (Case Manager) |
| **병렬화** (Parallel Processing) | 순차적 단계를 **동시병행** 처리 (앞서 다룬 "Fast-Tracking"과 유사원리)  |
| **분권화** (Empowerment)         | 의사결정 권한을 **실무자에게 이전**(승인단계 축소)                     |
| **최소화** (Elimination)         | 부가가치 없는 **검토·승인·대기 단계 제거**                         |

→ 암기: **"합치고(통합), 동시에 하고(병렬), 권한을 넘기고(분권), 없앨 건 없앤다(최소화)"** — 4개 원칙이 결국 \*\*"단계를 줄이고 권한을 낮춘다"\*\*는 하나의 논리로 귀결됩니다.

### Ⅳ. 실패요인 및 성공조건 (실무형 배점)

| 실패요인                | 성공조건(뒤집기)                                                                       |
| :------------------ | :------------------------------------------------------------------------------ |
| 부분개선에 그침(As-Is에 갇힘) | **원점재설계 원칙 고수**, 경영진의 강한 의지                                                     |
| 조직저항(기득권 상실 우려)     | 변화관리 병행(앞서 다룬 "갈등관리" 답안과 연결)                                                    |
| IT를 단순 자동화 도구로만 사용  | **IT를 프로세스 재설계의 인에이블러(Enabler)로 활용** — 예: 기존 승인체계를 없앨 수 있는 건 실시간 정보공유 IT가 있기 때문 |
| 성과측정 미비             | BSC/KPI 연계(앞서 다룬 BSC 전략맵과 연결)                                                   |

→ "IT는 BPR의 도구가 아니라 재설계를 가능하게 하는 조건(Enabler)"이라는 논리 — 이게 BPR/IT 관계의 핵심 출제 포인트입니다. IT가 있어야 통합·병렬화·분권화가 실현 가능하다는 것.

### Ⅴ. 결론 포인트 (차별화 한 줄)

BPR의 진짜 어려움은 기술이 아니라 \*\*"기득권을 내려놓게 하는 조직변화관리"\*\*에 있습니다 — 이는 앞서 다룬 "터크만 모델(격동기)"·"갈등요인과 해결전략"과 정확히 연결되는 지점이며, BPR·CoE·AX추진이 모두 결국 \*\*"조직의 변화수용력"\*\*이라는 공통분모를 갖는다는 논리로 마무리하면, 오늘까지 다룬 조직관리 계열 답안들이 하나로 꿰어집니다.

### **1. 답안 전개 스토리 (머릿속 핵심 흐름)**

> "과거 기업들은 효율이 떨어지면 기존 방식을 조금씩 고쳐 쓰는 땜질식 처방(PI)에 의존했다. 하지만 급변하는 시대에는 이런 점진적 개선만으로는 살아남을 수 없다. 기존의 낡은 규칙을 다 찢어버리고, 아예 \*\*'백지 상태(Zero-base)'\*\*에서 일하는 방식을 처음부터 다시 그리는 극약 처방이 필요한데, 이것이 바로 \*\*'BPR'\*\*이다. BPR은 부서 간의 이기주의 장벽을 부수고 철저히 '프로세스 중심'으로 회사를 뜯어고치는 급진적 혁신이다. 밥그릇이 깨지는 이런 파괴적 혁신은 필연적으로 엄청난 직원들의 저항을 부르기 때문에, \*\*최고경영자의 강력한 칼잡이 리더십(Top-down)\*\*과 뼈를 깎는 **변화관리(Change Mgmt)**, 그리고 이를 구현할 **IT 기술**이 삼위일체가 되어야만 성공할 수 있다."

***

### **2. 실제 답안에 쓸 핵심 내용 (암기용)**

#### **I. \[도입] 백지 상태(Zero-Base)에서 다시 그리는 혁신, BPR 개요**

* **정의:** 비용, 품질, 서비스, 속도와 같은 핵심적인 성과 지표에서 극적인 향상을 이루기 위해, 기업의 **업무 프로세스(Business Process)를 근본적으로 다시 생각하고 급진적으로 재설계**하는 기법.
* **목적:** 단순한 부서 이기주의 타파, 고객 지향적인 가치 사슬(Value Chain) 재구축, IT 기술을 지렛대(Enabler)로 활용한 획기적 생산성 도약.

#### **II. \[본론 1] 마이클 해머(Michael Hammer)가 정의한 BPR 4대 핵심 키워드 (절대 암기)**

이 4가지 키워드는 BPR 답안의 심장과 같습니다. 반드시 눈에 띄게 적어주세요.

1. 🌱 **근본적 (Fundamental):** "우리가 왜 이 일을 하고 있는가? 왜 반드시 이런 방식으로 해야만 하는가?"라는 가장 뿌리 깊은 본질적 질문에서 출발. (기존의 당연한 규칙들을 타파)
2. 🧨 **급진적 (Radical):** 기존의 것을 조금씩 고치는 것(개선)이 아니라, 옛것을 버리고 백지 상태(Zero-base)에서 완전히 새로운 구조를 짜는 파괴적 혁신.
3. 📈 **극적 (Dramatic):** 5\~10% 수준의 미미한 실적 향상이 아니라, 단숨에 50%\~100% 이상 퀀텀 점프(Quantum Jump)하는 극적인 성과 향상 추구.
4. ⚙️ **프로세스 중심 (Process):** 조직(부서)이나 사람 단위로 쪼개서 생각하지 않고, 고객에게 가치를 전달하는 처음부터 끝까지의 '업무 흐름(프로세스)' 전체를 최적화의 대상으로 삼음.

#### **III. \[본론 2] BPR 추진 절차 및 PI(점진적 개선)와의 핵심 비교**

**1. BPR 추진 4단계 방법론 흐름도** `[비전 및 목표 수립] → [AS-IS 프로세스 분석] → [TO-BE 프로세스 재설계] → [시스템 구현 및 변화관리 적용]`

**2. BPR vs PI (Process Innovation) 비교표** 면접에서도 단골로 묻는 "BPR과 PI의 차이가 무엇입니까?"에 대한 모범 답안입니다.

| **구분**    | **BPR (재설계)**                        | **PI (프로세스 혁신/개선)**                 |
| :-------- | :----------------------------------- | :---------------------------------- |
| **혁신 강도** | **급진적 (Radical), 파괴적**               | **점진적 (Incremental), 지속적**          |
| **출발점**   | **백지 상태 (Zero-base)** (과거의 프로세스는 버림) | **기존 프로세스 유지** (현행 프로세스의 병목/비효율 제거) |
| **조직 변화** | 기존 조직 구조를 **완전히 해체 및 재배치**           | 기존 부서의 틀(조직도)은 **유지**               |
| **추진 방식** | 하향식 (**Top-down**) - CEO 주도          | 상향식 (**Bottom-up**) - 실무자 주도        |
| **리스크**   | 극도로 높음 (성공하면 대박, 실패 시 치명타)           | 상대적으로 낮음                            |

#### **IV. \[결론/제언] 성공적인 BPR을 위한 3대 성공 요인 (CSF)**

* **(키워드 위주 2줄 마무리)** "BPR의 최대 적은 '지금 이대로가 좋다'는 내부 기득권의 거센 저항입니다. 성공적인 BPR을 위해서는 **① 최고경영자의 강력한 스폰서십(Top-down)**, ② 최신 IT 기술(AI, 클라우드 등)의 조력자(Enabler) 활용, ③ 저항을 잠재우고 비전을 공유하는 \*\*'변화관리(Change Management)'\*\*가 완벽하게 삼위일체를 이루어야 합니다."
