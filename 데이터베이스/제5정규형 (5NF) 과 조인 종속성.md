### **제5정규형 (5NF) 과 조인 종속성 (Join Dependency)**

#### 답안 전체 스토리 흐름 (목차)

```
Ⅰ. 개요 (왜 4NF 이후에도 이상 현상이 남는가)
Ⅱ. 조인 종속성 핵심 원리
Ⅲ. 제5정규형 핵심 원리
Ⅳ. 정규화 전체 비교
Ⅴ. 결론
```

포인트: 개요에서 \*\*"앞서 다룬 MVCC·트랜잭션 무결성이 '런타임 데이터 일관성'을 보장한다면, 정규화는 '스키마 설계 단계에서 이상 현상(Anomaly)을 원천 제거'하는 설계 원칙이다 — 1NF\~4NF가 함수 종속성·다치 종속성을 제거한다면, 제5정규형(5NF·PJNF·Project-Join Normal Form)은 '3개 이상 속성 간에 존재하는 조인 종속성(Join Dependency)을 분해해 프로젝션-조인으로 무손실 재구성 불가능한 이상 현상까지 제거'하는 정규화의 최종 완성 단계이며, 앞서 다룬 CBO 옵티마이저가 실행계획에서 다중 조인을 처리할 때 조인 종속성이 없는 5NF 스키마가 일관된 결과를 보장하는 이론적 기반"\*\*이라는 한 줄로 시작하면 전체 맥락이 드러납니다.

***

#### Ⅱ. 조인 종속성 핵심 원리

**가. 조인 종속성 정의**

```
[조인 종속성 (Join Dependency) 정의]

릴레이션 R이 속성 집합 {X, Y, Z, ...}로
무손실 분해될 수 있을 때:

JD(R) = *(X, Y, Z)
→ R = πX(R) ⋈ πY(R) ⋈ πZ(R)
   (프로젝션 후 조인 시 원본 R 완전 복원)

단, 이 분해가 후보키에 의해 내포되지 않으면
→ 조인 종속성이 존재하는 것
→ 5NF 위반
```

***

**나. 조인 종속성 예시**

```
[5NF 위반 예시: 공급자-부품-프로젝트]

릴레이션 SPJ:
┌──────┬──────┬──────────┐
│공급자 │부품  │프로젝트   │
├──────┼──────┼──────────┤
│S1    │P1   │J1        │
│S1    │P2   │J1        │
│S2    │P1   │J1        │
│S2    │P2   │J2        │
└──────┴──────┴──────────┘

비즈니스 규칙:
  공급자가 부품을 공급하고 (SP)
  부품이 프로젝트에 사용되고 (PJ)
  프로젝트가 공급자와 관계있으면 (SJ)
  → (S, P, J) 튜플이 반드시 존재

→ JD*(SP, PJ, SJ) 성립
→ 후보키(공급자·부품·프로젝트)에 의해 내포되지 않음
→ 5NF 위반 🚨
```

#### Ⅲ. 제5정규형 핵심 원리

**가. 5NF 정의 및 달성 조건**

| **핵심 척도** | **📊 5NF 정의·조건 🚨**                                                                             | **🔑 5NF 분해 방법 🚨**                                                                                          | **🏁 이상 현상 제거 💯**                                                                                                  |
| :-------- | :---------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------ |
| **정의**    | 릴레이션 R이 5NF ↔ R의 모든 조인 종속성이 **후보키에 의해 내포**됨 / 즉 후보키로만 무손실 분해 가능 / 조인 종속성 자체는 존재해도 무방·후보키 내포가 핵심 | **SPJ → 3개 릴레이션 분해**: SP(공급자·부품) / PJ(부품·프로젝트) / SJ(공급자·프로젝트) / πSP(SPJ) ⋈ πPJ(SPJ) ⋈ πSJ(SPJ) = SPJ (무손실 ✅) | **삽입 이상 제거**: 새 공급자-부품 관계를 SP에만 삽입 가능 / **삭제 이상 제거**: 프로젝트 삭제 시 공급자-부품 관계 유지 / **갱신 이상 제거**: 부품-프로젝트 관계 변경 시 PJ만 수정 |
| **전제 조건** | **4NF 만족 필수** / 즉 다치 종속성 제거 후 5NF 검토 / 모든 5NF 릴레이션은 4NF 만족 / 역은 성립 안 함                          | **무손실 분해 검증**: 분해된 릴레이션들의 자연 조인이 원본과 동일한지 확인 / 앞서 다룬 **CBO 실행계획** 검증으로 조인 결과 확인                              | **완전 정규형 달성**: 5NF = 정규화의 실질적 완성 / DKNF(도메인-키 정규형)가 이론적 최종이나 실용성 낮음 / 실무 5NF가 사실상 정규화 최종 목표                         |

***

**나. 5NF 분해 과정 도식화**

```
[5NF 분해: SPJ → SP, PJ, SJ]

원본 SPJ:
┌──────┬──────┬──────────┐
│공급자 │부품  │프로젝트   │
├──────┼──────┼──────────┤
│S1    │P1   │J1        │
│S1    │P2   │J1        │
│S2    │P1   │J1        │
│S2    │P2   │J2        │
└──────┴──────┴──────────┘
       ↓ 5NF 분해

SP 릴레이션:      PJ 릴레이션:     SJ 릴레이션:
┌──────┬──────┐  ┌──────┬──────┐  ┌──────┬──────┐
│공급자 │부품  │  │부품  │프로젝│  │공급자 │프로젝│
├──────┼──────┤  ├──────┼──────┤  ├──────┼──────┤
│S1    │P1   │  │P1   │J1    │  │S1    │J1    │
│S1    │P2   │  │P2   │J1    │  │S2    │J1    │
│S2    │P1   │  │P1   │J1    │  │S2    │J2    │
│S2    │P2   │  │P2   │J2    │  └──────┴──────┘
└──────┴──────┘  └──────┴──────┘

검증: SP ⋈ PJ ⋈ SJ = 원본 SPJ ✅ (무손실 분해)
```

#### Ⅳ. 정규화 전체 비교

**가. 1NF\~5NF 단계별 요약**

| 정규형      | 제거 대상          | 조건                    |
| :------- | :------------- | :-------------------- |
| **1NF**  | 반복 그룹·비원자 속성   | 모든 속성 원자값             |
| **2NF**  | 부분 함수 종속성      | 비키 속성이 후보키 전체에 완전 종속  |
| **3NF**  | 이행 함수 종속성      | 비키 속성 간 종속 제거         |
| **BCNF** | 모든 비자명 함수 종속성  | 모든 결정자가 후보키           |
| **4NF**  | 다치 종속성(MVD)    | 모든 MVD가 후보키에 의해 내포    |
| **5NF**  | **조인 종속성(JD)** | **모든 JD가 후보키에 의해 내포** |

***

**나. 정규화 트레이드오프**

```
[정규화 수준별 트레이드오프]

정규화 높음 (5NF)
  ✅ 이상 현상 완전 제거
  ✅ 데이터 무결성 최고
  🚨 조인 증가 → 쿼리 복잡도·성능 저하
  🚨 앞서 다룬 CBO가 복잡 조인 실행계획 필요

정규화 낮음 (반정규화·Denormalization)
  ✅ 조인 감소 → 읽기 성능↑
  ✅ 분석·OLAP 환경 최적
  🚨 데이터 중복·이상 현상 위험
  🚨 쓰기 성능 저하

→ 실무: OLTP는 3NF~BCNF 중심
         OLAP·DW는 의도적 반정규화
         5NF는 데이터 모델링 검증 기준으로 활용
```

***

**(제언)** "5NF는 정규화 이론의 완성이자 데이터 모델링의 궁극적 목표입니다. **실무에서는 OLTP 시스템을 BCNF\~4NF 수준으로 설계하고 5NF를 검증 기준으로 활용하되, 앞서 다룬 CBO 옵티마이저가 다중 조인을 효율적으로 처리할 수 있도록 인덱스·파티셔닝·통계 정보를 함께 설계하며, OLAP·데이터 웨어하우스 환경에서는 조회 성능을 위해 의도적 반정규화로 5NF를 부분 완화하는 것이 쿼리 성능과 데이터 무결성의 균형을 맞추는 실용적 데이터베이스 설계 전략입니다.**"
