# 메모리 시스템 및 계층구조 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 구조도 → 정책별 비교표 → 일관성 유지기법

---

## 1. 캐시 주소매핑 방식

**구조도(필요성)**
```
[CPU] ←빠름→ [캐시(작고 빠름)] ←느림→ [주기억장치(크고 느림)]
캐시는 주기억장치 전체를 담을 수 없어, "어느 캐시라인에 어느 메모리블록을 저장할지" 매핑규칙 필요
```

**정책별 비교표**

| 매핑방식 | 동작원리 | 장단점 |
|---|---|---|
| **직접매핑(Direct Mapping)** | 메모리주소를 캐시라인수로 나눈 나머지(modulo)로 고정 슬롯 결정 | 구현단순·빠름, 단점: 같은 슬롯에 매핑되는 다른 블록끼리 충돌(Thrashing) 잦음 |
| **연관매핑(Fully Associative)** | 어떤 캐시라인에든 자유롭게 저장 가능 | 충돌 없음, 단점: 모든 라인을 동시검색해야해 하드웨어 복잡·비용 큼 |
| **집합연관매핑(Set-Associative)** | 여러 라인을 그룹(Set)으로 묶고, 그룹 내에서는 자유배치(직접+연관의 절충) | 실무 표준(보통 4-way, 8-way), 충돌완화와 구현복잡도의 균형 |

**일관성 유지기법과의 연계**: 매핑방식과 무관하게 멀티코어 환경에서는 각 코어의 캐시 간 데이터일관성(MESI 등)을 별도로 유지해야 함(아래 3번 키워드)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 캐시히트율/캐시미스율 | 매핑방식 선택이 직접 영향을 주는 성능지표 |
| TLB(Translation Lookaside Buffer) | 가상메모리 주소변환을 캐싱하는 특수목적 캐시(동일 매핑원리 적용) |
| 다차원색인구조(R-Tree 등) | "빠른 탐색을 위한 구조화"라는 점에서 캐시매핑과 유사한 설계철학(DB도메인과 연결) |

## 2. 쓰기정책 (Write Through vs Write Back)

**구조도**
```
[Write Through] CPU가 캐시에 쓰면 → 동시에 주기억장치에도 즉시 반영
[Write Back]    CPU가 캐시에 쓰면 → 캐시에만 반영(Dirty Bit 설정) → 해당라인이 교체될 때만 주기억장치에 반영
```

**정책별 비교표**

| 구분 | Write Through | Write Back |
|---|---|---|
| 메모리 반영시점 | 즉시(매번) | 라인교체 시점(지연) |
| 데이터 일관성 | 항상 최신(안전) | Dirty Bit으로 추적 필요 |
| 쓰기성능 | 느림(매번 메모리접근) | 빠름(캐시에서만 처리) |
| 메모리트래픽 | 많음 | 적음(같은 데이터 반복수정 시 한번만 반영) |
| 장애시 위험 | 낮음(메모리가 항상 최신) | 높음(전원차단 시 Dirty 데이터 손실가능) |

**일관성 유지기법**: Write Back 정책에서는 Dirty Bit으로 "이 라인이 메모리보다 최신"임을 추적, 멀티코어 환경에서는 이 Dirty 상태가 MESI프로토콜의 Modified(M) 상태와 직결

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| MESI 프로토콜 | Write Back의 Dirty상태를 멀티코어 환경에서 관리하는 구체적 프로토콜(다음 키워드) |
| 회복기법(REDO/UNDO) | "변경사항을 언제 영구저장소에 반영할지"라는 동일한 트레이드오프가 DB의 회복기법에도 존재(DB도메인과 연결) |
| SSD FTL(플래시변환계층) | 쓰기정책과 유사하게, SSD도 즉시쓰기 vs 지연쓰기(버퍼링) 트레이드오프가 존재 |

## 3. 캐시일관성 (MESI 프로토콜)

**구조도(멀티코어 캐시일관성 문제)**
```
[Core1-캐시] [Core2-캐시] [Core3-캐시]  ← 각자 같은 메모리블록의 사본을 따로 보유 가능
        └──────┬──────┘
            [공유 메모리]
한 코어가 자신의 캐시값을 수정하면, 다른 코어들의 캐시는 "낡은 값"을 모른채 계속 사용 → 일관성 붕괴
```

**MESI 4가지 상태 비교표**

| 상태 | 의미 |
|---|---|
| **M(Modified)** | 이 캐시만 최신값을 보유(수정됨), 메모리는 낡은값, 다른캐시엔 사본없음 |
| **E(Exclusive)** | 이 캐시만 값을 보유하나 메모리와 동일(수정안됨), 다른캐시엔 사본없음 |
| **S(Shared)** | 여러 캐시가 동일한 값을 공유 보유(모두 메모리와 동일) |
| **I(Invalid)** | 이 캐시라인의 값은 무효(다른 코어가 수정해 더이상 못씀) |

**일관성 유지기법(상태전이 예시)**: Core1이 S상태(공유)인 데이터를 쓰기(Write)하면 → Core1은 M상태로 전환, 동시에 버스를 통해 다른 코어들에게 "무효화(Invalidate)" 신호를 보내 다른코어의 동일라인을 I상태로 전환 → 이후 Core2가 그 데이터를 읽으려면 Core1(M상태)으로부터 최신값을 받아와야 함(Cache-to-Cache transfer 또는 메모리 경유)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 버스 스누핑(Bus Snooping) | MESI프로토콜이 다른코어의 상태변화를 감지하는 하드웨어 메커니즘 |
| CXL.cache | MESI와 유사한 캐시일관성 개념을 CPU-가속기 간 인터커넥트로 확장(아래 키워드와 연결) |
| 병행제어(락기반) | "여러주체가 공유자원에 동시접근할 때 일관성을 어떻게 유지하는가"라는 동일문제의식이 DB 병행제어와 본질적으로 유사(DB도메인과 연결) |

## 4. HBM (High Bandwidth Memory)

**구조도**
```
[기존 메모리] CPU/GPU ←(PCB 평면배선)→ DRAM칩들(나란히 배치, 대역폭 제한)

[HBM] GPU/AI가속기 옆에 DRAM칩을 수직으로 여러층 쌓고(3D 스태킹)
      TSV(Through Silicon Via, 실리콘관통전극)로 칩들을 관통연결
      → 매우 짧은 거리+매우 넓은 데이터통로(폭)로 초고속 대역폭 확보
```

**정책별 비교표(기존 GDDR/DDR과 비교)**

| 구분 | DDR/GDDR(기존) | HBM |
|---|---|---|
| 적층방식 | 평면배치 | 3D 수직적층(TSV) |
| 대역폭 | 상대적으로 낮음 | 매우높음(GDDR보다 수배) |
| 전력효율 | 낮음 | 높음(짧은 신호경로) |
| 비용 | 저렴 | 고가(첨단패키징 필요) |
| 용도 | 일반PC·서버 | AI가속기(GPU), HPC |

**일관성 유지기법**: HBM 자체는 일관성 메커니즘을 갖지않고, GPU/CPU와의 데이터 일관성은 상위 인터커넥트(CXL.memory 등)나 GPU자체 캐시일관성 프로토콜이 별도로 담당

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| CXL(.memory) | HBM의 용량한계를 보완하는 메모리확장 인터커넥트(다음 키워드와 직결) |
| TSV(실리콘관통전극) | HBM 3D적층의 핵심 패키징 기술 |
| AI반도체 / NPU | HBM이 필수로 탑재되는 AI가속기 하드웨어(AI도메인과 연결) |

## 5. CXL (.io / .cache / .memory)

**구조도**
```
[CPU] ──CXL링크(PCIe 물리계층 기반)── [CXL디바이스(가속기/메모리확장장치)]
        │
   3개 서브프로토콜이 하나의 링크 위에서 동시 동작
   CXL.io(기본 입출력) + CXL.cache(캐시일관성 공유) + CXL.memory(메모리 직접접근)
```

**정책별 비교표(디바이스 유형별 사용 프로토콜)**

| 디바이스유형 | 사용 프로토콜 | 용도 |
|---|---|---|
| Type1 | .io + .cache | 가속기가 호스트메모리를 캐시처럼 일관성있게 접근 |
| Type2 | .io + .cache + .memory | GPU/FPGA 등 자체메모리+호스트메모리 모두 일관성있게 공유 |
| Type3 | .io + .memory | 메모리풀링 전용 디바이스(캐시일관성 불필요, 순수 용량확장) |

**일관성 유지기법**: CXL.cache가 MESI와 유사한 캐시일관성 프로토콜을 CPU-디바이스 간에 확장 구현 — 디바이스가 호스트메모리의 특정라인을 캐싱하면, 호스트도 그 변경을 인지하도록 양방향 동기화

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 메모리풀링(Memory Pooling) | CXL 3.0의 핵심 신기능, 여러 호스트가 메모리자원을 동적으로 공유 |
| HBM | CXL과 함께 AI인프라의 메모리 대역폭·용량 한계를 보완하는 양대 기술 |
| MESI | CXL.cache가 모델로 삼는 멀티코어 캐시일관성 프로토콜의 원형 |

## 6. 메모리 인터리빙 (Memory Interleaving)

**구조도**
```
[인터리빙 없음] 연속주소가 한 메모리뱅크에 순차저장 → 뱅크1개만 계속 사용(병목)

[인터리빙 적용] 연속주소를 여러 뱅크에 번갈아 분산저장
주소0→뱅크A, 주소1→뱅크B, 주소2→뱅크C, 주소3→뱅크D, 주소4→뱅크A...
→ 연속된 데이터에 접근할 때 여러뱅크를 동시에/번갈아 접근해 병렬처리 효과
```

**정책별 비교표**

| 구분 | 비인터리빙 | 인터리빙 |
|---|---|---|
| 뱅크 활용 | 순차적(1개씩) | 병렬적(여러뱅크 동시) |
| 연속접근 성능 | 느림 | 빠름(병렬화 효과) |
| 적용방식 | - | 저차(Low-order) 인터리빙 vs 고차(High-order) 인터리빙 |

**일관성 유지기법**: 인터리빙 자체는 일관성 이슈를 직접 일으키지 않으나, 멀티코어가 인터리빙된 메모리에 동시접근 시 일반적인 메모리 일관성 모델(MESI 등 캐시단)이 별도로 적용됨

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 메모리뱅크(Bank) | 인터리빙의 기본 단위 |
| 병렬컴퓨팅 / 상호연결망 | 인터리빙이 메모리 차원에서 구현하는 병렬화 사상의 일종(다른 핵심키워드와 연결) |
| RAID(0+1/1+0) | 디스크레벨에서 유사한 "분산저장으로 병렬성능 확보"하는 스트라이핑 기법과 사상적으로 동일(네트워크/저장장치 도메인과 연결) |

## 7. 빅 엔디언 vs 리틀 엔디언

**구조도(0x12345678을 메모리에 저장하는 방식)**
```
[빅 엔디언(Big Endian)] 사람이 읽는 순서와 동일 — 최상위바이트(MSB)부터 낮은주소에 저장
주소:   1000  1001  1002  1003
값:     12    34    56    78

[리틀 엔디언(Little Endian)] 최하위바이트(LSB)부터 낮은주소에 저장
주소:   1000  1001  1002  1003
값:     78    56    34    12
```

**정책별 비교표**

| 구분 | 빅엔디언 | 리틀엔디언 |
|---|---|---|
| 가독성(디버깅) | 사람이 직관적으로 읽기 쉬움(16진수 덤프 그대로) | 직관적이지 않음(역순) |
| 대표 사용처 | 네트워크 프로토콜(TCP/IP는 빅엔디언이 표준="Network Byte Order") | x86/x64 CPU(인텔 계열) |
| 산술연산 효율 | - | 하위바이트부터 저장되어 일부 연산에 효율적(설계상 이유) |

**일관성 유지기법**: 서로 다른 엔디언 시스템 간 데이터교환 시(예: x86서버↔네트워크) **바이트오더 변환(htonl/ntohl 함수 등)**을 거쳐야 데이터가 깨지지 않음

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| TCP/IP 프로토콜 헤더 | 네트워크 전송시 빅엔디언(Network Byte Order)으로 통일하는 표준 규약(네트워크 도메인과 연결) |
| 직렬화(Serialization) | 엔디언 차이를 추상화해 시스템간 데이터교환을 표준화하는 상위기법 |

## 8. DRAM vs SRAM

**구조도(셀 구조 차이)**
```
[DRAM] 캐패시터(축전기) 1개 + 트랜지스터 1개로 셀 구성
       → 전하가 시간이 지나면 누설되어 사라짐 → 주기적 재충전(Refresh) 필수

[SRAM] 플립플롭(논리회로, 보통 6개 트랜지스터)로 셀 구성
       → 전원이 공급되는 동안 상태유지(Refresh 불필요)
```

**정책별 비교표**

| 구분 | DRAM | SRAM |
|---|---|---|
| 구조 | 캐패시터+트랜지스터(단순) | 플립플롭(복잡) |
| 속도 | 느림(SRAM보다) | 매우 빠름 |
| 집적도/용량 | 높음(셀이 작아 대용량 가능) | 낮음(셀이 커 소용량) |
| 전력소모 | Refresh로 지속전력 소모 | Refresh 불필요(대기시 저전력) |
| 비용(비트당) | 저렴 | 고가 |
| 주요용도 | 주기억장치(메인메모리) | 캐시메모리(CPU 내부) |

**일관성 유지기법**: DRAM은 Refresh주기 내에 데이터를 재충전해야 데이터 일관성(데이터유실 방지)이 보장됨(Auto Refresh, Self Refresh, LPASR — 이전 정리한 DDR갱신 키워드와 직결)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| DDR SDRAM 갱신(Refresh) | DRAM의 Refresh 메커니즘 상세(네트워크/저장장치 관련 이전파일과 연결) |
| 캐시메모리(주소매핑/쓰기정책) | SRAM이 실제로 사용되는 대표 응용처(이 문서 1·2번 키워드와 직결) |
| FRAM | DRAM·SRAM과 달리 비휘발성이면서도 빠른 속도를 노리는 차세대 메모리(다음 키워드) |

---

## 9. FRAM (Ferroelectric RAM)

**구조도(동작원리)**
```
[FRAM 셀] 강유전체(Ferroelectric) 물질의 분극방향으로 0/1 저장
   → 전원이 꺼져도 분극상태가 유지됨(비휘발성)
   → 분극방향을 전환하는 데 캐패시터 충전과 달리 누설전류가 거의 없음
```

**정책별 비교표(타 메모리와 비교)**

| 구분 | DRAM | Flash(SSD 등) | FRAM |
|---|---|---|---|
| 휘발성 | 휘발성(전원차단시 소실) | 비휘발성 | **비휘발성** |
| 쓰기속도 | 빠름 | 느림(블록단위 쓰기) | **매우빠름**(DRAM급) |
| 쓰기내구성 | 무제한(휘발성이라 내구성 개념 약함) | 제한적(수천~수만회) | **매우높음**(수조회 이상) |
| 용량/비용 | 대용량·저가 | 대용량·저가 | 소용량·고가(현재기준) |

**일관성 유지기법**: FRAM은 Refresh가 불필요하고 쓰기 시 즉시 비휘발성으로 기록되어, 별도의 일관성유지 메커니즘(Refresh 등) 없이도 데이터 보존이 안정적 — 갑작스런 전원차단에도 데이터손실 위험이 낮음

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| MRAM/PRAM(차세대 비휘발성메모리) | FRAM과 함께 비교되는 또다른 차세대 메모리(STT-MRAM, PCRAM 등) |
| 플래시메모리 FTL | FRAM과 달리 블록단위 쓰기·소거가 필요한 플래시의 한계를 보여주는 대조사례 |
| 스마트미터(AMI) / IoT | FRAM이 실제로 활용되는 응용분야(빈번한 쓰기+저전력+비휘발성이 모두 필요한 환경) |

## 10. ROM 종류 및 기능

**구조도(ROM 진화과정)**
```
[ROM(Mask ROM)] 제조시점에 데이터 영구고정(이후 변경불가)
   → [PROM] 사용자가 1회만 프로그래밍 가능(이후 변경불가)
      → [EPROM] 자외선으로 전체 소거후 재기록 가능(특수장비 필요)
         → [EEPROM] 전기신호로 바이트단위 소거·재기록 가능(장비불필요)
            → [Flash Memory] EEPROM의 발전형, 블록단위로 더 빠르게 소거·재기록(현재 표준)
```

**정책별 비교표**

| 종류 | 재기록 가능여부 | 기능/용도 |
|---|---|---|
| **Mask ROM** | 불가 | 펌웨어 등 절대 변경불필요한 고정데이터 |
| **PROM** | 1회만 가능 | 소량생산·커스텀용도 |
| **EPROM** | 가능(자외선 소거, 느림·불편) | 과거 임베디드 개발용 |
| **EEPROM** | 가능(전기적, 바이트단위) | BIOS 설정값 등 소용량 데이터 |
| **Flash** | 가능(전기적, 블록단위, 빠름) | SSD, USB메모리, 스마트폰 저장소(현재 주류) |

**일관성 유지기법**: ROM 계열은 기본적으로 "쓰기빈도가 낮음"을 전제하므로 일관성 이슈가 크지 않으나, Flash는 빈번한 쓰기로 인한 마모(Wear)를 관리하는 **웨어레벨링(Wear Leveling)**이 일관성·내구성 유지의 핵심기법

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| SSD FTL(플래시변환계층) | Flash의 웨어레벨링·블록관리를 실제로 수행하는 컨트롤러 계층 |
| BIOS/UEFI | EEPROM/Flash에 저장되는 대표적 펌웨어 데이터 |
| FRAM | ROM계열(느린재기록)과 대조적으로 RAM처럼 빠른 재기록이 가능한 비휘발성메모리 |

## 종합 흐름도

```
[CPU-캐시 계층] 캐시주소매핑(직접/연관/집합연관) ──→ 쓰기정책(Write Through/Back)
        │
        ▼
[멀티코어 일관성] MESI 프로토콜(M/E/S/I 상태전이) ──→ CXL.cache(인터커넥트로 확장)
        │
[메모리 확장/고속화] HBM(3D적층, 대역폭) ──→ CXL.memory(메모리풀링, 용량확장)
        │
[메모리 병렬화] 메모리인터리빙(뱅크분산)
        │
[메모리 셀기술 비교] DRAM(휘발성,저가) vs SRAM(휘발성,고속) vs FRAM(비휘발성,고속)
        │
[데이터표현 규약] 빅/리틀엔디언(바이트순서)
        │
[비휘발성 저장계층] ROM 계열(Mask→PROM→EPROM→EEPROM→Flash)
```
