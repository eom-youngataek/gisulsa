# 가상메모리 관리 및 스토리지 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 기법 개념 → 비교 → 단편화 최소화 방안

---

## 1. 페이징 (Paging)

**기법 개념**
```
[논리주소공간] 고정크기 페이지(Page, 보통 4KB)로 균등 분할
[물리주소공간] 동일크기 페이지프레임(Page Frame)으로 분할
   → 페이지테이블이 "논리페이지 → 물리프레임" 매핑정보 관리
   → CPU가 논리주소 접근 시, MMU가 페이지테이블을 참조해 물리주소로 변환
```

**비교(세그멘테이션 대비 특징)**: 모든 페이지가 동일크기라 관리가 단순하고 외부단편화가 발생하지 않음(아래 표에서 상세비교)

**단편화 최소화 방안**: 페이징은 외부단편화는 없지만, 페이지크기보다 작은 데이터를 할당할 때 페이지 내부에 남는 공간(**내부단편화**)이 발생 → 페이지크기를 작게 설정하면 내부단편화는 줄지만 페이지테이블 크기(관리오버헤드)가 증가하는 트레이드오프 존재

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| MMU(Memory Management Unit) / TLB | 페이지테이블 변환을 실제로 수행하는 하드웨어와 그 캐시 |
| 페이지교체알고리즘(LRU, FIFO 등) | 물리메모리가 가득찼을 때 어느 페이지를 디스크로 내보낼지 결정하는 기법 |
| 스레싱(Thrashing) | 페이지교체가 과도하게 빈번해져 시스템성능이 급격히 저하되는 현상 |
| 그림자페이징(Shadow Paging) | "페이지테이블"이라는 동일 용어를 DB회복기법에서 다른 목적으로 활용하는 사례(DB도메인과 연결) |

## 2. 세그멘테이션 (Segmentation)

**기법 개념**
```
[논리주소공간] 프로그램의 논리적 의미단위(함수, 배열, 스택 등)로 가변크기 분할 — 각 세그먼트는 크기가 다름
[물리주소공간] 세그먼트테이블이 "세그먼트번호+오프셋 → 물리시작주소" 매핑정보 관리
```

**비교(페이징과의 핵심 차이)**

| 구분 | 페이징 | 세그멘테이션 |
|---|---|---|
| 분할단위 | 고정크기(균등) | 가변크기(논리적의미단위) |
| 분할기준 | 물리적 크기기준 | 논리적 기능기준(프로그램모듈 등) |
| 단편화 유형 | 내부단편화 발생 | **외부단편화** 발생 |
| 보호/공유 | 페이지단위 보호(의미단위가 아니라 다소 거침) | 세그먼트(의미)단위 보호·공유가 용이(더 직관적) |
| 주소변환 | 논리페이지번호+오프셋 | 세그먼트번호+오프셋 |

**단편화 최소화 방안**: 세그먼트는 가변크기라 할당·해제가 반복되면 메모리에 사용가능한 작은 빈공간들이 흩어지는 **외부단편화**가 발생 → 압축(Compaction, 사용중인 세그먼트들을 한쪽으로 모아 빈공간을 통합)으로 해소, 단 압축은 시스템 일시정지(오버헤드) 수반

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 페이지드 세그멘테이션(Paged Segmentation) | 세그먼트를 다시 페이지로 나눠 두 기법의 장점을 결합한 혼합방식 |
| 동적메모리할당(malloc 등) | 세그멘테이션과 동일하게 가변크기 할당으로 외부단편화가 발생하는 응용프로그램레벨 사례 |
| 메모리 인터리빙 | 메모리를 분할관리한다는 점에서 유사하나 목적(병렬성 vs 논리적분리)이 다름 |

## 3. 단편화 유형(내부/외부) 및 최소화방안

**기법 개념(2대 단편화 유형)**

| 유형 | 정의 | 발생원인 |
|---|---|---|
| **내부단편화(Internal Fragmentation)** | 할당된 블록 내부에서, 실제 사용되지 않고 낭비되는 공간 | 고정크기 할당 시, 필요한 양보다 더 큰 블록을 할당받아 남는 부분 발생(페이징) |
| **외부단편화(External Fragmentation)** | 할당가능한 빈 공간들이 작은 조각으로 여러곳에 흩어져, 합치면 충분하지만 연속된 큰 블록을 못만드는 상태 | 가변크기 할당·해제가 반복되며 빈공간이 잘게 쪼개짐(세그멘테이션, 동적할당) |

**비교(시각적 예시)**
```
[내부단편화] 페이지크기4KB인데 실제데이터 3KB 사용 → 1KB 낭비(페이지내부에 갇힘)

[외부단편화] 메모리: [사용중2KB][빈1KB][사용중3KB][빈1KB][사용중2KB][빈1KB]
            → 빈공간 합계3KB 있지만, 3KB 연속요청은 할당불가(흩어져있어서)
```

**단편화 최소화 방안**
- 내부단편화 대응: 페이지크기를 작게(세분화), 또는 가변크기 할당(슬랩할당자 등)과 결합
- 외부단편화 대응: **압축(Compaction)**, **메모리풀(Memory Pool)/슬랩할당(Slab Allocation)**으로 동일크기 객체를 미리 묶어 관리, **버디시스템(Buddy System)**으로 2의거듭제곱 단위 분할·병합

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 버디시스템(Buddy System) | 외부단편화를 줄이면서도 합병이 쉬운 동적할당 알고리즘 |
| 가비지컬렉션(GC) | 응용프로그램레벨에서 단편화·미사용메모리를 정리하는 자동화기법(JVM GC 등) |
| 디스크단편화 / SSD웨어레벨링 | 동일한 단편화 개념이 보조기억장치 레벨에서도 발생(저장장치 도메인과 연결) |

## 4. DRAM 갱신 (Auto Refresh / Self Refresh / LPASR)

**기법 개념**
```
[갱신 필요이유] DRAM 셀의 캐패시터는 시간이 지나면 전하가 누설되어 데이터 소실
   → 주기적으로 셀을 재충전(Refresh)해야 데이터 유지(보통 64ms 이내 전체 재충전)
```

**비교(3가지 갱신방식)**

| 방식 | 동작주체 | 사용시점 |
|---|---|---|
| **Auto Refresh** | 메모리컨트롤러가 일정주기마다 자동으로 Refresh 명령 발행 | 시스템 정상동작(전원 켜진 상태) |
| **Self Refresh** | DRAM이 외부컨트롤러 개입없이 **자체적으로** 내부타이머로 Refresh 수행 | 저전력모드/슬립상태(컨트롤러까지 꺼도 데이터유지) |
| **LPASR(Low Power Auto Self Refresh)** | Self Refresh 중에서도 **온도에 따라 Refresh 주기를 동적조절**(저온일수록 누설이 적어 주기를 늘려 전력추가절감) | 모바일기기 등 전력민감 환경 |

**단편화 최소화 방안(관점 적용 — Refresh의 성능오버헤드 최소화)**: Refresh 중에는 해당 메모리에 접근 불가(Refresh 오버헤드) → 뱅크별로 시간차를 두고 순차 Refresh(All-bank Refresh가 아닌 Per-bank Refresh)하여 전체 시스템 정지시간을 최소화

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| DRAM vs SRAM | Refresh가 필요없는 SRAM과의 근본적 구조차이(메모리시스템 이전파일과 연결) |
| HBM | HBM도 DRAM 기반이라 동일한 Refresh 메커니즘이 적용되며, 고집적化로 Refresh 오버헤드 관리가 더 중요해짐 |
| FRAM | Refresh가 전혀 필요없는 비휘발성 대안 메모리(이전파일과 연결) |

## 5. 블록/파일/오브젝트 스토리지 접근방식

**기법 개념(3대 스토리지 접근방식)**

| 방식 | 접근단위 | 동작방식 |
|---|---|---|
| **블록스토리지(Block Storage)** | 고정크기 블록(섹터) | OS가 직접 블록단위로 읽기/쓰기(파일시스템을 OS가 직접 구성), 가장 빠름 |
| **파일스토리지(File Storage)** | 파일/디렉토리(계층구조) | NAS처럼 네트워크로 공유, 파일시스템이 이미 추상화되어 제공됨(파일명으로 접근) |
| **오브젝트스토리지(Object Storage)** | 객체(데이터+메타데이터+고유ID) | 평면구조(디렉토리 없음), REST API(HTTP)로 접근, 무한확장에 적합 |

**비교(특징 비교표)**

| 구분 | 블록 | 파일 | 오브젝트 |
|---|---|---|---|
| 성능 | 매우빠름(저지연) | 중간 | 상대적으로 느림(API오버헤드) |
| 확장성 | 제한적 | 중간 | 매우높음(페타바이트급) |
| 메타데이터 | 거의없음 | 제한적(파일속성) | 풍부(커스텀메타데이터 자유추가) |
| 적합용도 | DB, 가상머신 디스크 | 공유문서, 홈디렉토리 | 백업, 미디어파일, 빅데이터 저장 |

**단편화 최소화 방안(관점적용)**: 블록스토리지는 파일시스템 차원의 단편화(디스크조각화) 관리가 필요(디프래그), 오브젝트스토리지는 객체단위 저장으로 전통적 단편화 개념이 거의 없고 대신 객체분산배치(샤딩)로 균등성 관리

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| NAS / SAN | 파일스토리지(NAS)와 블록스토리지(SAN)의 실제 인프라 구현사례 |
| S3(Simple Storage Service) | 오브젝트스토리지의 대표적 실제 서비스 |
| 데이터레이크 | 오브젝트스토리지가 데이터레이크 구축의 핵심 기반 인프라로 활용(AI데이터운영 도메인과 연결) |

## 6. 스토리지 가상화 유형

**기법 개념**
> 물리적으로 분산된 여러 저장장치를 논리적으로 통합해, 사용자/애플리케이션에게는 하나의 단일 저장공간처럼 보이게 만드는 기술

**비교(가상화 위치별 유형)**

| 유형 | 구현위치 | 특징 |
|---|---|---|
| **호스트기반(Host-based)** | 서버(OS) 레벨 | 소프트웨어로 구현, 비용낮음, 서버자원 일부 소모 |
| **스토리지기반(Storage-based)** | 스토리지장치 자체(컨트롤러) | 스토리지어레이 내에서 가상화, 서버부담없음 |
| **네트워크기반(Network-based)** | SAN 스위치/어플라이언스 | 이종 스토리지를 네트워크단에서 통합, 가장 유연하나 구성복잡 |

**단편화 최소화 방안(관점적용)**: 가상화계층이 여러 물리스토리지의 빈공간을 통합관리(씬프로비저닝, Thin Provisioning)해, 개별 물리장치 단위로 발생하던 단편화·여유공간 낭비를 풀(Pool) 차원에서 효율화

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 씬프로비저닝(Thin Provisioning) | 실제 사용량만큼만 공간을 동적할당해 낭비를 줄이는 핵심 가상화 기법 |
| 스토리지 가상화 vs 서버 가상화(VM/컨테이너) | 가상화의 적용대상(저장장치 vs 컴퓨팅)이 다른 인접개념(SW방법론 도메인의 컨테이너와 비교) |
| RAID | 스토리지가상화 이전단계의 물리적 다중화·성능향상 기법(네트워크 도메인과 연결) |
| 멀티클라우드 | 여러 클라우드 스토리지를 가상화로 통합관리하는 최신 응용사례 |

## 종합 흐름도

```
[가상메모리 분할방식] 페이징(고정크기, 내부단편화) vs 세그멘테이션(가변크기, 외부단편화)
        │
        ▼
[단편화 문제] 내부단편화 ── 외부단편화
        │  (페이지크기조정)      (압축/버디시스템/슬랩할당)
        │
[메모리 보존 메커니즘] DRAM갱신(Auto/Self/LPASR) — 별도 축의 메모리 안정성 이슈
        │
[저장장치 계층 확장]
  블록/파일/오브젝트 스토리지(접근방식) ──→ 스토리지가상화(여러 물리장치를 논리적 통합)
```
