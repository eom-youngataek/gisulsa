# 차세대 컴퓨팅 아키텍처 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 개념 → 기존 아키텍처 비교 → 활용분야

---

## 1. 양자컴퓨터 (큐비트/양자우월성/결잃음/구현방법)

**개념**
- **큐비트(Qubit)**: 일반 비트는 0 또는 1 중 하나만 갖지만, 큐비트는 **중첩(Superposition)**으로 0과 1을 동시에 일정확률로 가질 수 있음(측정시점에 하나로 확정)
- **양자우월성(Quantum Supremacy)**: 양자컴퓨터가 특정 문제에서 기존 슈퍼컴퓨터로는 현실적시간 내 불가능한 계산을 수행해낸 상태
- **양자결잃음(Quantum Decoherence)**: 외부환경(진동·열·전자기파)의 간섭으로 큐비트의 양자상태(중첩)가 깨져 일반비트처럼 되어버리는 현상(양자컴퓨터의 최대 난제)

**기존 아키텍처 비교(고전컴퓨터 vs 양자컴퓨터)**

| 구분 | 고전컴퓨터(비트) | 양자컴퓨터(큐비트) |
|---|---|---|
| 상태표현 | 0 또는 1(확정적) | 0과1의 중첩(확률적) |
| 정보량(n개 단위) | n비트로 2^n개 상태중 1개만 표현 | n큐비트로 2^n개 상태를 **동시에** 표현가능(병렬성) |
| 연산방식 | 논리게이트(AND/OR 등) | 양자게이트(중첩·얽힘을 조작) |
| 안정성 | 매우안정(노이즈영향적음) | 매우불안정(결잃음으로 단시간만 유지) |

**구현방법(대표 방식)**: 초전도큐비트(극저온 초전도회로, IBM/Google 채택), 이온트랩(전자기장으로 가둔 원자이온), 광자기반(빛의 양자상태 활용), 위상큐비트(이론적으로 결잃음에 강함, 연구단계)

**활용분야**: 신약개발(분자구조 시뮬레이션), 암호해독(쇼어알고리즘으로 RSA 위협 — PQC 등장배경), 금융포트폴리오 최적화, 물류경로 최적화

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| PQC / QKD | 양자컴퓨터의 암호해독 위협에 대응하는 차세대 암호기술(보안 도메인과 연결) |
| 양자머신러닝(QML) | 양자컴퓨터의 병렬성을 머신러닝에 응용하는 차세대 AI기술(AI도메인과 연결) |
| 큐비트오류정정 | 결잃음 문제를 완화하기 위한 핵심 연구분야(여러 물리적큐비트로 1개의 논리큐비트를 안정화) |

## 2. 뉴로모픽 반도체 (SNN vs 폰노이만)

**개념**: 인간 뇌의 신경세포(뉴런)와 시냅스 구조·동작방식을 모방해 설계한 반도체 — **SNN(Spiking Neural Network)**을 하드웨어로 직접 구현해 이벤트기반(필요시에만 반응)으로 초저전력 연산

**기존 아키텍처 비교(폰노이만 구조와 비교)**

| 구분 | 폰노이만 구조(기존CPU/GPU) | 뉴로모픽(SNN기반) |
|---|---|---|
| 연산-저장 분리 | **분리**(CPU와 메모리가 별도, 데이터를 계속 이동시켜야함 = 폰노이만 병목) | **통합**(연산과 저장이 한 유닛에서 함께, 뉴런처럼 동작) |
| 동작방식 | 클럭에 맞춰 항상 동작(동기식) | 이벤트(스파이크) 발생시에만 반응(비동기식, 이벤트드리븐) |
| 전력효율 | 상대적으로 낮음(항상 전력소모) | **매우높음**(반응이 없으면 전력소모도 없음) |
| 프로그래밍방식 | 명령어 순차실행(폰노이만 모델) | 뉴런·시냅스 가중치 학습(생물학적 모델) |

**활용분야**: 엣지디바이스의 초저전력 AI추론(웨어러블, 센서), 실시간 패턴인식(이미지·음성), 향후 AIoT 디바이스의 핵심 반도체로 부상

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| SNN(Spiking Neural Network) | 뉴로모픽반도체가 실제로 구현하는 신경망 모델(딥러닝 도메인과 연결) |
| AIoT 보안취약점 | 뉴로모픽 칩이 탑재되는 엣지AI 디바이스의 보안 고려사항(보안 도메인과 연결) |
| CXL / HBM | 뉴로모픽이 "연산-저장 통합"으로 해결하려는 폰노이만 병목문제를, 기존구조에서는 CXL.memory·HBM으로 완화시도(메모리시스템 도메인과 연결) |

## 3. 앰비언트 컴퓨팅 (Ambient Computing)

**개념**: 컴퓨팅이 특정 디바이스(스마트폰·PC)에 국한되지 않고, 사용자 주변환경 전체(조명·스피커·센서 등)에 **자연스럽게 녹아들어 인간의 개입(명시적 조작) 없이도** 상황을 인식해 스스로 동작하는 컴퓨팅 패러다임

**기존 아키텍처 비교(IoT와 비교)**

| 구분 | 일반 IoT | 앰비언트 컴퓨팅 |
|---|---|---|
| 사용자 개입 | 앱/리모컨으로 직접 명령(능동적조작) | 사용자가 의식하지 않아도 환경이 자율판단·반응(무의식적상호작용) |
| 지능수준 | 단순 센싱·제어(규칙기반) | 맥락이해+AI판단(상황적응형) |
| 디바이스경계 | 개별기기단위로 분리인식 | 여러기기가 **하나의 통합환경**처럼 동작(경계가 흐려짐) |

**활용분야**: 스마트홈(사용자가 귀가하면 자동으로 조명·온도·음악이 선호패턴대로 조정), 헬스케어(평소생활패턴 모니터링으로 이상징후 자동감지), 차세대 사무환경(회의실 입장만으로 장비자동세팅)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| IoT 3대핵심기술 / AIoT | 앰비언트컴퓨팅의 기술적 토대(네트워크 도메인과 연결) |
| 컴퓨팅 컨티뉴엄 | 클라우드-엣지-디바이스가 매끄럽게 연결된다는 점에서 앰비언트컴퓨팅의 인프라적 기반(아래 키워드와 연결) |
| 상황인지컴퓨팅(Context-Aware Computing) | 앰비언트컴퓨팅의 핵심 이론적 토대가 되는 선행개념 |

## 4. 병렬컴퓨팅 (상호연결망/토러스)

**개념**: 여러 프로세서가 동시에 작업을 나누어 처리해 전체 처리속도를 높이는 컴퓨팅 방식 — 프로세서들을 어떻게 연결하는지가 **상호연결망(Interconnection Network)**의 핵심 설계과제

**기존 아키텍처 비교(상호연결망 구조 비교)**

| 구조 | 특징 |
|---|---|
| **버스(Bus)형** | 모든 프로세서가 하나의 공유선로 사용(단순하나 확장시 경쟁심화) |
| **크로스바(Crossbar)** | 모든 프로세서쌍을 직접 연결가능(빠르나 연결수가 N²로 증가, 비용급증) |
| **메쉬(Mesh)형** | 인접 프로세서끼리만 격자형태로 연결 |
| **토러스(Torus)형** | 메쉬구조의 **양끝을 서로 연결**(원환구조)해 가장자리 노드도 양쪽이웃을 가지게 함 |

**토러스 구조 상세**: 메쉬구조는 가장자리 프로세서가 적은수의 이웃만 가져 통신경로가 불균등(가장자리가 불리)하나, 토러스는 끝과 끝을 연결해 **모든 노드가 동일한수의 이웃**을 가지게 됨(균등성·확장성 향상)

**활용분야**: 슈퍼컴퓨터·대규모 HPC클러스터의 노드간 연결구조, AI학습용 GPU클러스터(다중GPU 효율적 데이터교환)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 멀티GPU 기술 | 토러스 등 상호연결망으로 다중GPU를 연결해 대규모 AI모델학습을 가속(AI도메인과 연결) |
| 메모리인터리빙 | 메모리레벨의 병렬화기법으로, 병렬컴퓨팅(프로세서레벨)과 동일한 사상을 공유(메모리시스템 도메인과 연결) |
| 폴락의 법칙 / 암달의 법칙 | 병렬컴퓨팅 확장의 이론적 한계를 설명하는 법칙들(이전파일과 연결) |

## 5. 인터미턴트 컴퓨팅 (Intermittent Computing)

**개념**: 배터리없이 **에너지하베스팅(태양광·진동·RF신호 등에서 미세전력 수집)**으로만 동작하는 초저전력 디바이스를 위한 컴퓨팅 패러다임 — 전력이 불규칙하게 공급되고 끊기는(Intermittent) 환경에서도 작업을 안정적으로 지속

**기존 아키텍처 비교(상시전력 컴퓨팅과 비교)**

| 구분 | 일반 컴퓨팅(상시전력) | 인터미턴트 컴퓨팅 |
|---|---|---|
| 전력공급 | 안정적·지속적(배터리/전원) | 불규칙·간헐적(에너지하베스팅) |
| 작업중단 대응 | 거의없음(전력안정) | **전력차단시점에 작업상태를 비휘발성메모리에 저장**, 전력복구시 이어서 재개(체크포인팅) |
| 메모리설계 | DRAM(휘발성) 중심 | **FRAM/MRAM 등 비휘발성메모리** 적극활용(전력차단에도 데이터유지) |

**활용분야**: 배터리교체가 불가능한 초소형 IoT센서(다리·건물 매립형 센서), 웨어러블 헬스패치, 우주/극한환경 센서

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| FRAM(Ferroelectric RAM) | 인터미턴트컴퓨팅이 전력차단 대응을 위해 핵심적으로 활용하는 비휘발성메모리(메모리시스템 도메인과 연결) |
| 체크포인팅(Checkpointing) | DB의 체크포인트와 유사하게, 작업상태를 주기적으로 저장해 중단·재개를 가능케하는 기법 |
| 에너지하베스팅(Energy Harvesting) | 인터미턴트컴퓨팅의 전력공급 원천기술 |

## 6. 서버리스 컴퓨팅 (Serverless Computing)

**개념**: 개발자가 서버를 직접 프로비저닝·관리하지 않고, 코드(함수)만 작성해 업로드하면 클라우드사업자가 **요청이 들어올 때만** 자동으로 실행환경을 할당해 실행하는 컴퓨팅모델(FaaS, Function as a Service가 대표형태)

**기존 아키텍처 비교(IaaS/PaaS와 비교)**

| 구분 | IaaS | PaaS | 서버리스(FaaS) |
|---|---|---|---|
| 관리범위 | 인프라(VM)는 사용자관리 | 플랫폼은 제공, 앱배포는 사용자 | **코드(함수)만 작성**, 나머지 전부 자동관리 |
| 과금방식 | 서버가동시간 기준 | 서버가동시간 기준 | **실제 실행시간(요청처리시간)만** 과금(유휴비용 없음) |
| 확장성 | 수동/자동스케일링 설정필요 | 일부자동 | **완전자동**(요청량에 따라 즉시 확장/축소, 0까지 축소가능) |
| 한계 | 관리부담 큼 | 중간 | **콜드스타트**(오랜만의 요청시 초기구동지연), 장시간실행 부적합 |

**활용분야**: 이벤트기반 처리(이미지업로드시 자동썸네일생성), API백엔드(트래픽이 불규칙한 서비스), 배치작업(정기적 데이터처리)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 컨테이너 / 쿠버네티스 | 서버리스 플랫폼 내부에서 함수실행환경을 구현하는 기반기술(SW아키텍처 도메인과 연결) |
| 오토스케일링 | 서버리스의 자동확장 개념이 일반화된 클라우드 인프라 운영기법 |
| MSA | 서버리스는 MSA를 더욱 세분화한 "함수단위" 아키텍처로 비유 가능(SW아키텍처 도메인과 연결) |

## 7. 컴퓨팅 컨티뉴엄 (Computing Continuum)

**개념**: 클라우드-엣지-디바이스(사물)를 **단절된 별개 계층이 아니라 하나의 연속된(Continuum) 컴퓨팅 자원**으로 보고, 워크로드를 상황에 맞게 최적위치(클라우드든 엣지든 디바이스든)에서 동적으로 실행하는 통합 패러다임

**기존 아키텍처 비교(전통적 클라우드-엣지 분리와 비교)**

| 구분 | 전통적 분리(클라우드 vs 엣지) | 컴퓨팅 컨티뉴엄 |
|---|---|---|
| 자원관점 | 클라우드/엣지/디바이스를 별도시스템으로 설계·관리 | **하나의 통합자원풀**로 관리, 경계가 유연 |
| 워크로드배치 | 사전에 고정배치(이건 클라우드, 저건 엣지) | **동적·자동배치**(지연요구·자원상황에 맞춰 실시간 최적위치 결정) |
| 관리복잡도 | 계층별 별도관리 | 통합 오케스트레이션 필요(복잡도는 높으나 효율 극대화) |

**활용분야**: 자율주행(상황에 따라 차량내 엣지에서 즉시처리 vs 클라우드로 전송해 정밀분석을 동적선택), 스마트시티(수많은 센서-엣지-클라우드 자원을 통합관리), 산업IoT

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 엣지컴퓨팅 / 모바일엣지컴퓨팅(MEC) | 컴퓨팅컨티뉴엄을 구성하는 핵심 중간계층(네트워크 도메인과 연결) |
| 앰비언트 컴퓨팅 | 컴퓨팅컨티뉴엄이라는 인프라적 기반 위에서 구현되는 사용자경험 패러다임(위 3번 키워드와 연결) |
| 디지털트윈 | 컨티뉴엄 전반의 실시간 데이터를 가상모델로 동기화하는 응용사례 |

## 8. 메모리반도체 vs 비메모리반도체 (시스템반도체)

**개념**: 반도체를 기능에 따라 **데이터를 저장하는 메모리반도체(DRAM/NAND 등)**와 **데이터를 연산·처리하는 비메모리반도체(시스템반도체, CPU/GPU/AP 등)**로 구분

**기존 아키텍처 비교**

| 구분 | 메모리반도체 | 비메모리반도체(시스템반도체) |
|---|---|---|
| 기능 | 데이터 저장(휘발성DRAM/비휘발성NAND) | 데이터 연산·처리(CPU/GPU/AP/ASIC 등) |
| 제품종류 | 소수의 표준화된 종류(DRAM,NAND 위주) | **수천종 다품종**(용도별 맞춤설계 — 자동차용,모바일용,AI용 등) |
| 생산방식 | 대량생산(소품종대량) | 다품종소량생산(설계·디자인 역량이 핵심경쟁력) |
| 한국 경쟁력 | 세계1위(삼성·SK하이닉스) | **상대적으로 취약**(팹리스·파운드리 생태계 미성숙) |
| 시장구조 | 가격변동성 큼(사이클산업) | 안정적(설계기술·고객관계기반 진입장벽) |

**반도체 산업의 가치사슬(Value Chain)**: 설계(팹리스, Fabless) → 제조(파운드리, Foundry — 위탁생산전문) → 패키징/테스트(후공정) — 메모리는 종합반도체기업(IDM)이 설계~제조 수직통합, 비메모리는 팹리스(설계)와 파운드리(생산)가 분업화된 구조가 일반적

**비메모리 성장을 위한 비전/전략**: 팹리스 기업육성(설계전문인력양성), 파운드리 투자확대(TSMC와 경쟁), AI반도체 등 신성장분야 선제투자(NPU/온디바이스AI칩)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 팹리스(Fabless) / 파운드리(Foundry) | 비메모리반도체 산업의 핵심 분업구조(설계전문 vs 생산전문) |
| HBM | 메모리반도체이지만 AI(비메모리,GPU)와 결합되어 가치가 급증한 사례(메모리시스템 도메인과 연결) |
| NPU / AI반도체 국산화 | 한국이 비메모리경쟁력 강화를 위해 전략적으로 육성하는 분야 |
