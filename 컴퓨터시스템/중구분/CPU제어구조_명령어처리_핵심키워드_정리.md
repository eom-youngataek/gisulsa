# CPU 및 제어구조 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 방식 분류 → 동작원리 → 비교표

---

## 1. 인터럽트 3방식 (Polling / Daisy-Chain / Vector)

**방식 분류**: CPU가 여러 I/O장치 중 "누가 인터럽트를 요청했는지" 식별하고 처리하는 3가지 방법

**동작원리**
```
[Polling 방식] CPU가 모든 장치를 순서대로 직접 하나씩 확인(Status레지스터 검사)
   장치1확인→요청없음→장치2확인→요청있음!→처리
   (소프트웨어적으로 순회, 별도 하드웨어 불필요하나 CPU시간 낭비)

[Daisy-Chain 방식] 모든 장치를 직렬(사슬)로 연결, 인터럽트신호가 장치를 거쳐가며 전파
   CPU←[장치1]←[장치2]←[장치3]  (가장 CPU에 가까운 장치가 우선권)
   (하드웨어적 우선순위 자동결정, 단 한 장치고장시 뒤쪽 전체장애 가능)

[Vector 방식] 장치마다 고유 인터럽트벡터(처리루틴 주소)를 가지고 있어,
   인터럽트 발생시 장치가 직접 자신의 벡터번호를 CPU에 전달 → CPU가 즉시 해당 처리루틴으로 분기
   (가장 빠름, 별도 식별과정 불필요)
```

**비교표**

| 구분 | Polling | Daisy-Chain | Vector |
|---|---|---|---|
| 식별방식 | CPU가 순회확인(SW) | 하드웨어 사슬전파 | 장치가 직접 벡터제공 |
| 속도 | 느림 | 중간 | 빠름 |
| 하드웨어비용 | 낮음 | 중간 | 높음 |
| 우선순위 | 프로그램순서로 결정 | 물리적연결순서로 자동결정 | 벡터테이블설계로 결정 |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 인터럽트벡터테이블(IVT) | Vector방식에서 각 인터럽트번호와 처리루틴주소를 매핑하는 자료구조 |
| DMA(Direct Memory Access) | 인터럽트와 함께 I/O 효율화의 양대 메커니즘(인터럽트구동 I/O vs DMA의 비교출제) |
| 시스템콜 | 인터럽트메커니즘을 소프트웨어가 의도적으로 활용하는 대표사례(아래에서 상세) |

## 2. Micro-Programmed vs Hard-Wired (제어장치 구현방식)

**방식 분류**: CPU의 제어장치(Control Unit)가 명령어를 해석해 제어신호를 생성하는 2가지 구현방법

**동작원리**
```
[Hard-Wired(고정배선)] 논리게이트·플립플롭의 물리적 배선조합으로 제어신호를 직접 생성
   명령어OP코드 → [디코더+조합논리회로] → 제어신호(직접 하드웨어로 결정됨, 매우 빠름)

[Micro-Programmed(마이크로프로그램)] 각 명령어를 실행하는 절차를 "마이크로명령어"들의 
   시퀀스(마이크로프로그램)로 미리 작성해 제어메모리(ROM/RAM)에 저장
   명령어OP코드 → [제어메모리에서 해당 마이크로프로그램 순차 읪어 실행] → 제어신호 생성
```

**비교표**

| 구분 | Hard-Wired | Micro-Programmed |
|---|---|---|
| 구현방식 | 물리적 배선(조합논리회로) | 제어메모리에 저장된 마이크로코드 |
| 속도 | 빠름(배선이 직접동작) | 느림(메모리 읽기단계 추가) |
| 유연성/수정용이성 | 낮음(설계변경시 회로재설계) | **높음**(마이크로코드만 수정하면 명령어집합 변경가능) |
| 복잡한 명령어집합 지원 | 어려움 | 용이(CISC에 적합) |
| 대표적용 | RISC(단순명령어, 고속처리) | CISC(복잡다양한 명령어, x86 계열) |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| RISC vs CISC | 제어장치 구현방식 선택과 직결되는 명령어집합 철학(RISC-V와 직접 연결, 아래에서 상세) |
| 마이크로코드 패치(Microcode Update) | Micro-Programmed 방식의 유연성을 실제활용한 사례(CPU출시후 버그를 펌웨어업데이트로 수정) |
| ROM/EEPROM | 마이크로프로그램이 실제로 저장되는 메모리유형(메모리시스템 도메인과 연결) |

## 3. 버스 중재 (Bus Arbitration)

**방식 분류**: 여러 장치가 하나의 공유버스를 사용하려 할 때, **누구에게 버스사용권을 줄지** 결정하는 방식

**동작원리(주요 방식)**
```
[중앙집중형 - 데이지체인] 버스승인신호(Grant)가 장치들을 순서대로 거쳐가며 전파
   (Daisy-chain 인터럽트와 동일원리를 버스점유에 적용)

[중앙집중형 - 폴링/카운터] 컨트롤러가 장치ID를 순차증가시키며 "네차례인가?" 확인

[분산형 - 자가선택(Self-Selection)] 장치들이 각자 우선순위코드를 버스에 동시출력,
   가장높은 우선순위코드를 가진 장치가 스스로 버스를 점유(중앙컨트롤러 불필요)

[분산형 - 충돌감지(Collision Detection)] 여러장치가 동시전송시도시 충돌을 감지하고 재시도
   (이더넷의 CSMA/CD와 동일원리)
```

**비교표**

| 구분 | 중앙집중형 | 분산형 |
|---|---|---|
| 제어주체 | 중앙 버스컨트롤러 | 장치들이 자율조정 |
| 단일장애점 | 있음(컨트롤러고장시 전체마비) | 없음 |
| 구현복잡도 | 단순 | 복잡(장치마다 조정로직 필요) |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| CSMA/CD/CA | 버스중재의 충돌감지방식과 동일한 원리를 네트워크매체접근에 적용(네트워크 도메인과 연결) |
| 시스템버스 구성요소 | 버스중재가 적용되는 상위 하드웨어 구조(주소버스/데이터버스/제어버스) |
| PCIe / CXL | 현대 시스템에서 버스중재 개념이 확장된 고속 직렬인터커넥트(메모리시스템 도메인과 연결) |

## 4. CPU 레지스터 (종류)

**방식 분류(기능별 레지스터 유형)**

| 레지스터 | 역할 |
|---|---|
| **PC(Program Counter)** | 다음에 실행할 명령어의 주소 보관 |
| **IR(Instruction Register)** | 현재 인출(Fetch)된 명령어 자체를 보관 |
| **MAR(Memory Address Register)** | 메모리접근시 사용할 주소 보관 |
| **MBR(Memory Buffer Register)** | 메모리에서 읽거나 쓸 데이터 보관 |
| **AC(Accumulator)/범용레지스터** | 연산결과 등 임시데이터 저장 |
| **상태레지스터(Status/Flag Register)** | 연산결과의 상태(Carry, Zero, Overflow 등 플래그) 보관 |
| **SP(Stack Pointer)** | 스택의 최상단 주소 보관(함수호출·인터럽트처리시 활용) |

**동작원리(명령어 인출-실행 사이클에서의 역할)**
```
①PC가 가리키는 주소 → MAR에 복사 → 메모리접근
②메모리에서 읽은 명령어 → MBR경유 → IR에 저장
③PC값 자동증가(다음명령어 준비) → IR의 명령어 해석·실행 → AC 등에 결과저장
```

**비교표(범용레지스터 vs 특수목적레지스터)**

| 구분 | 범용레지스터 | 특수목적레지스터(PC/IR/SP등) |
|---|---|---|
| 용도 | 프로그래머가 자유롭게 데이터저장에 활용 | 정해진 특정기능만 수행 |
| 개수 | CPU설계에 따라 다수(RISC는 보통 더많음) | 고정(아키텍처마다 정의) |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 조건 플래그(Status Register) | 상태레지스터 내부의 세부 비트들(Carry/Zero/Sign/Overflow 등) |
| ARM 동작모드 | 레지스터셋이 동작모드별로 다르게 구성되는 사례(다음 키워드) |
| 인터럽트처리 | 인터럽트발생시 PC·상태레지스터를 스택에 저장(Context Save)하는 과정과 직결 |

## 5. ARM 동작모드

**방식 분류(권한레벨별 동작모드)**

| 모드 | 권한레벨 | 용도 |
|---|---|---|
| **User Mode** | 비권한(낮음) | 일반 애플리케이션 실행 |
| **System Mode** | 권한(높음) | OS커널 작업(User모드와 레지스터 공유하나 권한만 높음) |
| **Supervisor(SVC) Mode** | 권한 | 시스템콜(SVC명령어) 발생시 진입 |
| **IRQ/FIQ Mode** | 권한 | 일반인터럽트(IRQ) / 고속인터럽트(FIQ, 전용레지스터 보유해 더빠른응답) 처리 |
| **Abort/Undefined Mode** | 권한 | 메모리접근오류, 미정의명령어 처리 |

**동작원리**: 각 모드는 일부 레지스터를 **전용으로(Banked Register)** 보유해, 모드전환시 Context Switch 비용을 최소화(예: FIQ모드는 R8~R14가 전용레지스터라 인터럽트처리시 기존값을 저장할 필요없이 즉시 사용가능)

**비교표(명령어 처리과정과 연계)**: User모드에서 시스템콜(SVC명령어) 실행 → Supervisor모드로 전환 → 커널루틴 수행 → 완료후 User모드로 복귀(이 모드전환이 보안·안정성의 핵심 경계)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| Dual Mode(이중모드, User/Kernel) | ARM의 다중모드를 더 단순화한 일반적 OS보호메커니즘(컴퓨터구조 이전파일과 연결) |
| 시스템콜 | User모드→Supervisor모드 전환의 실제 트리거(아래에서 상세) |
| RISC-V | ARM과 함께 비교되는 또다른 주요 ISA(다음 키워드) |

## 6. RISC-V

**방식 분류(RISC-V의 특징)**: **오픈소스 ISA(명령어집합아키텍처)** — ARM/x86과 달리 라이선스비용없이 누구나 자유롭게 구현·수정가능

**동작원리(모듈형 설계)**
```
[기본명령어집합(Base ISA)] RV32I(32비트정수) 등 필수 핵심명령어만 포함(매우 작고 단순)
   + [확장모듈(Extension)] 필요한 기능만 선택적으로 추가
     M(곱셈/나눗셈), F/D(부동소수점), A(원자적연산), C(압축명령어) 등
   → 용도에 맞게 "필요한 확장만" 조합해 맞춤형 프로세서 설계 가능
```

**비교표(ARM/x86과 비교)**

| 구분 | x86(CISC) | ARM(RISC) | RISC-V(RISC) |
|---|---|---|---|
| 라이선스 | 독점(Intel/AMD) | 라이선스비용필요(ARM Holdings) | **완전 오픈소스(무료)** |
| 명령어집합 | 복잡·다양(레거시누적) | RISC기반, 모드별 레지스터뱅킹 | RISC기반, **모듈형 확장구조** |
| 설계자유도 | 매우낮음 | 제한적(ARM 라이선스조건내) | 매우높음(자체 커스텀확장 가능) |
| 활용처 | PC/서버 | 모바일/임베디드 | 신흥(IoT, AI가속기, 학술/국가전략기술) |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| micro-programmed vs hard-wired | RISC철학(단순명령어)은 hard-wired 구현에 적합해 RISC-V도 주로 hard-wired 채택 |
| 온디바이스AI / NPU | RISC-V가 국산 AI반도체 설계 등에서 라이선스자유로 활용되는 핵심 동기(AI도메인과 연결) |
| 반도체 자립/국산화 | RISC-V 채택의 산업·정책적 배경(미중기술패권 등 지정학적 요인) |

## 7. TCAM (Ternary Content Addressable Memory)

**방식 분류**: 일반 RAM이 "주소→값"을 찾는 것과 반대로, **"값(패턴)→주소"**를 찾는 특수메모리(병렬비교 가능)

**동작원리**
```
[일반메모리] 주소 입력 → 해당주소의 저장된값 출력 (주소기반 접근)

[CAM(Content Addressable Memory)] 찾고싶은 값(데이터)을 입력 
   → 메모리의 모든셀과 동시(병렬)비교 → 일치하는 셀의 주소를 즉시 출력 (내용기반 접근, 매우빠름)

[TCAM(3진법 CAM)] 각 비트가 0, 1, 그리고 **"X"(don't care, 무관)** 3가지 상태 가능
   → 와일드카드 매칭 지원(예: "192.168.1.*"같은 IP범위 매칭에 적합)
```

**비교표(일반 CAM vs TCAM, 활용처)**

| 구분 | 일반 CAM(Binary) | TCAM(Ternary) |
|---|---|---|
| 비교가능 상태 | 0, 1만 | 0, 1, X(무관) |
| 적합용도 | 정확히 일치하는 검색 | **범위/패턴매칭**(라우팅테이블, ACL규칙) |
| 비용/전력 | 낮음 | 높음(셀구조복잡, 전력소모큼) |

**활용분야**: 네트워크 라우터의 **최장접두사매칭(Longest Prefix Match)**(IP주소를 가장 구체적인 라우팅규칙에 1클럭사이클로 즉시매칭), 방화벽 ACL규칙 고속검색

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 라우팅테이블 / 최장접두사매칭 | TCAM의 가장 대표적인 실무 활용사례(네트워크 도메인과 연결) |
| 해시테이블 | TCAM과 대조적으로 "정확한 일치"만 빠르게 찾는 일반적 자료구조(소프트웨어적 대안) |
| 방화벽/ACL | TCAM이 고속처리를 담당하는 보안장비의 핵심 하드웨어(보안 도메인과 연결) |

## 8. 폴락의 법칙 (Pollack's Rule)

**방식 분류**: CPU 마이크로아키텍처 설계에서 **칩 면적(트랜지스터수)과 성능간의 관계**를 설명하는 경험법칙

**동작원리(법칙 내용)**
```
성능향상 ≈ √(면적증가)
즉, 코어면적(트랜지스터수)을 2배로 늘려도 성능은 약 √2(≈1.41배)밖에 향상되지 않음
(면적증가가 성능증가로 100% 전환되지 않고, 효율이 체감하는 현상)
```

**비교표(시사점 — 단일코어 확장 vs 멀티코어 확장)**

| 전략 | 효과 | 한계 |
|---|---|---|
| 단일코어 면적 2배 확장 | 성능 약1.41배만 향상(폴락의법칙) | 면적 대비 성능효율 저하(투자수익 감소) |
| 동일면적으로 코어 2개(멀티코어) | 병렬작업시 이론상 최대 2배 향상 가능 | 모든작업이 병렬화가능해야함(암달의법칙 한계) |

**의미**: 폴락의 법칙이 바로 **"왜 업계가 단일코어 초대형화 대신 멀티코어로 전환했는지"**에 대한 핵심 이론적 근거 — 면적당 효율을 고려하면 작은코어 여러개가 큰코어 하나보다 유리

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 암달의 법칙(Amdahl's Law) | 폴락의법칙(면적-성능)과 함께 멀티코어시대의 성능한계를 설명하는 또다른 핵심법칙(병렬화가능비율의 한계) |
| 병렬컴퓨팅 / 상호연결망 | 폴락의법칙이 정당화하는 멀티코어·병렬처리 아키텍처 전환의 흐름 |
| 빅리틀 아키텍처(big.LITTLE) | 폴락의법칙을 활용해 큰코어+작은코어를 혼합배치하는 ARM의 실제 설계전략 |

## 9. CPU / GPU / FPGA / ASIC 비교

**방식 분류(처리방식별 특성)**

| 구분 | CPU | GPU | FPGA | ASIC |
|---|---|---|---|---|
| 처리방식 | 범용 순차처리(소수의 강력한코어) | **대규모 병렬처리**(수천개의 단순코어) | **하드웨어 재구성가능**(프로그래밍으로 회로구조 변경) | **특정용도 전용설계**(회로가 고정,변경불가) |
| 유연성 | 매우높음(모든프로그램 실행) | 높음(병렬연산에특화) | 중간(재구성가능하나 설계필요) | **없음**(한번제조되면 고정) |
| 처리능력(특정작업) | 범용작업엔 우수, 병렬작업엔 비효율 | 병렬연산(행렬곱등 AI학습)에 최고효율 | 범용보다빠름, ASIC보다는 유연 | **가장빠름·전력효율 최고**(해당작업전용) |
| 전력소비(작업당) | 중간 | 높음(전체전력은 크나 작업당효율은 우수) | 중간 | **가장낮음** |
| 개발비용/기간 | 없음(이미존재하는 범용칩 구매) | 없음(범용GPU 구매) | 중간(HDL설계 필요, 재수정가능) | **매우높음**(초기설계비용 막대, 양산후 수정불가) |

**동작원리(AI워크로드 적용관점)**: AI학습(대량 행렬연산, 병렬화용이) → GPU 압도적우위 / 특정 AI모델을 대량으로 반복추론(고정워크로드) → ASIC(예: Google TPU)이 전력효율 최고 / 신기술검증·소량생산(설계변경여지필요) → FPGA로 유연하게 대응

**비교표(선택기준 요약)**: 범용성필요→CPU, 대규모병렬연산→GPU, 유연성+전용화 중간지점→FPGA, 대량생산+최고효율(설계확정후)→ASIC

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| TPU(Tensor Processing Unit) | ASIC의 대표적 AI특화 사례(Google개발) |
| HBM | GPU/ASIC(AI가속기)에 필수 결합되는 고대역폭메모리(메모리시스템 도메인과 연결) |
| NPU(Neural Processing Unit) | 모바일/온디바이스AI에 특화된 ASIC계열 칩(AI도메인과 연결) |
| 뉴로모픽 반도체(SNN) | 위 4가지와는 또다른 차세대 패러다임(생물학적 신경망 모방, 이전파일의 차세대컴퓨팅과 연결) |

## 10. 시스템 콜 (System Call)

**방식 분류(주요 시스템콜 유형)**

| 유형 | 예시 |
|---|---|
| 프로세스제어 | fork(), exec(), exit() |
| 파일관리 | open(), read(), write(), close() |
| 장치관리 | ioctl() |
| 정보유지 | getpid(), time() |
| 통신 | socket(), send(), recv() |

**동작원리(User모드 → Kernel모드 전환과정)**
```
①응용프로그램에서 라이브러리함수 호출(예: printf) 
   → ②내부적으로 시스템콜 명령어 실행(소프트웨어 인터럽트, x86은 INT/SYSCALL명령어)
   → ③CPU가 User모드에서 Kernel모드로 전환(ARM은 SVC모드 진입)
   → ④커널이 해당 시스템콜 처리루틴 실행(실제 하드웨어 접근수행)
   → ⑤처리완료후 User모드로 복귀, 결과 반환
```

**비교표(시스템콜 vs 일반함수호출)**

| 구분 | 일반함수호출 | 시스템콜 |
|---|---|---|
| 권한모드 | 동일모드내(User→User) | **모드전환**(User→Kernel→User) |
| 오버헤드 | 낮음 | 높음(모드전환·컨텍스트저장 비용) |
| 목적 | 같은프로그램내 로직재사용 | 하드웨어자원(파일,네트워크 등) 접근 |

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| ARM 동작모드(Supervisor/SVC) | 시스템콜발생시 실제로 전환되는 목적지 모드 |
| 인터럽트(Vector방식) | 시스템콜이 본질적으로 "소프트웨어가 의도적으로 발생시키는 인터럽트"라는 점에서 동일메커니즘 공유 |
| Dual Mode(이중모드구조) | 시스템콜이 존재해야하는 근본적 이유(User모드의 권한제한을 우회해 안전하게 커널기능 사용) |

## 종합 흐름도

```
[CPU 동작 기본요소] CPU레지스터(PC/IR/SP등) ──→ 명령어 인출-실행 사이클
        │
[제어장치 구현] Hard-Wired(고속,RISC) vs Micro-Programmed(유연,CISC)
        │
[외부 이벤트 처리] 인터럽트3방식(Polling/Daisy-chain/Vector) ── 버스중재(자원경쟁 해결)
        │
[권한/모드 관리] ARM동작모드 ──→ 시스템콜(User↔Kernel 전환 트리거)
        │
[ISA 철학] RISC-V(오픈소스,모듈형) ←비교→ ARM/x86
        │
[성능확장 이론] 폴락의법칙(면적-성능 비선형) → 멀티코어/이종컴퓨팅 정당화
        │
[워크로드별 최적하드웨어] CPU(범용) vs GPU(병렬) vs FPGA(재구성) vs ASIC(전용)
        │
[특수목적 메모리] TCAM(패턴매칭 고속검색, 네트워크장비 핵심)
```
