### **차세대 WAN 라우팅: 세그먼트 라우팅 (SRv6)**

#### 답안 전체 스토리 흐름 (목차)

```
Ⅰ. 개요 (왜 기존 MPLS·SR-MPLS로는 부족한가)
Ⅱ. SRv6 핵심 구조 및 동작 원리
Ⅲ. 기존 기술과의 비교 및 적용 체계
Ⅳ. 결론
```

포인트: 개요에서 \*\*"앞서 다룬 SDN·NFV가 '제어·데이터 평면 분리로 네트워크를 소프트웨어로 제어'하는 패러다임이라면, SRv6(Segment Routing over IPv6)는 그 패러다임을 WAN 라우팅에 적용해 '패킷 헤더에 경로 전체를 인코딩함으로써 중간 노드는 별도 상태 정보 없이 헤더만 보고 전달하는 소스 라우팅 기술'이다 — 기존 MPLS가 모든 중간 노드에 레이블 스위칭 상태를 유지해야 하는 복잡성과, SR-MPLS가 IPv6 환경에서 한계를 보이는 문제를 SRv6가 IPv6 확장 헤더(SRH)에 세그먼트 리스트를 실어 해결하며, 앞서 다룬 5G·6G 네트워크 슬라이싱·SATIN 위성통신 연계의 핵심 WAN 기술"\*\*이라는 한 줄로 시작하면 전체 맥락이 드러납니다.

***

#### Ⅱ. SRv6 핵심 구조 및 동작 원리

**가. SRv6 핵심 개념**

| 개념                               | 내용                                                        | 핵심 키워드                                 |
| :------------------------------- | :-------------------------------------------------------- | :------------------------------------- |
| **세그먼트 (Segment)**               | 네트워크 경로의 단위 지시어 / 노드·링크·서비스·VPN 지시                        | SID(Segment Identifier)로 표현            |
| **SID**                          | 128비트 IPv6 주소 형태 / Locator(위치)+Function(기능)+Arguments(인자) | Locator:Function:Args 구조               |
| **SRH (Segment Routing Header)** | IPv6 확장 헤더로 세그먼트 리스트 탑재 / 남은 세그먼트 수(SL) 포함                | Next Header·Segments Left·Segment List |
| **SR-TE (Traffic Engineering)**  | 세그먼트 리스트로 명시적 경로 지정 / 대역폭·지연·색상 기반 경로 선택                  | Policy·Candidate Path·Preference       |

***

**나. SRv6 동작 원리**

```
[SRv6 패킷 전달 흐름]

출발지(Source) → 목적지(Destination)
경로: A→B→C→D

①소스 노드(A)가 SRH에 세그먼트 리스트 삽입
  SRH: [SID_D, SID_C, SID_B]
  SL(Segments Left) = 2 (현재 SID_B 처리)
  DA(Destination Address) = SID_B

②B 노드 수신
  자신의 SID = DA → SL-- / SL=1
  DA → SID_C로 교체 후 C로 전달

③C 노드 수신
  자신의 SID = DA → SL-- / SL=0
  DA → SID_D로 교체 후 D로 전달

④D 노드 수신
  SL=0 → 최종 목적지 → SRH 제거·페이로드 처리

핵심: 중간 노드(B·C)는 별도 상태 정보 없음
      SRH만 보고 전달 → Stateless 전달 ✅
```

**나. SRv6 핵심 기능 체계**

| **핵심 척도** | **📊 SRH 구조·인코딩 🚨**                                                                                                    | **🔑 SR-TE·네트워크 슬라이싱 🚨**                                                                                            | **🏁 서비스 체이닝·VPN 💯**                                                                                                                       |
| :-------- | :---------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------ |
| **핵심 기술** | **SID 128비트 구조**: Locator(네트워크 위치)/Function(처리 기능)/Args(파라미터) / **SRH**: IPv6 확장 헤더·세그먼트 리스트·SL 포함 / 기존 IPv6 인프라 재사용 ✅  | **SR-TE Policy**: 명시적 경로 지정 / 지연·대역폭·색상 기반 경로 선택 / **5G 네트워크 슬라이싱**: 슬라이스별 SID 할당·트래픽 분리 / 앞서 다룬 **AI-RAN·O-RAN** 연계 | **SFC(Service Function Chaining)**: FW→IPS→LB 서비스 순서를 SID로 표현 / **L3VPN·L2VPN**: MPLS 없이 IPv6+SRH로 VPN 구현 / 앞서 다룬 **CASB·NGFW** 인라인 서비스 체이닝 |
| **장점**    | **Stateless 중간 노드**: 경로 상태 중간 노드 저장 불필요 → 확장성↑ / **소스 라우팅**: 경로 제어권을 엣지·컨트롤러로 집중 / **단일 프로토콜**: MPLS 레이블 불필요·IPv6만으로 완결 | **빠른 재라우팅**: 장애 시 SRH 세그먼트 리스트 즉각 교체 / **트래픽 엔지니어링**: 최단 경로 아닌 의도 기반 경로 선택 / 앞서 다룬 **IBN** 철학의 WAN 구현                | **클라우드 네이티브 친화**: 컨테이너·K8s 서비스 SID 매핑 / **멀티도메인**: AS 경계 넘어 단일 SRH로 종단간 제어 / 앞서 다룬 **VXLAN·BGP EVPN**과 연계                                   |
| **도입 현황** | **국내**: SKT·KT 5G 백홀·코어 SRv6 도입 / **글로벌**: 소프트뱅크·차이나텔레콤·AT&T / **표준**: IETF RFC 8986(SRv6 Network Programming)          | **6G 연계**: IMT-2030 네트워크 슬라이싱 핵심 / 앞서 다룬 **NTN 위성** 지상 연동 WAN                                                        | **SR Policy**: Cisco·Juniper·Nokia 지원 / **오픈소스**: VPP·FRRouting·Linux 커널 SRv6                                                               |

#### Ⅲ. 기존 기술과의 비교 및 적용 체계

**가. MPLS vs SR-MPLS vs SRv6 비교**

| 비교 항목        | MPLS            | SR-MPLS  | SRv6                  |
| :----------- | :-------------- | :------- | :-------------------- |
| **경로 인코딩**   | 레이블 스택          | 레이블+세그먼트 | IPv6 SRH ✅            |
| **중간 노드 상태** | 필요(LIB·LFIB) 🚨 | 필요       | **불필요(Stateless)** ✅  |
| **IPv6 친화성** | 낮음              | 중간       | **완전 호환** ✅           |
| **TE 지원**    | RSVP-TE 복잡      | 개선       | **SR-TE Policy 단순** ✅ |
| **서비스 체이닝**  | 복잡              | 복잡       | **SID 기반 단순** ✅       |
| **5G·클라우드**  | 제한적             | 부분적      | **네이티브 지원** ✅         |
| **전환 비용**    | -               | 낮음       | 중간(SRH 지원 필요)         |

**나. SRv6 전체 아키텍처 도식화**

```
[SRv6 WAN 아키텍처]

                SDN 컨트롤러
                (SR-TE Policy 배포)
               /       |       \
              /        |        \
         엣지A      코어B       엣지C
       [SRH 삽입]  [SID 처리]  [SRH 제거]
           |           |           |
       5G기지국     데이터센터    클라우드

[SRH 패킷 구조]
┌─────────────────────────────┐
│  IPv6 기본 헤더              │
│  Next Header = SRH(43)      │
├─────────────────────────────┤
│  SRH (Segment Routing Header)│
│  Segments Left (SL)         │
│  Segment List[0] = SID_C    │
│  Segment List[1] = SID_B    │ ← 현재 처리
│  Segment List[2] = SID_A    │ ← 이미 처리
├─────────────────────────────┤
│  페이로드 (TCP/UDP 데이터)    │
└─────────────────────────────┘

[SRv6 서비스 체이닝]
패킷 → [FW SID] → [IPS SID] → [LB SID] → 서버
       방화벽 검사  침입탐지    부하분산
→ SID 순서 변경만으로 서비스 순서 즉각 변경 ✅
```

***

**(제언)** "SRv6는 'MPLS의 복잡성을 IPv6 위에서 소스 라우팅으로 단순화하는 차세대 WAN 기술'입니다. **앞서 다룬 5G 네트워크 슬라이싱·6G IMT-2030의 의도 기반 네트워킹(IBN) 구현에 SRv6 SR-TE Policy가 핵심 기술로 채택되고 있으며, 앞서 다룬 NGFW·CASB 인라인 서비스를 SFChaining SID로 표현해 클라우드·온프레미스 혼합 환경에서 일관된 보안 정책을 적용하고, 앞서 다룬 AI-RAN·Open RAN과 결합해 5G 백홀 트래픽을 슬라이스별로 SRv6로 분리 제어하는 것이 차세대 통신·클라우드 통합 네트워크 아키텍처의 핵심 전략입니다.**"
