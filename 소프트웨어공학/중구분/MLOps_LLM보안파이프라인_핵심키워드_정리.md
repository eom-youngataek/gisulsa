# MLOps 및 LLM 보안 파이프라인 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 파이프라인 구성요소 → 보안위협 매핑 → 가드레일 구조

---

## 1. MLOps 파이프라인 (CT 포함)

**파이프라인 구성요소**
```
[데이터 파이프라인] 수집 → 정제 → 검증(품질체크)
        ↓
[CI: 모델학습] 코드/데이터 변경감지 → 자동학습 → 모델성능 검증(오프라인 평가)
        ↓
[CD: 모델배포] 스테이징 배포 → A/B테스트 → 운영환경 점진배포(Canary)
        ↓
[CT: 지속학습(Continuous Training)] 운영 중 실시간 모니터링 
        → 데이터드리프트/모델드리프트 감지 → 재학습 자동트리거 → 위 사이클 반복
```

**보안위협 매핑**
- CT파이프라인이 운영데이터를 자동으로 재학습에 반영하는 구조는 **데이터/모델 포이즈닝(OWASP LLM04)**의 공격경로가 될 수 있음
- 모델 레지스트리(학습된 모델 저장소) 접근권한 미흡 시 **모델 탈취/모델추출공격**의 표적이 됨
- 파이프라인 자체(오케스트레이션 도구)의 취약점은 **공급망공격(LLM03)**으로 연결

**가드레일 구조**
```
[CT 트리거 전] 재학습 데이터 품질·이상치 검증 게이트(자동승인 금지, 임계치 초과시 사람검토 강제)
[모델 레지스트리] 접근권한 최소화(RBAC) + 모델 버전 서명(무결성 검증)
[배포 전] 신규모델을 자동으로 OWASP LLM 위협 시나리오로 레드팀 테스트 후 배포승인
```

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 데이터 관측가능성(Data Observability) | CT 트리거 판단의 전제가 되는 드리프트 감지 인프라 |
| AI학습데이터 품질관리 지표 | 재학습 데이터 품질검증 게이트의 구체적 평가기준 |
| 데이터 포이즈닝 / 적대적공격 4유형 | CT파이프라인이 노출되는 핵심 공격형태 |
| CI/CD 파이프라인 | MLOps가 확장한 원형 DevOps 파이프라인 |

## 2. LLM 코드생성

**파이프라인 구성요소**
```
[자연어 요구사항/이슈] → [LLM 코드생성 에이전트] 코드초안+테스트코드 동시생성
        → [1차 자동검증] 정적분석(SAST) + 단위테스트 실행
        → [2차 사람검토(필수게이트)] 코드리뷰 승인
        → [CI/CD 파이프라인] 빌드·배포
```

**보안위협 매핑**
- **OWASP LLM05(Improper Output Handling)**: 생성코드를 검증없이 즉시 실행·배포하는 경우 직접적 위협으로 연결
- **패키지 환각(Package/Slopsquatting)**: LLM이 실재하지 않는 패키지명을 추천 → 공격자가 동일이름의 악성패키지를 선점배포해 공급망 침투(LLM03과 연계)
- 학습데이터에 내재된 오래된/취약한 코드패턴이 그대로 재현되는 잠재적 보안약점 이식

**가드레일 구조**
```
[생성 즉시] SAST(정적분석) 자동스캔 — 시큐어코딩 위반여부 1차 차단
[패키지 추천 시] 화이트리스트/SBOM 대조 검증 — 미등록 패키지는 자동경고
[배포 전] 사람 코드리뷰를 우회불가 필수 게이트로 강제(자동배포 금지)
```

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 시큐어코딩 / SAST·DAST | LLM 생성코드의 취약점을 걸러내는 핵심 방어선 |
| SBOM / SCA | 패키지 환각 공격을 차단하는 공급망검증 도구 |
| 페어/핑퐁 프로그래밍 | "사람+LLM" 협업 코딩구조의 전통적 대응사례 |
| TDD | LLM이 테스트코드도 함께 생성하는 구조와 결합 가능한 개발기법 |

## 3. OWASP Top10 for LLM

**파이프라인 구성요소(SDLC 단계별 통합지점)**
```
[설계단계] 위협모델링에 LLM01~10 포함 → 아키텍처 리뷰
[개발단계] 프롬프트템플릿/에이전트권한 설계에 보안요건 반영
[테스트단계] 적대적 프롬프트셋으로 레드티밍 자동화(CI에 통합)
[운영단계] 가드레일 적용 + 실시간 모니터링(이상응답 탐지)
```

**보안위협 매핑(10대 항목)**
| 항목 | 핵심위협 |
|---|---|
| LLM01 | 프롬프트인젝션 |
| LLM02 | 민감정보유출 |
| LLM03 | 공급망(데이터/모델/패키지) |
| LLM04 | 데이터/모델 포이즈닝 |
| LLM05 | 부적절한 출력처리 |
| LLM06 | 과도한 에이전시(권한) |
| LLM07 | 시스템프롬프트 유출 |
| LLM08 | 벡터/임베딩 취약점 |
| LLM09 | 환각/허위정보 |
| LLM10 | 무제한 자원소비 |

**가드레일 구조**: 항목별 1:1 매핑 — LLM01→Input Guardrail, LLM06→에이전트 최소권한 정책, LLM08→벡터DB 접근통제, LLM10→사용량쿼터 게이트 등 각 위협유형에 대응하는 가드레일을 게이트별로 배치

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 적대적공격 / 모델전도공격 / Model DoS | OWASP 항목에 직접 대응하는 구체적 공격기법(AI보안위협 도메인) |
| AI신뢰성검인증(CAT) | OWASP 점검결과가 인증심사의 핵심 평가기준으로 활용 |
| MITRE ATLAS / TTPs | 위협을 "분류"하는 OWASP와 "공격기법"을 세분화하는 ATLAS의 상호보완 관계 |
| 레드티밍(Red Teaming) | 테스트단계에서 OWASP 위협을 실제로 검증하는 핵심 실행기법 |

## 4. 프롬프트 인젝션 방어

**파이프라인 구성요소(방어계층 구조)**
```
[입력채널] 사용자 직접입력 + 외부데이터(RAG검색결과, 도구응답 등 간접경로)
        ↓
[방어계층1: 입력검증] 악성패턴/이상지시어 사전탐지·필터링
        ↓
[방어계층2: 권한분리(Instruction Hierarchy)] 
        System프롬프트(최우선) > 개발자 지시 > 사용자입력 > 외부데이터(최하위 신뢰도)
        — 역할(role)별 신뢰수준을 명확히 구분해 하위채널의 지시가 상위를 덮어쓰지 못하게 설계
        ↓
[방어계층3: 출력검증] 응답이 시스템지시 범위를 벗어나는지 사후검사
        ↓
[최종 응답]
```

**보안위협 매핑**: 직접 인젝션(사용자입력에 명시적 악성지시) vs **간접 인젝션**(RAG검색문서·웹페이지·도구응답에 악성지시 은닉, 현재 가장 큰 위협) — 두 유형 모두 LLM01에 해당하나 간접형은 탐지난이도가 훨씬 높음

**가드레일 구조**: Input Guardrail(시그니처기반 탐지) + Instruction Hierarchy(구조적 신뢰도 분리) + 외부데이터 격리(RAG 검색결과는 "데이터"로만 취급, "지시"로 해석되지 않도록 프롬프트 템플릿에서 명확히 구분표시) + Output Guardrail(최종 응답 검증)

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| MCP(Model Context Protocol) | 외부도구 연동 시 간접 프롬프트인젝션의 신규 경로가 되는 표준 |
| Advanced RAG / Modular RAG | 검색결과(외부문서)가 간접인젝션의 주요 매개체가 되는 생성형AI 구조 |
| SQL인젝션 | 구조적 유사성(신뢰할 수 없는 입력이 명령으로 해석됨)과 차이점(자연어는 문법경계가 없음) 비교출제 |
| 시스템프롬프트 유출(LLM07) | 권한분리가 실패할 경우 시스템프롬프트 자체가 노출되는 연계위협 |

## 5. LLM 가드레일 (Guardrails)

**파이프라인 구성요소(가드레일 아키텍처 상세)**
```
[사용자 입력]
   ↓
[Input Guardrail]
   - 주제 이탈 검사(허용된 업무범위 내 질문인지)
   - 프롬프트인젝션 시그니처 탐지
   - PII(개인정보) 탐지·마스킹
   ↓
[LLM 본체 처리] (필요시 도구호출/RAG검색 포함)
   ↓
[Output Guardrail]
   - 환각(Hallucination) 검증 — 사실/근거 기반 여부 확인
   - 유해콘텐츠/편향 필터링
   - 출력형식(JSON 스키마 등) 검증
   ↓
[최종 사용자에게 응답]
```

**보안위협 매핑**: Input Guardrail은 LLM01(인젝션)·LLM02(정보유출 입력측)에 대응, Output Guardrail은 LLM05(부적절출력)·LLM07(프롬프트유출)·LLM09(환각)에 대응, 전체 아키텍처는 LLM06(과도한에이전시)을 권한정책으로 통제

**구조 상세화(탐지 방식 3단계 결합)**
1. **규칙기반**: 정규식·키워드 블랙리스트(빠르지만 우회 용이)
2. **ML분류기 기반**: 별도 경량 분류모델로 위협확률 판단(중간 정확도·속도)
3. **LLM-as-a-Judge**: 또 다른 LLM이 응답의 적절성을 재검토(가장 정교하나 비용·지연 증가)
→ 보통 1·2단계를 실시간 필터로, 3단계를 샘플링 기반 사후검증으로 결합

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| WAF(웹애플리케이션방화벽) | 트래픽 레벨 필터링(WAF)과 대화 레벨 필터링(가드레일)의 개념적 대응관계 |
| 제로트러스트 | "모든 입출력을 기본적으로 의심하고 검증"하는 가드레일의 철학적 기반 |
| 차분프라이버시 / PET | Input Guardrail의 PII탐지·마스킹이 실제 활용하는 프라이버시보호 기술 |
| AI신뢰성검인증(CAT) | 가드레일의 실효성을 제3자가 검증하는 인증체계 |

## 종합 흐름도

```
[운영 인프라] MLOps 파이프라인(CT) — 데이터/모델의 지속학습·배포 자동화
        │  (보안위협: 데이터포이즐닝, 모델탈취)
        │
[개발 생산성] LLM 코드생성 — AI가 코드작성, 사람은 검토자로 역할이동
        │  (보안위협: 부적절출력, 패키지환각/공급망)
        │
        ▼
[통합 위협분류체계] OWASP Top10 for LLM(LLM01~10)
        │
        ├──→ 프롬프트인젝션 방어(LLM01 집중대응, 입력단계 핵심)
        │
        └──→ LLM 가드레일(Input+Output 전구간 통합 방어 아키텍처)
```
