# 소프트웨어 비용 산정 및 대가 기준 핵심 키워드 정리 (정보관리기술사 대비)

> **공통 답안 전개 구조**: 최신 가이드 근거 → 산정방식 절차 비교 → 보정계수/체크리스트

---

## 1. FP (기능점수, 정밀법 vs 간이법)

**최신 가이드 근거**
> "소프트웨어 사업 대가산정 가이드"(매년 개정, 한국SW산업협회) 및 IFPUG(국제기능점수사용자그룹) 표준에 근거한 규모산정 기법

**산정방식 절차 비교**

| 구분 | 정밀법(정통법) | 간이법 |
|---|---|---|
| 절차 | ①데이터기능(내부논리파일ILF·외부연계파일EIF) 식별 → ②트랜잭션기능(EI·EO·EQ) 식별 → ③각 기능의 복잡도(단순/중간/복잡) 평가 → ④가중치 적용해 정밀 FP산출 | 시스템 전체 유형(업무유형) 기준으로 **단순화된 평균치**를 적용해 빠르게 산출 |
| 정확도 | 높음(상세 설계정보 필요) | 낮음(초기 기획단계에 적합) |
| 소요시간 | 오래 걸림 | 빠름 |
| 적용시점 | 설계완료 후 정밀 산정 | 사업초기 예산수립·제안서 작성단계 |

**보정계수/체크리스트**
- **개발유형별 보정계수**: 기본개발(신규) vs 재개발 vs 유지보수 — 재개발의 경우 기존자산 재사용률을 고려한 보정계수 적용
- **재개발 사업 보정계수 5가지(138회 기출패턴)**: 기능개선율, 인터페이스 변경율, 데이터 변경율, 재사용률, 변환작업 가중치 등을 종합반영
- **체크리스트(감리원 핵심 점검항목)**: 기능유형(ILF/EIF/EI/EO/EQ) 분류의 적정성, 복잡도 평가기준 일관성, 보정계수 적용근거 문서화 여부

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| ILF/EIF/EI/EO/EQ | FP 정밀법 산정의 5대 기능유형 구성요소(상세 출제 가능) |
| 정보시스템 감리 | FP검증이 감리원의 핵심 점검영역(경영정보시스템 도메인과 연결) |
| COCOMO II | FP로 산출된 규모(또는 LOC 환산)를 투입공수 추정의 입력값으로 활용(아래 키워드와 연계) |

## 2. COCOMO II (Constructive Cost Model)

**최신 가이드 근거**: Barry Boehm이 제시한 경험적(실증데이터 기반) 소프트웨어 비용추정 모델, 1995년 객체지향·반복개발 환경을 반영해 COCOMO II로 개정

**산정방식 절차**
```
①규모(Size) 측정: KLOC(천라인) 또는 기능점수를 LOC로 환산
   → ②노력(Effort) 산출: PM(Person-Month) = A × (Size)^B × ∏(노력조정요소)
   → ③개발기간(Duration) 산출: TDEV = C × (PM)^D
   → ④인력투입계획 수립
```

**산정모델 3단계(적용시점별)**
| 모델 | 적용시점 | 특징 |
|---|---|---|
| Application Composition Model | 초기 기획단계 | 프로토타입·재사용 기반, 단순 추정 |
| Early Design Model | 요구분석 완료 후 | 개략적 아키텍처 결정 후 산정 |
| Post-Architecture Model | 아키텍처 확정 후 | 가장 상세하고 정확한 산정(17개 노력조정요소 반영) |

**보정계수/체크리스트**: 노력조정요소(Cost Driver) 17개 — 제품신뢰성, 팀숙련도, 일정제약, 재사용수준 등을 1.0 기준으로 가중치 곱셈 반영해 최종 PM 보정

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| LOC(Lines of Code) | COCOMO의 기본 규모측정 단위(FP와 비교되는 전통적 측정법) |
| 투입공수(Man-Month) 방식 | COCOMO가 산출하는 최종 결과물 단위가 바로 투입공수(다음 키워드와 직결) |
| Putnam모델 | COCOMO와 함께 비교되는 또다른 경험적 비용추정모델(Rayleigh곡선 기반) |

## 3. SW대가산정지침 (소프트웨어 사업 대가산정 가이드)

**최신 가이드 근거**
> 한국소프트웨어산업협회가 매년 발표하는 "소프트웨어 사업 대가산정 가이드"(현재 매년 개정판 발표, AI서비스 도입 등 신규유형 반영 확대) — SW사업 발주·계약 시 표준 비용기준으로 활용

**산정방식 절차 비교(사업유형별 산정방식)**

| 사업유형 | 산정방식 |
|---|---|
| 신규개발 | FP기반 산정(정밀법/간이법) |
| 운영/유지관리 | **투입공수방식**(상주인력 M/M) 또는 **요율제방식**(개발비의 일정 비율로 연간 유지관리비 산정) |
| AI서비스 도입(최신 반영, 137회 기출) | 데이터구축비+모델학습비+인프라비용 등을 별도 산정절차로 구분 |

**보정계수/체크리스트**: 요율제 산정 시 고정비(인프라운영 등 변동없는 비용)와 변동비(이용량에 비례하는 비용)를 구분 산정, 운영단계 투입공수 산정 시 SLA수준에 따른 등급별 인력투입 기준 적용

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 공공SLA(전자정부법 개정) | 운영단계 대가산정이 SLA 등급과 직접 연계되는 최신 제도변화(139회 기출, 경영정보시스템 도메인과 연결) |
| AI서비스 도입 사업유형 | 137회 기출의 "생성형AI 도입 사업비 산정절차"가 가이드 최신판의 핵심 신규영역 |
| 조달청 협상에의한계약 제안서평가기준 | 대가산정과 별도로 제안서의 기술성을 평가하는 공공조달 제도(아래 항목과 연계) |

## 4. 투입공수 방식 (Man-Month)

**최신 가이드 근거**: SW대가산정가이드에서 "엔지니어링 대가기준"과 함께 운영·유지보수 단계 산정방법으로 명시

**산정방식 절차**
```
①업무범위 정의(운영대상 시스템 수·기능 복잡도) → ②투입인력 등급(고급/중급/초급기술자) 결정
   → ③등급별 표준 노임단가(매년 SW기술자 임금실태조사 기준 발표) 적용
   → ④투입기간(월) × 인력등급별단가 = 총 대가
```

**고정비/변동비 산정방식 비교**

| 구분 | 고정비 | 변동비 |
|---|---|---|
| 정의 | 이용량과 무관하게 발생하는 비용(인프라 임대료 등) | 처리량·트래픭에 비례하는 비용 |
| 적용사례 | 상주인력 기본운영비 | 콜수·트랜잭션량 기반 추가비용 |

**보정계수/체크리스트**: 노임단가는 매년 갱신되는 "SW기술자 평균임금" 공표자료를 그대로 적용해야 하며, 등급분류(기술자격·경력)의 적정성을 입찰 시 검증

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| IT역량분류체계 / IT직무제 | 투입공수 산정의 인력등급(고급/중급/초급)을 결정하는 상위 분류체계(132회 기출 — SW기술자 등급제→IT직무제 전환) |
| COCOMO II | COCOMO의 PM(Person-Month) 산출결과가 투입공수방식 대가산정의 입력값으로 활용 |
| 응용SW 요율제 유지관리비 | 투입공수방식과 대조되는 또다른 운영단계 산정방식(132회 기출) |

## 5. 소프트웨어사업 영향평가

**최신 가이드 근거**: 소프트웨어진흥법에 근거해 정보통신산업진흥원(NIPA)이 운영하는 제도 — 공공기관이 SW사업을 발주하기 전, 민간시장에 미치는 영향을 사전 평가

**산정방식 절차(평가체계)**
```
①영향평가 대상기관 판단(국가기관·공공기관 등 사업금액 기준) 
   → ②사업계획서 제출 → ③시장영향 분석(민간시장 잠식여부, 중복투자여부)
   → ④평가결과(적합/부적합/조건부) 통보 → ⑤사업추진 또는 계획수정
```

**보정계수/체크리스트(평가항목)**: 사업필요성, 사업범위의 적정성(민간기능 중복여부), 추진방식(자체개발vs구매vs민간위탁), 예산의 적정성

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| 소프트웨어진흥법 | 영향평가의 직접적 법적근거(경영정보시스템 도메인과 연결) |
| 패키지SW 도입절차 | 영향평가에서 "구매(민간솔루션 활용)"가 권장되는 대안으로 직결(SW방법론 도메인과 연결) |
| 대형소프트웨어 사업 전문평가제도 | 영향평가와 함께 대형사업의 품질을 검증하는 또다른 공공제도(136회 기출) |

## 6. 상용SW 직접구매·품질성능평가시험

**최신 가이드 근거**: 소프트웨어진흥법에 따라 국가기관 등이 상용SW를 직접구매할 경우, 자체 또는 지정시험기관을 통해 사전 품질성능평가시험을 수행하도록 규정

**산정방식 절차(평가시험 절차)**
```
①평가시험 적용대상 판단(직접구매 대상SW, 제외기준: 이미 인증받은 제품 등)
   → ②시험계획수립(평가항목·기준 정의) → ③품질성능평가시험 수행(기능·성능·보안성 등)
   → ④결과서 발급 → ⑤직접구매 진행 여부 결정
```

**보정계수/체크리스트(평가시험 기대효과)**: 저품질 상용SW의 공공도입 사전차단, 직접구매 활성화로 SW유통구조 효율화(중간유통마진 절감), 품질이 검증된 제품의 시장신뢰도 제고

**📌 연관 키워드**
| 키워드 | 연결 포인트 |
|---|---|
| CC(Common Criteria) / 정보보호제품 신속확인제도 | 품질성능평가시험과 유사하게 제품의 사전 검증을 수행하는 인접 제도(보안 도메인과 연결) |
| ISO/IEC 25010 | 품질성능평가시험이 실제로 측정하는 품질특성의 표준 근거 |
| 조달청 협상에의한계약 제안서평가 세부기준 | 직접구매와 별개로 SI사업 수주 시 제안서 자체를 평가하는 제도(136회 기출) |

```
[규모산정] FP(정밀법/간이법) ──→ COCOMO II(규모→투입공수 변환)
        │
[비용산정 표준] SW대가산정지침 — 신규개발(FP기반)/운영(투입공수·요율제)/AI서비스(신규유형) 구분
        │
        ├──→ 투입공수방식(Man-Month) — 등급별 노임단가 적용
        │
[공공조달 검증체계]
  소프트웨어사업 영향평가(발주 전 시장영향 검토)
        │
  상용SW 직접구매·품질성능평가시험(구매 전 품질검증)
```
